# 03 · 领域一：库存决策

> 先把一个域做漂亮，再复制到采购和设备。库存是管理层最常问、也最容易问错口径的。

---

## 1. 本域只回答这些问题

1. 某 SKU 在某仓的可用库存是多少？在库、锁定、残次各多少？
2. 同一 SKU 在两个仓怎么对比？哪边更该补？
3. 某仓可用量低于安全库存的 SKU 有哪些（Top N）？

不回答：未来 30 天需求预测、自动调拨指令。

---

## 2. 口径（必须与 RAG 文档一致）

写入假制度《库存可用量口径》：

```text
可用库存 = 在库数量 - 已锁定数量 - 残次数量
不含在途。在途单独展示。
安全库存来自 sku.safety_stock。
数据截止时间取 inventory.updated_at。
```

工具返回字段名与制度用词一致：`onHand`、`locked`、`defective`、`available`、`inTransit`、`safetyStock`、`dataAsOf`。

---

## 3. 仓储方法

```java
public record InventorySnapshot(
        String skuId,
        String skuName,
        String warehouseId,
        int onHand,
        int locked,
        int defective,
        int available,
        int inTransit,
        int safetyStock,
        Instant dataAsOf
) {}

public interface InventoryRepository {
    Optional<InventorySnapshot> find(String skuId, String warehouseId);
    List<InventorySnapshot> findLowStock(Collection<String> warehouseIds, int limit);
}
```

SQL 在视图里算 `available`，不要让模型算减法——它可能减错。

```sql
CREATE VIEW v_inventory_decision AS
SELECT i.sku_id,
       s.name AS sku_name,
       i.warehouse_id,
       i.on_hand,
       i.locked,
       i.defective,
       (i.on_hand - i.locked - i.defective) AS available,
       i.in_transit,
       s.safety_stock,
       i.updated_at AS data_as_of
FROM inventory i
JOIN sku s ON s.id = i.sku_id;
```

## 4. 工具

```java
@Component
public class InventoryTools {

    private final InventoryRepository repo;
    private final ToolSupport support;

    @Tool(description = """
            查询单个 SKU 在单个仓库的库存快照，含可用/在库/锁定/残次/在途/安全库存及数据截止时间。
            仅用于只读查询。需要 skuId 与 warehouseId。
            """)
    public String queryInventory(String skuId, String warehouseId, ToolContext ctx) {
        UserScope scope = support.scope(ctx);
        support.requireWarehouse(scope, warehouseId);
        support.requireCode(skuId);
        return support.toJson(repo.find(skuId, warehouseId)
                .orElseThrow(() -> new NoDataException("未找到该 SKU 在该仓的库存记录")));
    }

    @Tool(description = """
            对比同一 SKU 在两个仓库的可用库存与安全库存。用于判断哪边更紧。
            """)
    public String compareWarehouses(String skuId, String warehouseId1, String warehouseId2, ToolContext ctx) {
        UserScope scope = support.scope(ctx);
        support.requireWarehouse(scope, warehouseId1);
        support.requireWarehouse(scope, warehouseId2);
        var a = repo.find(skuId, warehouseId1);
        var b = repo.find(skuId, warehouseId2);
        return support.toJson(Map.of("left", a, "right", b));
    }

    @Tool(description = """
            列出当前用户有权仓库中，可用库存低于安全库存的 SKU，最多 20 条。
            不要用此工具查询无权限仓。
            """)
    public String listLowStock(ToolContext ctx) {
        UserScope scope = support.scope(ctx);
        return support.toJson(repo.findLowStock(scope.warehouseIds(), 20));
    }
}
```

把结果打成 JSON 字符串给模型。比自由文本更不容易被读错。`ToolSupport.toJson` 用 Jackson。

## 5. 系统提示里对本域的句子

```text
库存数字必须调用库存工具。可用库存定义以知识库《库存可用量口径》为准。
若工具返回 available 低于 safetyStock，结论必须提示补货风险，但不要下补货单。
在途不要加进可用。
```
