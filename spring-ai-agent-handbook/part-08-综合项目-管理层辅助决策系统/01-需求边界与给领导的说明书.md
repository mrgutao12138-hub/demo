# 01 · 需求边界与给领导的说明书

> 先写说明书再写代码。领导问的永远是：做什么、不做什么、数从哪来、会不会改库存、多少钱。

---

## 1. 一句话

Decision Copilot 是面向管理层的**只读**问答助手：用自然语言跨 ERP / WMS / EMS 查数、对口径、给建议；**不替代**正式报表、不自动改业务数据。

---

## 2. 做什么（第一期）

1. 库存：单 SKU 单仓可用量、两仓对比、低库存风险提示。
2. 采购：超期未到货订单、按供应商汇总、影响哪些 SKU。
3. 设备：近 N 天停机超过 30 分钟的产线、停机时长、是否可能影响产出（只提示相关性，不断言因果除非数据支持）。
4. 口径：什么叫可用库存、什么叫超期，来自制度知识库。
5. 所有数字带来源和时间。

---

## 3. 不做什么（第一期必须写进说明书）

1. 不自动改库存、不自动下采购单、不自动派维修工。
2. 不预测未来销量（那是另一类模型，需要专门特征与评估）。
3. 不替代财务关账与官方 KPI 看板。
4. 不回答人事薪酬、客户身份证、未授权仓库。
5. 不保证 100% 正确。AI 会归纳错误；以源系统为准。
6. 不在第一期接语音、PPT、邮件群发。

【红线】领导说「既然能查，顺便帮我下单吧」。回答：「下单走现有采购流程。副驾只出建议草稿，人点确认才生效——而且确认功能排在下一期。」

---

## 4. 数据从哪来

| 问题类型 | 来源 |
|---|---|
| 库存可用、在途、残次 | WMS 同步到决策库的宽表 / 视图 |
| 采购订单、承诺到货日 | ERP 同步宽表 |
| 停机事件 | EMS/设备系统同步表 |
| 「可用库存」定义 | 制度文档 RAG |
| 对话上下文 | 会话记忆，不当数据源 |

演示阶段：本地 Postgres 演示数据。试用阶段：只读同步。生产：仍不打业务主库写账号。

---

## 5. Agent 和 BI 看板怎么共存

用这个比喻跟领导讲：

- **看板**是仪表盘：每天固定看的时速、油量。适合「今日缺货 SKU 数」。
- **副驾**是你临时问的导航：跨系统、带解释、少见的组合问题。适合「这个 SKU 在 A 仓紧、供应商又超期，停机是不是会雪上加霜？」

两者都要。用 Agent 替换全部 BI，是把稳定指标交给会变化的模型，财务不会答应。

---

## 6. 风险（写进说明书）

1. 幻觉：模型可能把工具结果说错。缓解：结构化出处、评测集、关键决策人工复核。
2. 数据出域：云端 API。缓解：脱敏、合同、高敏感改本地模型（扩展篇）。
3. 越权：缓解：工具内强制范围，攻防验收。
4. 费用：按人限额。缓解：flash/pro 分流、日配额。
5. 可用性：模型挂。缓解：非 LLM 查询 API + 看板兜底。

---

## 7. 给领导的一页纸（可复制）

```text
项目：Decision Copilot（管理层辅助决策副驾）第一期
用户：指定管理层试用（建议 5 人）
能力：用中文问库存/采购超期/设备停机，得到带来源的解释与建议
不做：自动改数、自动下单、替代官方报表
数据：只读决策库（由 ERP/WMS/EMS 同步），制度文档检索
模型：DeepSeek 云端 API（公司密钥，有限额）
安全：按仓库授权；全量审计；无写工具
成功标准：15 分钟现场三问 + 拒写 + 越权演示通过
下一期：更多域、建议单草稿、视合规情况评估本地模型
```
