# 10 · 毕业答辩与返工清单

> 答辩对象可以是同事、架构师、或空气。标准不变：现场能跑，边界能讲，安全能展示。

---

## 1. 答辩结构（与能力地图 3.5 对齐）

1. 2 分钟：解决什么、不解决什么。  
2. 6 分钟：现场三问。  
3. 3 分钟：架构（ChatClient、Advisor、Tool、RAG、只读库）。  
4. 2 分钟：安全与成本。  
5. 2 分钟：下期。

---

## 2. 评委三句狠的（标准答法）

**数字从哪来的？**  
从只读决策库，经 Java 工具参数化查询。模型看不到数据库连接，只能看到工具返回的 JSON。

**如果模型胡说八道，用户怎么发现？**  
每条关键数字要求带来源与截止时间；页脚声明以源系统为准；我们用 20 问评测集回归；不允许无工具的数字。

**为什么不直接给管理层一个 BI 看板？**  
看板已经应该有。副驾补的是临时的、跨库存/采购/设备、需要解释口径的问题。两者共存，不是替换。

- [ ] 三域现场可问  
- [ ] 五段结构稳定出现  
- [ ] 来源可展示（至少工具）  
- [ ] 拒写、越权、注入至少各一次现场  
- [ ] 审计能还原演示中的提问  
- [ ] 评测集总分达标且必拒全过  
- [ ] 密钥不在 Git  
- [ ] 有非 LLM 的直查兜底  
- [ ] 你能不看讲义画出架构图

## 5. 主线毕业之后

按顺序：

1. `../part-09-工程化与上线/` 做灰度与成本  
2. `../extensions/` 换模型、本地、MCP  
3. 把评测集扩到 50 问，变成你们团队的回归资产  

不要毕业当天开始学 Ollama。先把 5 个试用用户服务稳。

## 6. 给你的一句收尾

你从「会写 Spring 接口」走到「能用 Advisor 链把模型关进只读工具笼子里」。  
这就是企业 Agent 开发者的日常，不是调一个聊天 API 的日常。

若某条毕业项没勾上——勾上再离开。半成品发给领导，会把后三个月的信任透支光。
