# 03 · 指标字典与口径对齐

> 同学们，管理层嘴里是中文，数据库里是英文字段。  
> 中间必须有一层 **指标字典**：中文名 → 官方 Tool → 固定 SQL → `dataAsOf` 规则。  
> 没有这层，Agent 就是在「编报表」。

---

## 1. 为什么需要指标字典

同一句「可用库存」，在不同公司可能指：

- 在库 − 预留
- 在库 − 预留 − 质检冻结
- 在库 − 预留 + 在途

**模型不知道你们选哪一种。** RAG 可以解释文字定义，但**数字必须走字典里登记的那条 SQL**。

指标字典是三方的合同：

```
业务方（中文名、口径说明）
        ↕
指标字典（metricId、SQL、Tool 名）
        ↕
开发（宽表、同步、Java Tool）
```

---

## 2. 本章演示指标字典（可直接当模板）

| metricId | 中文名 | 官方 Tool 方法 | 查询对象 | dataAsOf 来源 |
|---|---|---|---|---|
| `INV_AVAILABLE_QTY` | 库存可用量 | `InventoryQueryTool#queryAvailableInventory` | `vw_inventory_decision` | 行内 `data_as_of` 或 `sync_metadata.inventory` |
| `INV_LOW_STOCK_LIST` | 低库存清单 | `InventoryQueryTool#listLowAvailableInventory` | `vw_inventory_decision` | 同上 |

| `EMS_DOWNTIME_OVER_30M` | 停机超过30分钟 | `EquipmentQueryTool#queryDowntimeOver30Minutes` | `vw_downtime_decision` | `sync_metadata.downtime` |

## 3. 每条指标的口径正文（进 RAG + 字典备注）

### 3.1 INV_AVAILABLE_QTY · 库存可用量

**定义：** 指定租户、仓库、SKU 的 **可用量 = 在库数量 − 预留数量**。不含在途采购；质检冻结若未进预留字段，则不在本指标内（扩展需走变更流程）。

**官方 SQL 片段：**

```sql
SELECT available_qty, data_as_of
FROM vw_inventory_decision
WHERE tenant_id = :tenantId
  AND warehouse_id = :warehouseId
  AND sku_id = :skuId
LIMIT 1
```

**禁止：** 用 `on_hand_qty` 代替 `available_qty` 回答「能发多少」。

### 3.2 PO_OVERDUE_TOP · 超期采购

**定义：** 采购单状态为 `OPEN` 或 `PARTIAL`，**期望到货日早于当前日期**，且该行 **未到货数量 > 0**。

**排序：** `overdue_days DESC`，再 `pending_qty DESC`。

**不算超期：** 已 `CLOSED`；期望日到未来；已全部收货。

### 3.3 EMS_DOWNTIME_OVER_30M · 长停机

**定义：** 单次停机事件，从 `start_time` 到 `COALESCE(end_time, now)` 的时长 **≥ 30 分钟**。

**EMS 说明：** 本讲义 EMS = 设备 / 能源 / 运维系统。若公司是 **MES**，事件表字段可能叫 `work_center_id`，宽表仍产出 `production_line` + `duration_minutes`，Tool 接口不变。

**不算：** LINE-B 换型 15 分钟——视图已过滤。

## 4. 中文别名映射（给 Router / 提示词用）

模型选 Tool 前，可在 system 或轻量路由表里写：

| 用户可能说的词 | 映射 metricId |
|---|---|
| 可用、能发、可发、现货 | `INV_AVAILABLE_QTY` |
| 缺货、低库存、要补货 | `INV_LOW_STOCK_LIST` |
| 超期、晚了、没到货、采购拖期 | `PO_OVERDUE_TOP` |
| 停机、停线、故障、产线挂了 | `EMS_DOWNTIME_OVER_30M` |

**注意：** 别名只帮助**选 Tool**，不改变 SQL。若用户问「可用包不包括在途」，数字仍走 `INV_AVAILABLE_QTY`，**解释**走 RAG 制度文档。

## 5. 指标字典 YAML 示例（可放 `resources/metrics/`）

```yaml
metrics:
  - id: INV_AVAILABLE_QTY
    name: 库存可用量
    toolBean: inventoryQueryTool
    toolMethod: queryAvailableInventory
    requiredParams: [warehouseId, skuId]
    view: vw_inventory_decision
    syncDataset: inventory
    ragDocIds: [policy-inventory-available-v1]

  - id: PO_OVERDUE_TOP
    name: 超期采购订单
    toolBean: purchaseQueryTool
    toolMethod: queryOverduePurchaseTop
    requiredParams: []  # warehouseId 可选；tenant 强制在代码里
    view: vw_purchase_overdue_decision
    syncDataset: purchase
    ragDocIds: [policy-purchase-overdue-v1]

  - id: EMS_DOWNTIME_OVER_30M
    name: 停机超过30分钟
    toolBean: equipmentQueryTool
    toolMethod: queryDowntimeOver30Minutes
    requiredParams: []
    view: vw_downtime_decision
    syncDataset: downtime
    ragDocIds: [policy-downtime-v1]
```

上线前：**新增指标 = 新增字典行 + 宽表字段评审 + RAG 文档 + Tool 方法**，禁止「临时写 SQL」。

## 6. Tool 返回格式合同

所有指标 Tool 统一 JSON 形状（由 `ToolResultFormatter` 生成）：

```json
{
  "metricId": "INV_AVAILABLE_QTY",
  "metricName": "库存可用量",
  "dataAsOf": "2026-09-08 18:00:00 +08:00",
  "rowCount": 1,
  "rows": [
    {
      "warehouseId": "WH-EAST",
      "skuId": "SKU-1001",
      "availableQty": 450
    }
  ]
}
```

模型组织人话时必须引用 `dataAsOf`，例如：

> 华东仓 SKU-1001 当前可用 **450** 件，数据截至 **2026-09-08 18:00（东八区）**。

## 7. 与 RAG 的分工（复习）

| 问题类型 | 走哪条路 |
|---|---|
| 「可用量怎么算的？」 | RAG 制度 |
| 「华东仓 SKU-1001 可用多少？」 | Tool `INV_AVAILABLE_QTY` |
| 「可用怎么算，华东仓现在多少？」 | **先 Tool 出数，再 RAG 解释口径** |

---

## 8. 变更流程（生产必做）

1. 业务发口径变更申请（含中文定义、反例）。
2. 数据组改宽表 / 视图，更新 `sync_metadata` 说明。
3. 开发改 Tool SQL（或版本化 `metricVersion`）。
4. RAG 文档升版 `policy-*-v2`。
5. 回归三个必测问题 + 财务对账样本。
