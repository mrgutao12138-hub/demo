# 07 · 新鲜度对账与缓存

> 管理层第二句往往是：「这数什么时候的？」  
> 如果答不上来，第一句再准也白搭。  
> 这一节讲 `dataAsOf` 从哪来、怎么对账、什么时候可以缓存。

---

## 1. dataAsOf 的三层含义

| 层级 | 字段来源 | 表示什么 |
|---|---|---|
| **行级** | 宽表 `data_as_of` / `snapshot_at` | 这一行业务数据最后变更时间 |
| **数据集级** | `sync_metadata.last_sync_at` | 同步任务成功写入决策库的时间 |
| **响应级** | Tool JSON 顶层 `dataAsOf` | 对外展示用，取两者较保守者 |

规则（演示 Tool 已实现）：

```java
// 优先行级；列表查询用 sync_metadata
OffsetDateTime dataAsOf = resolveSyncTime(tenantId, "inventory");
if (!rows.isEmpty() && rows.get(0).get("dataAsOf") != null) {
    dataAsOf = (OffsetDateTime) rows.get(0).get("dataAsOf");
}
```

**回答模板：**

> 华东仓 SKU-1001 可用 **450** 件，数据截至 **2026-09-08 18:00（东八区）**，库存数据集同步于 **2026-09-08 18:00**。

若行级与数据集级相差 > 阈值（如 30 分钟），追加提示：

> 注意：该行快照与最近同步批次存在延迟，请以数据集同步时间为准联系 IT 对账。

---

## 2. sync_metadata 表（决策库「心跳」）

```sql
SELECT dataset_name, last_sync_at, source_system
FROM sync_metadata
WHERE tenant_id = 'TENANT-DEMO';
```

演示数据：

| dataset_name | last_sync_at | source_system |
|---|---|---|
| inventory | 2026-09-08 18:00 +08 | WMS |
| purchase | 2026-09-08 11:00 +08 | ERP |
| downtime | 2026-09-08 19:00 +08 | EMS |

**生产要求：**

- 同步任务**只有整批成功**才更新 `last_sync_at`。
- 失败不推进时间戳，Agent 侧可触发「数据暂不可用」降级文案。

---

## 3. 新鲜度 SLA 建议

| 数据集 | 典型 SLA | 超时用户可见文案 |
|---|---|---|
| 库存 | 5～15 分钟 | 「库存数据可能延迟 up to 15 分钟」 |
| 采购 | 15～60 分钟 | 「采购数据按小时同步」 |
| 停机 | 1～5 分钟 | 「停机事件近实时，仍非秒级」 |

SLA 写进 RAG 制度文档 + 指标字典备注，与 `dataAsOf` 一致。

## 4. 对账：决策库 vs 源系统

每周或每日批跑对账 SQL（**运维任务，不是 Agent Tool**）：

### 4.1 库存总量对账

```sql
-- 决策库
SELECT warehouse_id, SUM(available_qty) AS dm_total
FROM dm_inventory_snapshot
WHERE tenant_id = 'TENANT-DEMO'
GROUP BY warehouse_id;

-- 源 WMS（示意，在源库或同步中间层执行）
-- SELECT warehouse_id, SUM(on_hand - reserved) FROM wms_inventory GROUP BY warehouse_id;
```

差异 > 0.1% 告警，不自动改 Agent 口径。

### 4.2 超期采购笔数对账

```sql
SELECT COUNT(*) FROM vw_purchase_overdue_decision
WHERE tenant_id = 'TENANT-DEMO';
```

与 ERP 报表「超期未到」笔数比对。

### 4.3 停机事件条数

长停机条数日内波动大，对账重点看 **Top 事件 ID** 是否一致，而非总数。

## 5. 缓存策略（Tool 层）

### 5.1 什么时候可以缓存

| 可缓存 | 不可缓存 |
|---|---|
| 同一用户 60s 内重复问同一 `warehouseId+skuId` | 停机进行中（`is_ongoing=true`） |
| 低库存列表 TTL 120s | 采购刚审批后秒级追问 |
| 字典元数据、仓列表 | 任何写操作后的读 |

### 5.2 Caffeine 示例

```java
@Component
public class InventoryQueryCache {

    private final Cache<String, String> cache = Caffeine.newBuilder()
            .maximumSize(500)
            .expireAfterWrite(Duration.ofSeconds(60))
            .build();

    public String getOrLoad(String key, java.util.function.Supplier<String> loader) {
        return cache.get(key, k -> loader.get());
    }

    public static String key(String tenantId, String warehouseId, String skuId) {
        return tenantId + "|" + warehouseId + "|" + skuId;
    }
}
```

在 `queryAvailableInventory` 里：

```java
String cacheKey = InventoryQueryCache.key(tenantId, warehouseId, skuId);
return cache.getOrLoad(cacheKey, () -> doQuery(...));
```

**缓存键必须含 `tenantId` + 用户仓权版本**，防止换用户串数据。

### 5.3 返回里标明是否缓存（可选）

```json
{
  "metricId": "INV_AVAILABLE_QTY",
  "dataAsOf": "2026-09-08 18:00:00 +08:00",
  "cached": true,
  "cacheAgeSeconds": 12
}
```

管理层场景默认 `cached: false` 也可，但 `dataAsOf` **必须有**。

## 6. 降级策略

| 条件 | Agent 行为 |
|---|---|
| 决策库连接失败 | 「决策数据暂不可用，请稍后再试」；不调模型编造 |
| `last_sync_at` 超过 SLA 2 倍 | 仍返回数据，但强制附加延迟警告 |
| 同步任务失败 | 拒答或只答 RAG 口径、不答数字 |
| 只读账号权限异常 | 告警 + 拒答 |
