# 01 · 四种数据接入模式与为什么宽表优先

> 同学，接入企业数据不是「连上库就行」。  
> 你要在**安全、口径、延迟、可维护**之间做工程选择。  
> 这一节把四条路讲透，并给出老师推荐的演进顺序。

---

## 1. 先统一目标：什么是「只读决策数据源」

对 Agent 而言，ERP/WMS/EMS 不是「另一个 ORM 模块」，而是：

```
生产系统（可写、复杂、慢变）
        │  同步 / API
        ▼
决策读模型（只读、口径固定、可审计）
        │  Java Tool（参数校验 + 指标字典）
        ▼
大模型（只读 Tool 返回的 JSON 文本）
```

**决策数据源**的特征：

- 只回答**已定义**的管理问题，不开放任意 SQL。
- 每次返回带 **`dataAsOf`**，管理层能判断「这数有多新」。
- **租户、仓库**在 Tool 层强制过滤，不能靠模型「自觉」。

---

## 2. 模式 1：调现成 HTTP/RPC API

### 2.1 是什么

公司里已经有人做了「库存查询服务」「采购在途服务」，对外是 REST 或 Dubbo。  
你的 Tool 里用 `RestClient` / `WebClient` 调这些接口，把 JSON 转成模型可读的字符串。

### 2.2 优点

- **不碰数据库权限**，DBA 最省心。
- 口径在查询服务里已封装，和现有报表一致。
- 适合**试点第一周**：先让 Agent 能答管理层问题。

### 2.3 缺点

- 接口粒度常不匹配 Agent 问题（要调 3 个 API 才能拼一句话）。
- 延迟与限流受上游影响；链路上难统一 `dataAsOf`。
- 版本碎片化：ERP 升版，你要跟一堆 API 变更。

### 2.4 适用场景

| 适合 | 不适合 |
|---|---|
| 已有成熟查询中台 | 只有库、没有 API |
| 试点、接口 ≤ 5 个 | 需要复杂 join、宽表分析 |
| 短期 1～2 个月验证价值 | 长期统一决策口径 |

### 2.5 Tool 写法要点

```java
@Tool(description = "查询某仓某 SKU 可用库存（走库存查询服务官方 API）")
public String queryAvailableInventory(String warehouseId, String skuId) {
    access.assertWarehouseAccessible(warehouseId);
    // RestClient 调 /api/v1/inventory/available?warehouseId=&skuId=
    // 禁止把 API Key、写接口 URL 暴露给模型
}
```

**仍然遵守：** 一 Tool 一业务能力；强制 `warehouseId`；返回里拼 `dataAsOf`（取 API 的 `lastUpdated` 字段）。

---

## 3. 模式 2：只读数据库账号 + 视图

### 3.1 是什么

DBA 给 Agent 应用一个**只读账号**，只能 `SELECT` 若干**视图**（或宽表）。  
Java 用 **参数化 SQL** 查视图，例如：

```sql
SELECT available_qty, data_as_of
FROM vw_inventory_decision
WHERE tenant_id = :tenantId
  AND warehouse_id = :warehouseId
  AND sku_id = :skuId
LIMIT 1
```

### 3.2 优点

- 比模式 1 灵活，复杂 join 在视图里一次做完。
- 实施快：不必立刻搭同步链路。
- 视图即「口径合同」，改视图等于改官方定义。

### 3.3 缺点（重要）

- 只读账号若在同一**生产实例**上，仍有**负载、误连、网络暴露**风险。
- 生产表结构变更可能**弄坏视图**，Agent 夜间报错。
- 多系统（ERP+WMS+EMS）跨库 join 往往做不了，仍要 ETL。

### 3.4 硬性要求

| 要求 | 错误示范 |
|---|---|
| `NamedParameterJdbcTemplate` / MyBatis `#{}` | `"WHERE sku_id = '" + skuId + "'"` |
| 禁止 DDL/DML 权限 | `GRANT INSERT` 给 Agent 账号 |
| 只授视图 `SELECT` | `GRANT SELECT ON 全库` |
| 强制 `tenant_id` | 只靠 `warehouseId` 隐式过滤 |

### 3.5 适用场景

**过渡态**：已有 Postgres/MySQL，想两周内接上 Agent；同时规划迁到模式 3。

---

## 4. 模式 3：同步决策宽表到独立 Postgres（主推荐）

### 4.1 是什么

从 ERP/WMS/EMS **抽取**（CDC、定时批、消息队列）到**独立决策库**（本章演示就是这颗 Postgres）。  
Agent 只连决策库；生产写库与 Agent **网络隔离**。

```
ERP ──┐
WMS ──┼──► 同步任务 ──► decision_postgres（宽表 + sync_metadata）
EMS ──┘                        │
                               ▼
                        只读 JDBC + Tool
```

### 4.2 为什么主推荐

| 维度 | 模式 2 连生产 | 模式 3 独立宽表 |
|---|---|---|
| 安全 | 同实例，风险共担 | 物理/逻辑隔离 |
| 性能 | 怕拖慢生产 | 可建索引、物化表 |
| 口径 | 视图分散多库 | 宽表统一「决策语义」 |
| 新鲜度 | 各表 `updated_at` 不一 | `sync_metadata` 统一对外 |
| 审计 | 难分清 Agent 查询 | 决策库访问日志独立 |

### 4.3 宽表长什么样

演示库里的三个决策面（详见 `02`）：

1. `vw_inventory_decision` / `dm_inventory_snapshot` — 库存可用
2. `vw_purchase_overdue_decision` — 超期采购
3. `vw_downtime_decision` — 停机 ≥ 30 分钟

生产可把视图**物化**为 `dm_*` 表，按 5～15 分钟刷新；`sync_metadata.last_sync_at` 写入批次时间。

### 4.4 同步要注意什么

- **幂等**：按 `(tenant_id, 业务主键)` upsert。
- **延迟可接受**：管理层决策多数 tolerate 5～15 分钟；在 `dataAsOf` 里诚实标注。
- **不反向写**：决策库任何账号都不应有写回 ERP 的链路。

## 5. 模式 4：受控 Text-to-SQL（默认不作主路径）

### 5.1 是什么

让模型生成 SQL，在**极窄环境**里执行，返回结果。  
听起来灵活，本质是**把数据库的一部分读权限交给概率模型**——必须关进笼子（详见 `06`）。

### 5.2 笼子清单（预览）

- 白名单表/视图 only
- 只读数据库用户
- 执行前 `EXPLAIN`，拒绝全表扫过大
- `LIMIT` 强制上限
- 禁止 `INSERT/UPDATE/DELETE/DDL`
- **强制** `tenant_id = :currentTenant` 注入（模型生成的 WHERE 不够，要在包装层追加）

### 5.3 为什么不默认主路径

- 模型会**幻觉列名**、**漏 join 条件**、**用错聚合**。
- 同一句中文，两次生成 SQL 可能不一致，**口径无法审计**。
- 安全笼子再严，也挡不住「合法但巨慢」的查询。

**老师立场：** 模式 4 可作为**少数分析员**的后门，不能替代模式 3 的**指标字典 + 固定 Tool**。

---

## 6. 推荐演进（按公司成熟度）

### 阶段 A：价值验证（2～4 周）

- 有 API → **模式 1**，3 个 Tool 覆盖 3 类必问。
- 无 API → **模式 2** 只读视图，仍只 3 个 Tool。

### 阶段 B：口径固化（1～2 月）

- 立项 **模式 3** 决策库；先把库存、超期采购、停机三张宽表同步过来。
- 指标字典（`03`）评审通过；RAG 存口径说明，Tool 存数字。

### 阶段 C：规模化

- 按领域加 Tool（仍是一 Tool 一能力），宽表按需扩展。
- 模式 4 仅对**白名单分析场景**开放，且与主 Agent **分路由**。

---

## 7. 四种模式对照总表

| | 模式 1 API | 模式 2 只读视图 | 模式 3 宽表同步 | 模式 4 Text-to-SQL |
|---|:---:|:---:|:---:|:---:|
| 实施速度 | ★★★★★ | ★★★★ | ★★★ | ★★ |
| 安全隔离 | ★★★★ | ★★ | ★★★★★ | ★★ |
| 口径可控 | ★★★ | ★★★★ | ★★★★★ | ★ |
| 灵活探索 | ★★ | ★★★ | ★★★ | ★★★★★ |
| 适合 Agent 主路径 | 试点 | 过渡 | **生产默认** | 非默认 |
