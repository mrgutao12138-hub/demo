# 03 · 描述、参数、失败、超时与权限

> 工具写得好不好，模型会不会乱调，一半看 **description**，一半看 **Java 护栏**。  
> 这一节把「像玩具」改成「像企业演示」。

---

## 1. description 是工具的「招聘 JD」

模型选工具，主要靠：

1. 工具名（动词短语，英文）
2. **description**（中文写清：做什么、何时用、不要做什么）
3. 参数的 `@ToolParam` 说明

### 1.1 坏例子

```java
@Tool(description = "查库存")
public String queryInventory(String skuId, String warehouseId) { ... }
```

模型不知道：要不要先 `getSku`？「A仓」算不算合法参数？能不能用来改数？

### 1.2 好例子（本章标准）

```java
@Tool(description = """
        查询指定仓库、指定 SKU 的库存快照：可用量、在途量、数据更新时间。
        适用于：用户明确给了仓和 SKU，问「有多少库存」。
        warehouseId 必须是 WH-A、WH-B、WH-C 之一；用户说 A仓 对应 WH-A。
        只读；禁止用于修改库存。不要在没有 SKU 时编造数量。
        """)
```

**老师口诀：** 像给新同事写 SOP——什么时候用、什么时候别用、红线写最后一行。

## 2. @ToolParam 与可选参数

```java
@Tool(description = "按条件查库存列表")
public String searchInventory(
        @ToolParam(description = "SKU 编号，必填") String skuId,
        @ToolParam(description = "仓库编码，不填则查全部授权仓", required = false) String warehouseId) {
    ...
}
```

2.0 规则：

- 默认**全部必填**
- `@ToolParam(required = false)` **或** 参数类型上的 `@Nullable`（JSpecify）→ JSON Schema 里为 optional
- 不要用 `Optional<T>` 作参数类型——用 `@Nullable` 代替

返回复杂对象可以，但建议工具返回 **模型好读的字符串** 或简单 DTO（Jackson 序列化）。管理层场景，字符串更可控。

## 3. returnDirect 与 resultConverter

### 3.1 returnDirect

```java
@Tool(description = "检索制度原文", returnDirect = true)
public String fetchPolicyClause(String clauseId) { ... }
```

为 `true` 时，`ToolCallingAdvisor` 执行完工具**直接返回**给用户，不再问模型。

库存场景**默认 false**——要让模型套「结论 / 数字 / 依据」结构。

注意：同一轮模型请求多个工具时，**只有全部** `returnDirect=true` 才会短路。

### 3.2 resultConverter

当返回值是复杂对象、或你想统一成表格文本：

```java
@Tool(description = "...", resultConverter = InventoryLineConverter.class)
public InventoryLine query(...) { ... }
```

实现 `ToolCallResultConverter`，在进 `ToolResponseMessage` 前转换。  
学习阶段可先手写 `String.format`，够用了再抽象。

## 4. 失败处理：给模型可读错误，不给堆栈

【红线】工具内部 `catch`，返回业务语义：

```java
try {
    return doQuery(...);
} catch (IllegalArgumentException e) {
    return "查询失败：" + e.getMessage() + "。请让用户确认仓位编码或 SKU。";
} catch (Exception e) {
    log.warn("queryInventory unexpected", e);
    return "系统繁忙，暂时无法查询库存，请勿编造数字。";
}
```

**不要** `throw new RuntimeException(e)` 甩给 `ToolCallingManager`——用户可能看到堆栈，模型也可能胡编补救数字。

### 4.1 失败类型对照

| 场景 | 工具返回给模型 | 用户最终体验 |
|---|---|---|
| SKU 不存在 | 「SKU 不存在: xxx」 | 请核对编号 |
| 仓位越权 | 「仓位不在白名单」 | 无权查看 |
| 下游超时 | 「查询超时，请稍后重试」 | 不编造数 |
| 模型参数 JSON 错了 | 框架层报错 | 一般重试或换问法 |

## 5. 超时

工具背后是 HTTP / JDBC 时，必须有超时。

```java
@Tool(description = "...")
public String queryInventory(String skuId, String warehouseId) {
    try {
        return CompletableFuture
                .supplyAsync(() -> remoteWmsClient.query(skuId, warehouseId))
                .orTimeout(3, TimeUnit.SECONDS)
                .join();
    } catch (TimeoutException e) {
        audit.record("queryInventory", summary, false, 3000);
        return "查询超时（3s），请勿编造库存数字。";
    }
}
```

演示项目用内存 `Map` 可不加；但 **Controller 或 Advisor 层** 仍建议给整次 `call()` 设上限（见下一章 max 迭代）。

## 6. 权限与 warehouseId 校验

【红线】**永远不要**相信模型传来的 `warehouseId`。

```java
private static final Set<String> ALLOWED = Set.of("WH-A", "WH-B", "WH-C");

public InventoryLine query(String skuId, String warehouseId, String userId) {
    if (!ALLOWED.contains(warehouseId)) {
        throw new IllegalArgumentException("仓位不在白名单: " + warehouseId);
    }
    if (!authService.canViewWarehouse(userId, warehouseId)) {
        throw new IllegalArgumentException("用户无权查看该仓");
    }
    // ...
}
```

学习阶段 `userId` 可写死 `"demo-manager"`；part-06 接真权限。

### 6.1 防注入

若参数将来进 SQL：

- 只用 `PreparedStatement` / JPA 命名参数
- `warehouseId` 正则 `^WH-[A-Z0-9]+$`，不匹配直接拒
- 绝不把用户原话拼进 SQL

## 7. 审计：tool 名 + 参数摘要

每个工具入口：

```java
audit.record("queryInventory", "skuId=" + skuId + ",warehouseId=" + warehouseId, success, costMs);
```

**记什么：** 工具名、关键业务键、成功否、耗时  
**不记什么：** 完整手机号、密钥、大段 PII

part-07 会把审计接到 Micrometer；本章 SLF4J 够用。

## 8. 三种定义方式下的同一原则

| 方式 | description 在哪写 | 失败谁处理 |
|---|---|---|
| `@Tool` | 注解上 | 方法内 catch |
| `MethodToolCallback` | `ToolDefinitions.builder(method).description(...)` | 同上 |
| `FunctionToolCallback` | `.description(...)` | Lambda 内 catch |

```java
@Bean
ToolCallback weatherTool(WeatherService svc) {
    return FunctionToolCallback.builder("currentWeather", (WeatherRequest req) -> {
        try {
            return svc.fetch(req);
        } catch (Exception e) {
            return "天气查询失败：" + e.getMessage();
        }
    })
    .description("查询城市天气，只读")
    .inputType(WeatherRequest.class)
    .build();
}
```

2.0：**必须**把 `ToolCallback` 显式传给 `ChatClient`，不能 `toolNames("currentWeather")`。
