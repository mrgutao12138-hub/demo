> 同学，欢迎来到主线里最重要的一章。

## 1. 你现在在哪

你已经会：

- 用 `ChatClient` 做同步、流式、结构化输出
- 配 `defaultSystem`、多个 `ChatClient` Bean
- 知道 Advisor 是「可重入的拦截器链」

你还不会：

- 模型怎么「点菜」、你的 Java 怎么「做菜」
- 一次用户问题背后，模型可能打几次 API
- 工具失败、超时、越权时，用户该看到什么
- 记忆该不该记住「中间那几次工具调用」

**这两周的目标：用模拟库存数据，写出第一个真 Agent。**

## 4. 本章唯一业务场景：模拟库存

全章统一用一个假 WMS，数据在内存 `Map` 里，不接真库：

| 工具 | 作用 | 有没有 |
|---|---|---|
| `getSku` | 查 SKU 名称、规格、单位 | ✅ |
| `queryInventory` | 查某仓某 SKU 的可用量、在途、更新时间 | ✅ |
| `compareWarehouses` | 对比各仓同一 SKU，给补货倾向 | ✅ |
| `updateInventory` | 改库存 | ❌ **故意不提供** |

系统提示里写死：**禁止执行任何写操作；没有改库存工具；用户要求改数必须礼貌拒绝。**

## 5. Spring AI 2.0 本章必须刻进脑子的一句话

> **工具循环在 `ChatClient` 的 `ToolCallingAdvisor` 里，不在 `ChatModel` 内部。**

1.x 时代各模型自己藏一套循环；2.0 把它提到 Advisor 链上，你才能插记忆、审计、限流。

配套事实（后面每节会展开）：

- `DefaultChatClient` 自动注册**恰好一个** `ToolAdvisor`（默认是 `ToolCallingAdvisor`）
- 流程：Tool Definition → 模型可能返回 tool calls → `ToolCallingManager` 执行 → 结果当 `ToolResponse` 回填 → 循环直到没有 tool calls
- 删除了 `SpringBeanToolCallbackResolver`、`toolNames()`、`internalToolExecutionEnabled`、`streamToolCallResponses`
- `spring.ai.chat.client.tool-calling.enabled=false` 可关自动执行
- `DeepSeekChatModel` 支持 tool calling

## 6. 【红线】本章反复出现，考前默写

1. **工具 = 受控 Java。** 模型不碰数据库；它只拿到你方法的返回值字符串。
2. **只读。** 学习阶段不提供任何写工具；综合项目里「建议补货」也只出建议单。
3. **校验 `warehouseId`。** 白名单 + 当前用户有权看的仓；SQL 片段、路径穿越一律拒。
4. **限制 max 迭代。** 工具循环要有上限，防模型反复查同一仓。
5. **审计 tool 名和参数摘要。** 日志里要有「调了什么、参数摘要、耗时」；不记完整隐私字段。

这五条不是「最佳实践」，是**不及格线**。

## 7. 本周三个必测用户问题（先记下来）

学完要在自己项目上跑通：

1. 「A 仓 SKU-1001 现有多少可用库存？」
2. 「对比 A 仓和 B 仓 SKU-1001，哪个更该补货？」
3. 「帮我把 A 仓 SKU-1001 库存改成 0。」——**必须被拒绝**

三次调用的工具轨迹写进日志或笔记。验收细节见 `08-本阶段验收三个必测问题.md`。

## 8. 【易混】网上旧教程，本章直接划掉

| 旧写法（1.x） | 2.0 怎么办 |
|---|---|
| `.toolNames("xxx")` | 删掉；必须 `.tools(...)` 或 `defaultTools` 显式传 `ToolCallback` / `@Tool` 对象 |
| `SpringBeanToolCallbackResolver` | 已删除；用 `FunctionToolCallback.builder()` 注册 `@Bean` |
| `internalToolExecutionEnabled` | 已删除；循环只在 `ToolCallingAdvisor` |
| 在 `ChatModel` 里指望自动执行工具 | 业务走 `ChatClient`；底层 `ChatModel` 仅在你手写循环时用 |
| MCP 加 starter 就自动进 ChatClient | **不会**；要注入 `SyncMcpToolCallbackProvider` 再 `.tools(mcpTools)` |
