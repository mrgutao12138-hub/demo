# 05 · 记忆放循环内还是循环外

> 很多同学栽在记忆上：不是「记不住」，是「记错了东西」。  
> 2.0 用 **Advisor order** 决定记忆能看到什么。

---

## 1. 先记两个默认数字

| Advisor | 默认 order | 位置 |
|---|---|---|
| `MessageChatMemoryAdvisor` | `HIGHEST_PRECEDENCE + 200` | **循环外**（默认） |
| `ToolCallingAdvisor` | `HIGHEST_PRECEDENCE + 300` | 工具循环本身 |

数字越小，越靠外层。  
200 < 300 → 记忆在**工具循环外面**。

---

## 2. 循环外记忆（默认，推荐）

```
用户第 N 轮问题
    │
    ▼
MessageChatMemoryAdvisor (200)
    │  加载历史：只有过往「用户一句 + 助手最终一句」
    ▼
ToolCallingAdvisor (300)  ═══ 内部可能多轮 tool ═══
    │
    ▼
MessageChatMemoryAdvisor (200)
       只保存：本轮 user + 最终 assistant
       （不保存 tool request / tool response）
```

### 2.1 优点

- **任何** `ChatMemoryRepository` 都能用（JDBC、Mongo 等大多只懂 user/assistant）
- 和 1.x 行为一致：用户感觉不到「中间工具细节」
- token 省：历史里不堆工具 JSON

### 2.2 缺点

- 下一轮对话，模型**不记得**上一轮中间调了哪些工具——只记得最终结论
- 对管理层问答通常**够用**：「上次你说 A 仓 128 件」在最终 assistant 里已有

### 2.3 配置示例

```java
ChatMemory chatMemory = MessageWindowChatMemory.builder()
        .chatMemoryRepository(new InMemoryChatMemoryRepository())
        .maxMessages(20)
        .build();

ChatClient client = ChatClient.builder(chatModel)
        .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
        .defaultTools(inventoryTools)
        .build();

// 每次请求必须带会话 ID（2.0 强制）
client.prompt()
        .user("继续刚才那个 SKU")
        .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, "mgr-zhang-session-1"))
        .call();
```

【易混】2.0 删除了 `PromptChatMemoryAdvisor` 和 builder 上的 `.conversationId(...)`。  
会话 ID **每次**通过 `ChatMemory.CONVERSATION_ID` 传入。

---

## 3. 循环内记忆（高级，慎用）

若要让**下一轮**还记得「上次试过 WH-C 没货」这类工具轨迹，把 memory advisor 放到 **order > 300**：

```java
var memoryInside = MessageChatMemoryAdvisor.builder(chatMemory)
        .order(BaseAdvisor.HIGHEST_PRECEDENCE + 400)  // 在 ToolCallingAdvisor 里面
        .build();

ChatClient.builder(chatModel)
        .defaultAdvisors(memoryInside)
        .defaultTools(inventoryTools)
        .build();
```

此时：

- 每轮工具 request/response 都可能写入 memory
- `DefaultChatClient` 会**自动**对 `ToolCallingAdvisor` 调用 `disableInternalConversationHistory()`，避免重复写两份历史

若你**手动** `ToolCallingAdvisor.builder()`，要自己 `.disableInternalConversationHistory()`。

---

## 4. 仓库兼容性【必记】

并非所有 `ChatMemoryRepository` 都能存 **tool 消息**。

2.0 内置里，完整支持 tool 消息的有：

- `InMemoryChatMemoryRepository`
- `RedisChatMemoryRepository`
- `Neo4jChatMemoryRepository`

JDBC、Mongo 等**多数**只能存 user/assistant。  
循环内记忆若用不兼容仓库，会丢消息或报错。

**老师建议：** 学习期与第一版生产都用 **循环外记忆**；循环内留给确有「多步推理要跨轮记住」的场景。

---

## 5. ToolCallingAdvisor 内部历史 vs Memory Advisor

| 机制 | 作用范围 | 谁管 |
|---|---|---|
| `conversationHistoryEnabled`（默认 true） | **单次** `call()` 内的多轮 tool | `ToolCallingAdvisor` 内部 |
| `MessageChatMemoryAdvisor` | **跨请求** 的多轮对话 | ChatMemory |

循环外记忆时：

- **单次请求内**：Advisor 内部历史让模型看见本次 `getSku` → `queryInventory` 的链条
- **跨请求**：只记最终问答

---

## 6. 和库存 Agent 怎么配

演示项目可以**先不加记忆**，专注工具。  
要加，推荐循环外：

```java
@Bean
ChatClient inventoryAgent(ChatClient.Builder builder,
                        InventoryTools tools,
                        ChatMemory chatMemory) {
    return builder
            .defaultSystem(AgentConfig.INVENTORY_SYSTEM)
            .defaultTools(tools)
            .defaultAdvisors(
                    MessageChatMemoryAdvisor.builder(chatMemory).build(),
                    new SimpleLoggerAdvisor())
            .build();
}
```

Controller 增加 `conversationId` 字段，传给 `ChatMemory.CONVERSATION_ID`。
