# 04 · 多工具编排与停止条件

> 真 Agent 很少「一问一工具」。  
> 这一节学：模型怎么串工具、你怎么让它**停下来**。

---

## 1. 多工具编排：谁决定顺序？

**模型决定**调用哪些工具、什么顺序、调几次。  
**你决定**提供哪些工具、每次返回什么、最多循环几轮。

典型模式：

| 用户意图 | 可能轨迹 |
|---|---|
| 「SKU-1001 是什么？A 仓多少？」 | `getSku` → `queryInventory` |
| 「对比 A、B 仓 SKU-1001」 | `compareWarehouses` **或** 两次 `queryInventory` |
| 「哪个仓最紧缺？」 | `compareWarehouses` 一次即可 |

不必强行规定顺序——靠 **description** 引导。若你发现模型总多调一次，再收紧 system 或合并工具（`compareWarehouses` 就是合并思路）。

---

## 2. 一次请求里的时间线（对比题）

用户：「对比 A 仓和 B 仓 SKU-1001，哪个更该补货？」

```
轮次1  用户问题 + 3 个 Tool Definition
       → 模型：tool_call compareWarehouses(skuId=SKU-1001)
       → Java 执行，返回各仓快照字符串

轮次2  历史 + ToolResponse
       → 模型：无 tool_call，生成管理层话术
       → 结束
```

也可能：

```
轮次1  → queryInventory(WH-A)
轮次2  → queryInventory(WH-B)
轮次3  → 文字总结
```

两种都对。**验收看数字是否来自工具**，不看必须调几次。

## 3. 停止条件（默认就够，但要会改）

`ToolCallingAdvisor` 默认：

```java
response != null && response.hasToolCalls()
```

为真就继续；否则返回最终文本。

### 3.1 你还可以用的停止手段

| 手段 | 用途 |
|---|---|
| **max 工具轮次** | 防死循环（下面有示例） |
| **returnDirect** | 工具结果即最终答案 |
| **自定义 ToolExecutionEligibilityChecker** | 按 finishReason 等细控 |
| **关 tool-calling** | 只让模型「说想调工具」，不真执行 |

### 3.2 【必做】限制 max 迭代

模型可能反复 `queryInventory` 同一参数。必须设上限。

**方式 A：自定义观察 Advisor（推荐学习）**

在 order `400`（> ToolCallingAdvisor 的 300）放计数器：

```java
public class ToolIterationLimitAdvisor implements CallAdvisor, StreamAdvisor {

    private final int maxIterations;
    private static final ThreadLocal<Integer> COUNT = ThreadLocal.withInitial(() -> 0);

    public ToolIterationLimitAdvisor(int maxIterations) {
        this.maxIterations = maxIterations;
    }

    @Override
    public int getOrder() {
        return Ordered.HIGHEST_PRECEDENCE + 400;
    }

    @Override
    public ChatClientResponse adviseCall(ChatClientRequest request, CallAdvisorChain chain) {
        ChatClientResponse response = chain.nextCall(request);
        if (response.chatResponse() != null && response.chatResponse().hasToolCalls()) {
            int n = COUNT.get() + 1;
            COUNT.set(n);
            if (n > maxIterations) {
                throw new IllegalStateException(
                        "工具循环超过上限 " + maxIterations + " 次，已中止以防死循环");
            }
        } else {
            COUNT.remove();
        }
        return response;
    }

    @Override
    public Flux<ChatClientResponse> adviseStream(ChatClientRequest request, StreamAdvisorChain chain) {
        return chain.nextStream(request).doOnNext(r -> {
            if (r.chatResponse() != null && r.chatResponse().hasToolCalls()) {
                int n = COUNT.get() + 1;
                COUNT.set(n);
                if (n > maxIterations) {
                    throw new IllegalStateException("工具循环超过上限");
                }
            }
        }).doOnComplete(COUNT::remove);
    }
}
```

注册：

```java
.defaultAdvisors(
    new SimpleLoggerAdvisor(),
    new ToolIterationLimitAdvisor(5)  // 学习期 5 次足够
)
```

**方式 B：业务层 try-catch**，超限返回固定文案给用户。

【红线】生产建议 **3～8 次**，按工具成本调整；绝不能无限循环。

## 4. 拒写：没有工具 + system 双保险

用户：「帮我把 A 仓 SKU-1001 库存改成 0」

期望：

1. **没有** `updateInventory` 工具
2. system 写明禁止写操作
3. 模型直接文字拒绝；**不应**出现写工具日志

若模型仍尝试调用不存在的工具名，`ToolCallingManager` 会报错——此时应在工具层或全局处理成「无此操作权限」。

可选加固：在 system 里列 **允许工具白名单**：

```text
你只能使用：getSku、queryInventory、compareWarehouses。
任何修改、删除、下单请求一律拒绝。
```

## 5. 混合工具类型

```java
chatClient.prompt()
    .user("...")
    .tools(
        inventoryTools,                    // @Tool 对象
        legacyMethodCallback,              // MethodToolCallback
        weatherFunctionCallback            // FunctionToolCallback Bean
    )
    .call();
```

与 `defaultTools` 是**并集**。危险工具不要放 `defaultTools`，按请求加。

## 6. 观察循环内部（不用删 ToolCallingAdvisor）

order > 300 的 Advisor 在**每一轮**都会被调用：

```java
// order = HIGHEST_PRECEDENCE + 400
public class ToolCallObservingAdvisor implements CallAdvisor, StreamAdvisor {
    @Override
    public ChatClientResponse adviseCall(ChatClientRequest request, CallAdvisorChain chain) {
        request.prompt().getInstructions().forEach(msg ->
                log.debug("迭代消息: {}", msg.getMessageType()));
        ChatClientResponse response = chain.nextCall(request);
        if (response.chatResponse() != null && response.chatResponse().hasToolCalls()) {
            response.chatResponse().getResult().getOutput().getToolCalls()
                    .forEach(tc -> log.info("模型请求工具: {} args={}", tc.name(), tc.arguments()));
        }
        return response;
    }
    // getOrder() = 400; adviseStream 同理
}
```

【易混】2.0 **删除**了 `streamToolCallResponses`。不要找这个配置；用观察 Advisor。

## 7. 关闭自动执行（对比实验）

全局：

```yaml
spring.ai.chat.client.tool-calling.enabled: false
```

单次：

```java
chatClient.prompt()
    .user("...")
    .tools(inventoryTools)
    .advisors(AdvisorParams.toolCallingAdvisorAutoRegister(false))
    .call();
```

此时模型可能返回 tool calls，但 **不会执行**。用于调试「模型想调什么」，或你自己用 `ToolCallingManager` 手写循环（高级，主线可不写）。
