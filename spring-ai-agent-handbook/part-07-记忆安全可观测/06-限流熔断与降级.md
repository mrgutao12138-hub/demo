# 06 · 限流、熔断与降级

> 模型是外部依赖，和支付网关同一类：会慢、会 429、会挂。  
> 你的 Java 服务不能一起殉葬。

---

## 1. 限流：先限人，再限系统

### 1.1 按用户

```text
每用户每分钟 ≤ 8 次提问
每用户每天 ≤ 80 次，或每天 token 预算 ≤ 某值
```

超限返回：

> 今日问答次数已达上限。紧急数据请直接打开 WMS 看板，或联系管理员提额。

### 1.2 按工具

`queryInventory` 可以松，`compareAllWarehouses` 这种重查询要更严。  
在工具第一行计数，超了返回「该分析太重，请缩小到具体仓或 SKU」。

### 1.3 全局限流

保护下游 DeepSeek 配额和数据库：

- 信号量：同时只有 N 个模型请求。
- 线程池与 MVC 的隔离：不要用 Tomcat 工作线程直接阻塞堆超长思考。思考模式请求用独立超时。

学习期用 Guava RateLimiter 或简单计数器即可。生产用网关限流 + Resilience4j。

---

## 2. 超时

建议默认：

| 环节 | 超时 |
|---|---|
| 单次工具 SQL | 3s |
| 单次模型 HTTP（flash） | 20s |
| 单次模型 HTTP（pro+thinking） | 60s |
| 整个用户请求 | 75s |
| 工具循环最大轮次 | 6 |

循环必须有硬顶。模型若反复调同一个失败工具，到顶就停，返回：

> 我多次查询仍未拿到完整数据。请稍后重试，或缩小问题范围。已尝试的工具：queryInventory。

---

## 3. 熔断

当 DeepSeek 连续失败（5xx、超时、429）：

1. 打开熔断，60 秒内新请求不再出网。
2. 返回降级（见下）。
3. 半开：放一个探针请求。

429 要尊重对方的退避。Spring AI 有 `spring.ai.retry.*`：默认会重试。你需要避免「重试把限流打得更狠」——对 429 用指数退避，且 `on-client-errors` 保持 false（4xx 大多不该盲重试，429 可单独当瞬态处理）。

---

## 4. 降级产品怎么做才不像死了

优先级从高到低：

1. **读缓存的上次查询结果**（带明确过期时间）：「以下为 10 分钟前缓存，非实时。」
2. **引导去看板：** 返回固定链接「库存看板 / 采购超期报表」。
3. **只答口径，不答数字：** RAG 仍可工作（若 embedding 本地）。「我暂时连不上模型分析，但这是可用库存口径：……数字请看系统。」——仅当有本地小模型或固定 FAQ 时。
4. **诚实失败：** 「AI 分析暂时不可用。」不要用假数字填空。

【红线】降级时编造库存数字，比系统报错更坏。

---

## 5. 模型挂了，工具还在

可以把「紧急查数」做成**不经过模型**的 REST：`GET /api/inventory?sku=&wh=`。  
管理层 App 里「AI 对话」旁边留「直接查」。Agent 是增强，不是唯一门。

这也能让安全部门放心：核心查数路径仍是普通 Java API。

## 6. 代码骨架

```java
@Service
public class DecisionFacade {

    public DecisionReply ask(UserScope scope, String cid, String question) {
        rateLimiter.check(scope.userId());
        try {
            return circuitBreaker.executeSupplier(() -> chatService.ask(scope, cid, question));
        } catch (CallNotPermittedException e) {
            return DecisionReply.degraded("模型通道繁忙或上游不可用，请使用库存查询页，或 1 分钟后重试。");
        } catch (TimeoutException e) {
            return DecisionReply.error("分析超时。请把问题改成单仓、单 SKU 再试。");
        }
    }
}
```

## 7. 【必做】

1. 给提问接口加上每用户每分钟限流。
2. 工具循环 max 设死。
3. 模拟：把 API Key 改错，用户看到降级文案而不是堆栈。
4. 提供一个不经过 LLM 的只读查询接口。
