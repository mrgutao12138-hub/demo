# 04 · 脱敏、密钥与写操作红线

> 这一篇全是红线。可以印在工位上。

---

## 1. 密钥

1. API Key 只放环境变量或密钥托管（Vault、云 KMS）。
2. `application.yml` 里只写 `${DEEPSEEK_API_KEY}`。
3. 日志框架把 `api-key`、`authorization`、`sk-` 加入脱敏。
4. 禁止把 Key 配进 Docker 镜像层；用运行时注入。
5. Key 泄露：立即在开放平台作废、换新、查审计里泄露窗口期的调用。
6. 开发用自己的 Key，试用用公司专用 Key，不要混。公司 Key 开限额。

Git 钩子建议：扫描 `sk-` 、`DEEPSEEK_API_KEY=` 后跟非占位符。

---

## 2. 脱敏：进模型之前

模型提供商会按他们的协议处理数据。你能控制的是**送出去之前**。

典型规则：

| 字段 | 策略 |
|---|---|
| 手机 | 工具返回里就打码，例如 138****1234 |
| 身份证 / 银行卡 | 决策场景根本不要查出这些列 |
| 供应商结算价 | 按角色：财务可见，仓经理不可见 |
| 员工姓名 | 可用工号+姓氏，看公司合规 |
| 精确地址 | 决策常用到城市/仓码即可 |

实现位置：**仓储层 DTO**，不是指望模型「请你脱敏」。模型看到了就会记在上下文里。

```java
public record InventoryView(
        String skuId,
        String warehouseId,
        int availableQty,
        Instant dataAsOf
) {}
// 不要包含 supplierBankAccount
```

## 3. 日志

允许：userId、conversationId、tool 名、参数摘要（sku、仓）、耗时、token、错误码。  
禁止：完整用户原句如果可能含隐私（至少截断并异步落审计表加密）、完整工具大 JSON、密钥、证件号。

参数摘要示例：`skuId=SKU-1001, warehouseId=WH-A`，不要把整行客户备注打出来。

---

## 4. 写操作红线（背下来）

第一版系统：

1. 不提供任何 UPDATE/INSERT/DELETE 工具。
2. 不提供调用 WMS「调整库存」API 的工具。
3. 不提供「代发邮件给供应商」的工具（那是写入外部世界）。
4. 「建议补货 30 件」只是文本建议，不写建议单也可以；若写建议单，要进独立草稿表，状态=`DRAFT`，由人确认。
5. 任何写操作必须：身份、二次确认、幂等键、可回滚或可对账。这是下一季度的事，不是本周的事。

有人会说「不写库哪叫 Agent」。请回答：

> Agent 的定义是能用工具达成目标。目标可以是「给出可信建议」。  
> 把生产库存交给会幻觉的循环，那不叫先进，叫赌博。

---

## 5. 只读账号还要再防一层

即使 JDBC 用户是 SELECT-only：

- 连接串不要指向主库；指向只读副本或决策库。
- 语句超时：`SET statement_timeout = '3s'`（Postgres）。
- 默认 `LIMIT`。
- 并发连接池小而明确，防止模型循环打爆。

工具把库打爆，不一定是写：一百个并发 `SELECT` 没限制一样能把从库拖死。

---

## 6. 【必做】

1. 确认仓库里没有真实 Key。
2. 工具 DTO 不含手机号字段。
3. 代码库搜索 `INSERT`/`UPDATE`/`deleteFrom` 出现在 tool 包应为空（审计表除外）。
4. 只读库用户在 Postgres 里 `GRANT SELECT`，不要 `GRANT ALL`。
