# 02 · 身份权限与数据范围

> 决策系统最危险的一句代码是：`select * from inventory`。  
> 更危险的是：工具里写了这句话，还让模型自己填 `warehouseId`。

---

## 1. 两层权限，缺一不可

### 1.1 应用层：你是谁

沿用你们公司现成的 SSO /网关。学习期最小演示：

```http
X-User-Id: u10086
X-User-Roles: manager
X-Warehouse-Scope: WH-A,WH-B
```

生产换成 JWT / 会话 Cookie。**不要让模型「猜」用户是谁。** 用户身份只来自网关。

### 1.2 数据层：你能看哪

管理层常有「我以为我能看全国」的错觉。产品上要明确：

- 总部角色：可看全部仓，但仍审计。
- 区域经理：只能看自己区域。
- 仓经理：只能看本仓。

Tool 内部用 Java 强制过滤，而不是把「请只查 A 仓」写在提示词里碰运气。

【红线】提示词不是权限系统。模型受诱导就会「帮忙查一下别的仓」。

## 2. 把范围做成上下文对象

```java
public record UserScope(
        String userId,
        Set<String> roles,
        Set<String> warehouseIds,
        Set<String> orgIds
) {
    public boolean canAccessWarehouse(String warehouseId) {
        if (roles.contains("HQ_VIEW")) {
            return true;
        }
        return warehouseIds.contains(warehouseId);
    }
}
```

用 `ThreadLocal` 或方法参数传入 Tool。推荐显式参数或 `ToolContext`，避免在异步线程里丢 ThreadLocal。

Spring AI 允许 `defaultToolContext` / 调用时 `.toolContext(...)`。把 `UserScope` 放进去，工具方法用 `ToolContext` 取出。若你觉得这套不好调试，就在 Service 层第一个参数显式传入 `UserScope`，Controller 负责组装——更笨，更清晰。

## 3. 工具里怎么拦

```java
@Tool(description = "查询指定仓库、指定 SKU 的可用库存。只能查当前用户有权限的仓库。禁止用于修改库存。")
public String queryInventory(
        @ToolParam(description = "SKU 编码") String skuId,
        @ToolParam(description = "仓库编码，例如 WH-A") String warehouseId,
        UserScope scope) {

    if (!scope.canAccessWarehouse(warehouseId)) {
        return "无权限查询仓库 " + warehouseId + "。请改问你有权限的仓库，或联系管理员开通。";
    }
    // 参数白名单：sku/warehouse 只允许字母数字和短横线
    return inventoryRepository.findAvailable(skuId, warehouseId);
}
```

要点：

1. **拒绝时返回给模型一句人话。** 模型会转述给用户。不要丢异常堆栈。
2. SQL 仍然带 `where warehouse_id = :id`，双保险。
3. 「查全国」做成单独工具 `queryInventorySummary`，内部自动 `IN (:allowedWarehouses)`，不要让模型传 `warehouseId=*`。

## 4. RAG 也要带范围

制度可能分「全国版 / 华东版」。检索时过滤：

```java
.advisors(a -> a.param(
        VectorStoreDocumentRetriever.FILTER_EXPRESSION,
        "org == '" + safeOrg + "' || org == 'GLOBAL'"))
```

`safeOrg` 来自 UserScope，不是用户输入原文。用户输入进过滤表达式 = 注入。

## 5. 演示用的最小安全过滤器

```java
@Component
public class UserScopeFilter implements Filter {

    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest request = (HttpServletRequest) req;
        String userId = request.getHeader("X-User-Id");
        if (userId == null || userId.isBlank()) {
            ((HttpServletResponse) res).sendError(401, "缺少用户身份");
            return;
        }
        UserScope scope = userDirectory.resolve(userId);
        request.setAttribute("userScope", scope);
        chain.doFilter(req, res);
    }
}
```

学习期用内存 `userDirectory`：两张用户卡（华东经理、华南经理）。攻防验收会用到。

---

## 6. 【必做】

1. 定义 `UserScope`，硬编码两个用户不同仓范围。
2. 所有查询工具第一行做 `canAccessWarehouse`。
3. 用用户 A 的头去问 B 的仓，必须失败。
4. 日志记录：userId、warehouseId、allowed、denied。
