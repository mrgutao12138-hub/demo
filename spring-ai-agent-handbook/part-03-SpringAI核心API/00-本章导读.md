## 2. 2.0 的第一原则（请背下来）

```
业务层 → ChatClient（一等公民）
底层   → ChatModel / DeepSeekChatModel（框架与特殊场景才碰）
```

| 层次 | 角色 | 你什么时候碰它 |
|---|---|---|
| `ChatClient` | 业务编排入口：prompt、advisor、tools、call/stream | **每天** |
| `ChatModel` | 向模型发 `Prompt`、拿 `ChatResponse` | 自定义模型封装、批处理、测试替身 |
| `DeepSeekChatModel` | DeepSeek 的具体实现 | 多模型手工装配、读推理内容时偶尔用 |

【易混】`ChatClient.create(chatModel)` 在 2.0 里能跑，但会**绕过自动配置的观测与 Customizer**。多模型场景请用 `ChatClientBuilderConfigurer`，后面第 07 节专讲。

## 4. 本章会反复出现的「决策助手」示例

后续各节的 Java 示例，都围绕同一个业务场景：**管理层辅助决策助手**。

它要能：

1. 用中文回答库存、订单、供应商、设备停机类问题；
2. 数字必须来自工具（本章先写死模拟，part-04 接真工具）；
3. 不确定时明确说「不知道」，禁止编造；
4. 复杂归因用 `deepseek-v4-pro` + thinking，日常问答用 `deepseek-v4-flash`。

第 02 节会给出**可直接复制**的中文 system prompt 长模板。你先别改花活，跑通再优化。

## 6. 本章禁止写法速查（看到就关掉教程）

| 禁止 | 原因 |
|---|---|
| `internalToolExecutionEnabled` | 1.x ChatModel 内部执行工具，2.0 已弃用 |
| `.toolNames(...)` | 2.0 用 `.tools(...)` 注册 heterogeneous 工具 |
| `PromptChatMemoryAdvisor` | 2.0 已移除，用 `MessageChatMemoryAdvisor` |
| `spring-ai-openai-spring-boot-starter` | 主线用 `spring-ai-starter-model-deepseek` |
| 记忆 advisor 构造时 `.conversationId(...)` | 2.0 必须在每次调用 `.advisors(a -> a.param(ChatMemory.CONVERSATION_ID, id))` |
| 多模型时裸用 `ChatClient.create(chatModel)` | 丢失观测与 `ChatClientBuilderCustomizer` |
