# 05 · 流式输出与结构化输出

> 管理层看对话，往往希望**字一个个冒出来**（体验），以及**表格字段固定**（可入库）。  
> 本章在 ChatClient 上扩展两条能力：`.stream().content()` 的 SSE，和 `.call().entity(record)` 的结构化 JSON。

---

## 1. 本章目标

1. 新增 SSE 接口，浏览器或 `curl -N` 能看到流式 chunk。
2. 用 **Java record** 做 DTO，Jackson 3 自动映射。
3. 使用 `validateSchema()` 做 schema 校验（失败可重试）。
4. 理解 **temperature** 对输出稳定性的影响。

---

## 2. 流式 API 回顾

```java
Flux<String> flux = chatClient
    .prompt()
    .user(message)
    .stream()    // 流式构建，仍未请求
    .content();  // 返回 Flux<String>，订阅后开始拉流
```

同步是 `.call().content()`，流式把 `call()` 换成 `stream()`。同样：**`content()` 才是触发点**。

---

## 3. 【必做】确认依赖

`pom.xml` 已有 `spring-boot-starter-web` 即可；WebFlux 的 `Flux` 由 Spring AI 传递引入。若 IDEA 报 `Flux` 找不到，执行 `mvn -q dependency:resolve` 并刷新 Maven。

无需额外加 `spring-boot-starter-webflux` 全栈（我们用 MVC + `Flux` 返回 SSE）。

## 4. 【必做】流式接口

在 `ChatController` 中**追加**方法（保留上一章的 `hello` 方法）。

完整类如下（可直接替换原文件）：

`src/main/java/com/example/hello/web/ChatController.java`：

```java
package com.example.hello.web;

import com.example.hello.web.dto.ChatRequest;
import com.example.hello.web.dto.ChatResponse;
import com.example.hello.web.dto.SentimentResult;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.http.MediaType;
import org.springframework.http.codec.ServerSentEvent;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;

@RestController
@RequestMapping("/api/chat")
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    @PostMapping("/hello")
    public ChatResponse hello(@RequestBody ChatRequest request) {
        String message = request.message();
        if (message == null || message.isBlank()) {
            return new ChatResponse("请输入非空消息。");
        }

        String content = chatClient
                .prompt()
                .user(message)
                .call()
                .content();

        return new ChatResponse(content);
    }

    /**
     * SSE 流式输出：每个 chunk 作为一条 Server-Sent Event。
     */
    @PostMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> stream(@RequestBody ChatRequest request) {
        String message = request.message();
        if (message == null || message.isBlank()) {
            return Flux.just(ServerSentEvent.<String>builder()
                    .event("error")
                    .data("请输入非空消息。")
                    .build());
        }

        return chatClient
                .prompt()
                .user(message)
                .stream()
                .content()
                .map(chunk -> ServerSentEvent.<String>builder()
                        .event("message")
                        .data(chunk)
                        .build());
    }

    /**
     * 结构化输出：映射为 record；validateSchema 在校验失败时触发重试。
     */
    @PostMapping("/sentiment")
    public SentimentResult sentiment(@RequestBody ChatRequest request) {
        String message = request.message();
        if (message == null || message.isBlank()) {
            return new SentimentResult("unknown", 0.0, "输入为空，无法分析。");
        }

        return chatClient
                .prompt()
                .user("""
                        分析下面这句话的情感，只输出 JSON，不要 markdown 代码块。
                        字段：label（positive/negative/neutral）、score（0到1的小数）、summary（一句中文）。
                        待分析：%s
                        """.formatted(message))
                .call()
                .entity(SentimentResult.class, spec -> spec.validateSchema());
    }
}
```

package com.example.hello.web.dto;

/**
 * Jackson 3（Boot 4）可直接反序列化 record。
 * 字段名需与模型返回的 JSON 属性一致（或用 @JsonProperty）。
 */
public record SentimentResult(
        String label,
        double score,
        String summary

}

## 6. 【必做】温度配置说明

`application.yml` 保持：

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      chat:
        model: deepseek-v4-flash
        temperature: 0.3
```

| temperature | 效果 | 适用 |
|---|---|---|
| 0.0 ~ 0.3 | 更确定、格式更稳 | 结构化 JSON、工具参数 |
| 0.5 ~ 0.8 | 更有变化 | 普通对话、文案 |
| 接近 1.0 | 发散大 | 学习期慎用，JSON 易坏 |

结构化接口若经常字段缺失，先把全局 `temperature` 降到 **0.2**，并配合 `validateSchema()`。

【选做】单次调用覆盖温度（了解即可，本章不强制）：

```java
import org.springframework.ai.deepseek.DeepSeekChatOptions;

chatClient.prompt()
    .user("...")
    .options(DeepSeekChatOptions.builder().temperature(0.1).build())
    .call()
    .entity(SentimentResult.class, spec -> spec.validateSchema());
```

## 7. 【必做】启动与 curl 验收

### 7.1 流式 SSE

```bash
curl -N -X POST http://localhost:8080/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"用三句话介绍流式输出"}'
```

`-N` 禁用缓冲，你能看到多条 `event:message` 和 `data:` 行逐步输出。

期望形态（片段）：

```
event:message
data:流式

event:message
data:输出

...
```

### 7.2 结构化 JSON

```bash
curl -s -X POST http://localhost:8080/api/chat/sentiment \
  -H "Content-Type: application/json" \
  -d '{"message":"今天项目终于跑通了，很开心！"}'
```

期望类似：

```json
{
  "label": "positive",
  "score": 0.92,
  "summary": "表达项目成功后的喜悦情绪。"
}
```

再测中性句：

```bash
curl -s -X POST http://localhost:8080/api/chat/sentiment \
  -H "Content-Type: application/json" \
  -d '{"message":"会议室在三楼。"}'
```

`label` 应接近 `neutral`。

### 7.3 validateSchema 何时帮你

若模型返回缺字段或 `label` 乱写，Spring AI 2.0 在 `validateSchema()` 开启时会尝试**按 schema 重试**。日志里可能看到多次模型往返——这是预期行为，生产上要配合超时与次数上限（后面 Advisor 章节再讲）。

## 8. 【建议】浏览器最小验证页（选做）

`src/main/resources/static/stream-demo.html`：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8"/>
  <title>流式演示</title>
</head>
<body>
  <textarea id="input" rows="3" cols="60">讲一个关于程序员的冷笑话</textarea>
  <button id="go">发送</button>
  <pre id="out"></pre>
  <script>
    document.getElementById('go').onclick = async () => {
      const message = document.getElementById('input').value;
      const out = document.getElementById('out');
      out.textContent = '';
      const res = await fetch('/api/chat/stream', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ message })
      });
      const reader = res.body.getReader();
      const decoder = new TextDecoder();
      while (true) {
        const { value, done } = await reader.read();
        if (done) break;
        out.textContent += decoder.decode(value);
      }
    };
  </script>
</body>
</html>
```

启动后访问 `http://localhost:8080/stream-demo.html` 点发送。页面较糙，仅用于验证 SSE 通路。

## 9. entity() 与 call() 再强调

```java
// 同步文本
.call().content();

// 流式文本
.stream().content();

// 结构化（无校验）
.call().entity(SentimentResult.class);

// 结构化（带 schema 校验）
.call().entity(SentimentResult.class, spec -> spec.validateSchema());
```

四条路径共同点：**最后一环**（`content()` / `entity()`）才触发模型。写测试时 mock 也要挂在消费端。

## 10. 常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| curl 流式一次全吐出来 | 未加 `-N` 或中间有代理缓冲 | 加 `-N`；换终端试 |
| `entity()` 反序列化失败 | 模型包了 markdown 代码块 | 提示词强调「只输出 JSON」；降 temperature |
| `Flux` 无法解析 | Maven 未刷新 | Reload + `mvn compile` |
| SSE 中文乱码 | 少见；检查 UTF-8 | `application.yml` 默认 UTF-8 即可 |
| 结构化字段名对不上 | JSON 属性与 record 不一致 | 改提示词或加 `@JsonProperty` |
