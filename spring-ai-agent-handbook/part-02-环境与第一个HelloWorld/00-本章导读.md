## 1. 本章要解决什么问题

学完 Part 00（心智模型）和 Part 01（总路线图），你心里应该已经有了一张草图：管理层问一句话 → Spring MVC → ChatClient → DeepSeek → 返回文字。

**本章就是把那张草图变成一台真的能转的机器。**

具体你会完成：

1. 把 JDK、Maven、IDEA 配到能编译 **Java 21 + Spring Boot 4.1** 的状态。
2. 在 DeepSeek 开放平台拿到 API Key，理解计费与限额，**不把密钥写进 Git**。
3. 从零创建一个 Spring Boot 4 项目：`pom.xml`、主类、`application.yml`、`.gitignore` 全部自己建。
4. 用 **Spring AI 2.0** 的 `ChatClient.Builder` 完成第一次对话（Hello World）。
5. 再往前一步：流式输出（SSE）和结构化输出（`record` + `validateSchema()`）。

做完本章，你应该能对着同事说：

> 「我本地有一个 Spring Boot 服务，调 DeepSeek 的 flash 模型，能同步对话、能流式吐字、能把 JSON 映射成 Java record。」

这就是 Part 03（Advisor 与工具）之前的**硬门槛**。

## 2. 技术冻结（本章全程遵守，禁止写成 1.x）

请把下面这张表抄到你的笔记本第一页。网上 90% 的中文 Spring AI 教程仍是 1.x，看到旧 starter 名、旧配置前缀，直接关掉。

| 项目 | 本章冻结值 |
|---|---|
| Java | **21 推荐**（最低 17） |
| Spring Boot parent | **4.1.x** |
| Spring AI BOM | **2.0.0**，`type` 为 `pom`，`scope` 为 `import` |
| Web 依赖 | `spring-boot-starter-web` |
| 模型依赖 | `spring-ai-starter-model-deepseek`（**不是** `spring-ai-openai-spring-boot-starter`） |
| API Key 配置前缀 | `spring.ai.deepseek.api-key`（**不是** `spring.ai.openai.api-key`） |
| 模型配置前缀 | `spring.ai.deepseek.chat.model` |
| 默认模型 | `deepseek-v4-flash`（Hello World 用 flash） |
| base-url | 默认已是 `https://api.deepseek.com`，一般不用改 |
| 日常注入 | `ChatClient.Builder`（自动配置，**prototype** 作用域） |
| 暂不注入 | `ChatModel`（底层接口，后面讲 Advisor 时再碰） |
| JSON 库 | **Jackson 3**（Boot 4 自带），DTO 用 **record** 即可 |

### 2.1 ChatClient 调用链（2.0 一等公民）

```java
// 同步拿纯文本
String text = chatClient.prompt().user(msg).call().content();

// 流式：得到 Flux<String>
Flux<String> stream = chatClient.prompt().user(msg).stream().content();

// 结构化：映射成 record
MyDto dto = chatClient.prompt().user(msg).call().entity(MyDto.class);

// 带 schema 校验（失败可重试）
MyDto dto = chatClient.prompt().user(msg)
    .call().entity(MyDto.class, spec -> spec.validateSchema());
```

**【易混】** `call()` 本身**不触发**模型请求；真正发 HTTP 的是 `.content()`、`.entity()` 这些「消费端」方法。写单元测试或打日志时要注意这一点。

### 2.2 密钥写法

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
```

环境变量名固定用 `DEEPSEEK_API_KEY`。**禁止**把真实 Key 写进 `application.yml` 再提交 Git。

## 5. 常见启动失败（先有个心理准备）

同学们第一次配 Spring AI 2.0，翻车率很高。下面四条占了 80% 的工单，**现在就看一眼**，后面各章还会再提醒：

| 现象 | 最常见原因 | 怎么修 |
|---|---|---|
| 找不到 `ChatClient` 或 DeepSeek 相关类 | `spring-ai-bom` **没 import**，或版本不是 2.0.0 | 检查 `dependencyManagement` 里 BOM 的 `type=pom` + `scope=import` |
| 启动报 Unknown starter / 依赖解析失败 | 用了 1.x 的 `spring-ai-openai-spring-boot-starter` | 改成 `spring-ai-starter-model-deepseek` |
| 401 / Invalid API Key | Key 写成了 `spring.ai.openai.api-key` | 前缀必须是 `spring.ai.deepseek` |
| 启动就报 `Could not resolve placeholder 'DEEPSEEK_API_KEY'` | 环境变量没设 | 见 `01-环境准备.md` 三平台命令 |

还有一类：**项目能启动，但一调接口就 500**。多半是 Key 为空、模型名拼错、或网络出不了 `api.deepseek.com`。`04` 会教你怎么从日志里认。
