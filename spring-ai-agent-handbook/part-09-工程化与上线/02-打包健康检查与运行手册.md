# 02 · 打包、健康检查与运行手册

> 代码在 IDE 里跑，不算上线。  
> 上线 = 别人能在你不在场时，按文档把服务拉起来、验活、重启。  
> 本章给 Decision Copilot 灰度实例一份「值班同学也能看懂」的运行手册骨架。

---

## 1. 灰度期交付物清单

发给运维或你自己部署前，准备这些：

| 交付物 | 内容 |
|---|---|
| 可执行 jar | `decision-copilot-*.jar` |
| 环境变量清单 | 见本文 §4 |
| 运行手册 | 本文 §6 模板，填上你们真实主机名 |
| 回滚包 | 上一版 jar + 上一版环境变量快照 |
| 联系人 | 开发主责、业务负责人（管 5 位领导的那位） |

## 2. 打包

### 2.1 Maven 标准打包

```bash
./mvnw -q clean package -DskipTests
# 产物：target/decision-copilot-0.1.0-SNAPSHOT.jar
```

灰度建议：

- **固定版本号**，不要用 `SNAPSHOT` 上 pilot（例如 `0.1.0-pilot1`）。
- 打 tag 或写变更说明：模型名、prompt 版本、知识库入库日期。

### 2.2 可执行 jar 启动

```bash
java -jar decision-copilot-0.1.0-pilot1.jar \
  --spring.profiles.active=pilot
```

生产级建议加上 JVM 参数（按机器内存调整）：

```bash
java -Xms512m -Xmx1024m \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/var/log/decision-copilot/ \
  -jar decision-copilot-0.1.0-pilot1.jar
```

### 2.3 环境变量加载

推荐 systemd `EnvironmentFile` 或容器 `env_file`：

```ini
# /etc/decision-copilot/pilot.env（权限 600）
SPRING_PROFILES_ACTIVE=pilot
DEEPSEEK_API_KEY=sk-从密钥管理服务复制
PILOT_DB_URL=jdbc:postgresql://db-internal:5432/decision_wide
PILOT_DB_READONLY_USER=dcopilot_ro
PILOT_DB_PASSWORD=***
PILOT_USER_IDS=u_a,u_b,u_c,u_d,u_e
```

**【红线】** `pilot.env` 不得放在 jar 同级目录并打进发布 zip 给外人。

## 3. 健康检查（Actuator）

### 3.1 依赖

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

### 3.2 pilot 暴露策略

```yaml
management:
  endpoints:
    web:
      base-path: /actuator
      exposure:
        include: health,info,metrics
  endpoint:
    health:
      probes:
        enabled: true
      show-details: when_authorized
```

- **负载均衡 / K8s 探针**：只打 `GET /actuator/health/liveness` 与 `readiness`。
- **不要**在灰度期暴露 `env`、`beans`、`heapdump`。

### 3.3 自定义 Health：依赖是否就绪

Decision Copilot 建议加两类自定义指示器：

**（1）只读数据源**

```java
@Component
public class ReadOnlyDataSourceHealthIndicator implements HealthIndicator {
    private final DataSource dataSource;

    @Override
    public Health health() {
        try (Connection c = dataSource.getConnection();
             var st = c.createStatement()) {
            st.execute("SELECT 1");
            return Health.up().withDetail("db", "reachable").build();
        } catch (Exception e) {
            return Health.down(e).withDetail("db", "unreachable").build();
        }
    }
}
```

**（2）向量库（若 pilot 用 pgvector）**

```java
// 简单版：查 vector 表是否存在或可 COUNT
// 失败 → DOWN，避免「能对话但检索全空」误导领导
```

**（3）模型 API（慎用）**

- 每次 health 都打 DeepSeek 会费钱、易被限流。
- 建议：**不在 liveness 里打模型**；单独定时任务每 5 分钟探测，结果写入缓存指标。
- readiness 可配置 `management.health.deepseek.enabled=false` 默认关。

### 3.4 探活命令（写进手册）

```bash
# 本机或跳板机
curl -sf http://localhost:8080/actuator/health/readiness | jq .

# 期望：{"status":"UP", ...}
# 若 DOWN：看 detail 里 db / vectorStore 哪项红了
```

## 4. 环境变量清单（pilot 模板）

| 变量名 | 必填 | 说明 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 是 | 固定 `pilot` |
| `DEEPSEEK_API_KEY` | 是 | DeepSeek API 密钥 |
| `PILOT_DB_URL` | 是 | 只读宽表 JDBC |
| `PILOT_DB_READONLY_USER` | 是 | 仅 SELECT 权限 |
| `PILOT_DB_PASSWORD` | 是 | 库密码 |
| `PILOT_USER_IDS` | 是 | 5 人 SSO id，逗号分隔 |
| `SERVER_PORT` | 否 | 默认 8080 |
| `JAVA_OPTS` | 否 | 堆内存等 |

## 5. 日志与审计落盘

灰度期日志至少包含：

| 字段 | 用途 |
|---|---|
| `traceId` | 一次问答全链路 |
| `userId` | 谁问的 |
| `questionSummary` | 问题摘要（可不记全文，见脱敏策略） |
| `toolsInvoked` | 工具名列表 |
| `ragDocIds` | 命中的文档片段 id |
| `model` | flash / pro |
| `promptTokens` / `completionTokens` | 成本 |
| `latencyMs` | 慢查询排查 |

日志路径建议：`/var/log/decision-copilot/app.log`，按天滚动，保留 ≥ 90 天（与审计保留一致）。

## 6. 运行手册模板（复制到 Wiki 后填空）

```markdown
# Decision Copilot Pilot 运行手册

## 1. 服务说明
- 用途：5 位管理层灰度问答（只读决策）
- 实例：pilot-01
- 代码版本：0.1.0-pilot1
- 配置 Profile：pilot

## 2. 启动
sudo systemctl start decision-copilot
# 或
java -jar /opt/decision-copilot/decision-copilot-0.1.0-pilot1.jar

## 3. 停止
sudo systemctl stop decision-copilot
# 优雅停机：默认 Spring Boot 会处理完进行中的请求（超时 30s）

## 4. 验活
curl -sf http://pilot-host:8080/actuator/health/readiness

## 5. 看日志
tail -f /var/log/decision-copilot/app.log
# 搜 traceId：grep 'traceId=xxx' app.log

## 6. 常见故障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| readiness DOWN, db red | 库连不上、账号过期 | 查 JDBC、VPN、防火墙 |
| 全员 403 | PILOT_USER_IDS 配错 | 对照 SSO id 修正 env，重启 |
| 全员「服务繁忙」 | 见 03 章熔断 | 查 DeepSeek 控制台配额 |
| 回答极慢 | 工具/SQL 慢 | 查宽表索引、调工具超时 |

## 7. 回滚
1. systemctl stop
2. 换回上一版 jar：decision-copilot-0.1.0-pilot0.jar
3. 恢复上一版 env 快照
4. systemctl start
5. curl 验活 + 开发负责人试一问

## 8. 升级（发新版）
1. 备份 env 与 jar
2. 停服务 → 换 jar → 启服务
3. 开发做「三问验收」（库存/采购/设备各一问）
4. 通知业务负责人「已升级，请领导试用」

## 9. 联系人
- 开发：________  手机：________
- 业务：________
- 非工作时间是否响应：否（灰度期可写「仅工作日 9-18」）
```

## 7. 灰度发布顺序（建议）

```
1. dev 自测三问通过
2. 部署 pilot 空载验活（health UP）
3. 开发 + 业务负责人各试 5 问
4. 开放第 1 位领导（通常是业务负责人自己）
5. 观察 2 天无事故 → 其余 4 人分批邀请（每天 1～2 人，便于定位问题）
```

不要周五下午一次性把链接发给 5 位领导。

---

## 8. 【必做】实验

1. 加入 `spring-boot-starter-actuator`，配好只暴露 health/info/metrics。
2. 实现数据源 HealthIndicator，故意改错密码，看 readiness 是否 DOWN。
3. 用 `java -jar` 在本机 `pilot` profile 启动，完成手册 §4 验活命令。
4. 把 §6 模板复制到你们 Wiki，填真实主机名和联系人。
