# 04 · 成本测算与配额

> 领导问「一个月多少钱」，你说「看情况」，信任就掉一半。  
> 领导问「能不能设上限」，你说「应该可以」，信任就掉另一半。  
> 本章教你：**用控制台真实单价 + 可填表 + 公式**，给出区间，而不是编造一个精确官方价。

---

## 1. 成本从哪来（Decision Copilot 灰度）

| 费用项 | 灰度 5 人是否发生 | 说明 |
|---|---|---|
| DeepSeek 对话 API（输入 token） | ✅ 主要 | 系统提示 + RAG 上下文 + 用户问题 + 工具结果回填 |
| DeepSeek 对话 API（输出 token） | ✅ 主要 | 模型最终回答；pro + thinking 通常更高 |
| Embedding（RAG 入库/查询） | ✅ 少量 | DeepSeek 对话 API **不提供** embedding；本地 Transformers 或别的 embedding 服务，灰度期多为 **一次性入库 + 偶尔增量** |
| 向量库 / 只读库 | ✅ 基础设施 | 通常已有 Postgres，增量成本记运维账 |
| 服务器 | ✅ | 1 台小规格 JVM 即可扛 5 人 |

**本章重点：** 对话 token 账单 + 如何控配额。

---

## 2. 单价从哪里查（不要猜）

1. 登录 **DeepSeek 开放平台控制台**。
2. 打开 **定价 / 计费说明** 页面（名称以控制台为准）。
3. 找到你 pilot 实际使用的模型，例如：
   - `deepseek-v4-flash`（或控制台显示的闪速档名称）
   - `deepseek-v4-pro`（或控制台显示的专业档名称）
4. 记录两项（**单位以控制台为准**，常见为「元 / 百万 token」或「元 / 千 token」）：
   - **输入单价** `P_in`
   - **输出单价** `P_out`

**【红线】** 讲义**不**写死「官方精确单价」。模型调价时，你只改表里的 `P_in` / `P_out`，公式不变。

若启用 **thinking / 推理档**，控制台可能对「推理 token」另有计价，请单独记为 `P_think` 并填入测算表备注。

---

## 3. 核心计算公式

### 3.1 单次问答成本

```
单次成本 ≈ (T_in / U) × P_in + (T_out / U) × P_out + (T_think / U) × P_think
```

| 符号 | 含义 |
|---|---|
| `T_in` | 本次请求输入 token 数（含 system、RAG、工具回填、用户问题） |
| `T_out` | 本次输出 token 数 |
| `T_think` | 推理/思考 token（若未单独计价则并入 `T_out` 或置 0） |
| `U` | 控制台单价的计量单位（例如 1_000_000 表示「每百万 token」） |
| `P_in` / `P_out` / `P_think` | 控制台当前单价 |

**示例（数字仅演示公式，单价请换你自己查的）：**

- 假设控制台写明：输入 **X 元 / 百万 token**，输出 **Y 元 / 百万 token**。
- 某次：`T_in = 8000`，`T_out = 1200`。
- 则单次 ≈ `8000/1_000_000 × X + 1200/1_000_000 × Y`。

### 3.2 单人单日成本

```
单人单日成本 ≈ 人均每天问次数 × 单次平均成本
```

### 3.3 灰度月成本（5 人）

```
月成本 ≈ 5 × 人均每天问次数 × 每月工作天数 × 单次平均成本
```

加 **安全系数**（建议 × 1.3～1.5），覆盖：

- 领导偶尔长问、多轮工具
- RAG 上下文变长
- 评测回归消耗

```
月成本（保守）≈ 上式 × 1.5
```

### 3.4 从日志反推单次 token（推荐）

灰度第一周用真实日志算平均值，比拍脑袋准：

```
单次平均 T_in  = 一周总 promptTokens / 一周总问答次数
单次平均 T_out = 一周总 completionTokens / 一周总问答次数
```

在 Spring AI 返回的 `Usage` 或你们审计表里聚合即可。

## 4. 可填测算表（请复制到 Excel / 飞书表格）

### 4.1 假设参数（你填）

| 字段 | 你填的值 | 老师建议起点（5 人灰度） |
|---|---|---|
| 灰度人数 `N` | | 5 |
| 人均每天问次数 `Q_day` | | 10～20（试点可先用 15） |
| 每月工作天数 `D_month` | | 22 |
| 主用模型 | | pilot 建议 pro；简单追问可用 flash |
| 单次平均输入 token `T_in` | | 先估 6000～12000；一周后改日志实测 |
| 单次平均输出 token `T_out` | | 先估 800～2000 |
| 单次平均推理 token `T_think` | | 开 thinking 则填；否则 0 |
| 安全系数 | | 1.5 |

### 4.2 单价（到控制台抄，不要编造）

| 模型 | 输入单价 `P_in` | 输出单价 `P_out` | 推理单价 `P_think` | 计量单位 `U` | 查阅日期 |
|---|---|---|---|---|---|
| deepseek-v4-flash | | | | | |
| deepseek-v4-pro | | | | | |

> 计量单位 `U` 填数字：若价为「元/百万 token」，则 `U = 1000000`。

### 4.3 自动公式列（Excel 示例）

假设表结构：

- `B2` = `Q_day`
- `B3` = `D_month`
- `B4` = `N`（=5）
- `B5` = `T_in`
- `B6` = `T_out`
- `B7` = `T_think`
- `B8` = `P_in`
- `B9` = `P_out`
- `B10` = `P_think`
- `B11` = `U`
- `B12` = 安全系数（1.5）

**单次成本（元）：**

```
=(B5/B11)*B8 + (B6/B11)*B9 + (B7/B11)*B10
```

**月成本（元）：**

```
=B4 * B2 * B3 * 单次成本单元格 * B12
```

### 4.4 填表示例（单价留白）

| 项 | 值 |
|---|---|
| N | 5 |
| Q_day | 15 |
| D_month | 22 |
| T_in（估） | 9000 |
| T_out（估） | 1500 |
| P_in | **到控制台填写** |
| P_out | **到控制台填写** |
| U | **按控制台单位填写** |
| 月成本（公式算完） | **= 你的数** |
| 月成本×1.5（报领导） | **= 你的数** |

给领导汇报时说：

> 「按当前控制台单价、每人每天约 15 问估算，5 人灰度一个月大约 **【区间下限～上限】元**，上限按 1.5 倍安全系数。试运行一周后我们用真实 token 日志修正。」

## 5. 配额与控制手段

### 5.1 平台侧（DeepSeek 控制台）

- 账户余额 / 充值提醒
- 若控制台提供 **用量告警、月度预算**，务必打开
- 保存 **用量统计** 页面截图，与内部审计对账

### 5.2 应用侧（你必须做）

| 手段 | 配置建议 |
|---|---|
| 每人每日问答上限 | pilot：`30` 次/人/天（见 01 章） |
| 单次 `T_in` 上限 | RAG `topK`、工具结果截断、历史记忆条数限制 |
| 模型分档 | 默认 pro；简单续问可路由 flash（进阶） |
| 管理端开关 | `decision-copilot.pilot.enabled=false` 一键停服 |

### 5.3 审计对账

每周一次：

```
内部审计表 SUM(promptTokens + completionTokens)
  ↔  DeepSeek 控制台用量曲线
```

偏差 > 15% 要查：是否有密钥泄露、是否有未鉴权接口。

---

## 6. 降本不等于降质（灰度期别乱切）

| 做法 | 是否推荐 |
|---|---|
| 口径/制度类问题用 pro + RAG | ✅ |
| 纯寒暄、格式整理用 flash | ✅ 可后续做路由 |
| 关掉工具结果里的明细，只留摘要 | ✅ 减 `T_in` |
| 为省钱关审计 | ❌ |
| 为省钱 `allowEmptyContext(true)` | ❌ 幻觉风险 |

---

## 7. 【必做】作业

1. 打开 DeepSeek 控制台，把 flash / pro 的 `P_in`、`P_out`、`U` 抄进 §4.2 表。
2. 用 §4.3 公式算「5 人 × 15 问/天 × 22 天」月成本，再 × 1.5。
3. 在 dev 环境问 3 道综合题（工具+RAG），从日志抄 3 次 `T_in`/`T_out` 求平均，对比估算误差。
4. 在 pilot 配置里写上 `daily-question-limit-per-user: 30`。

## 8. 小结

| 领导问 | 你怎么答 |
|---|---|
| 多少钱 | 公式 + 控制台单价 + 区间 + 一周后修正 |
| 会不会爆 | 每人日限 + 账户余额告警 + 密钥不泄露 |
| 值不值 | 灰度看「节省了多少跨部门核对时间」，04 只负责算钱 |
