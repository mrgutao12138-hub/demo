## 1. 本章要解决什么问题

前面各章，你主要在**开发环境**里验证能力。管理层灰度试用时，他们会问另一类问题：

- 「密钥会不会进 Git？」
- 「服务挂了，业务系统会不会跟着挂？」
- 「一个月大概花多少钱？能不能设上限？」
- 「答错了、泄密了、把库查爆了，你们有没有预案？」
- 「试用两周，反馈怎么收？怎么知道该不该扩大范围？」

这些不是「再调一个 prompt」能解决的。本章教你用 **Spring Boot 4 + Spring AI 2.0** 的标准工程手段，把 Decision Copilot 从「演示项目」变成「可灰度、可算账、可追责」的系统。

**本章灰度目标（请写进你的项目 README）：**

| 项 | 约定 |
|---|---|
| 试用人数 | **5 位管理层**（固定名单，不开放注册） |
| 权限 | 只读决策；无写操作、无自动下单 |
| 环境 | 独立 `staging` 或 `pilot` 实例，与生产 ERP 只读宽表对接 |
| 周期 | 建议 **2～4 周**；每周复盘一次 |
| 成功标准 | 见 `05-灰度试用与反馈闭环.md` |

## 3. 技术主线（请背下来）

灰度期的 Decision Copilot 架构，在 part-03 选型图基础上加三条横切：

```
┌─────────────────────────────────────────────────────────┐
│  5 位管理层  →  Web / 企业 IM（建议先 Web）               │
└───────────────────────────┬─────────────────────────────┘
                            │ HTTPS + SSO
┌───────────────────────────▼─────────────────────────────┐
│  pilot 实例  Spring Boot 4                               │
│  - 环境：spring.profiles.active=pilot                    │
│  - 密钥：环境变量 / 密钥管理服务，不进 Git                  │
│  - 限流：按 userId 每日问答次数上限                        │
└───────────────────────────┬─────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   ChatClient          只读宽表            VectorStore
   + Advisor 链        + 工具超时           制度/SOP
        │                   │                   │
        └───────────────────┴───────────────────┘
                            │
        横切：/actuator/health、审计日志、token 计量、熔断降级
```

**灰度期三条铁律：**

1. **密钥零入库。** `git grep -i api-key` 只能出现 `${DEEPSEEK_API_KEY}` 占位符。
2. **模型挂了，业务库不能挂。** 工具要有超时、连接池上限、熔断；模型失败要有降级文案。
3. **每一问可追溯。** 谁、何时、调了哪些工具、检索了哪些文档片段、大概多少 token。

## 5. 三个【红线】先念一遍

1. **灰度不是公测。** 5 人名单由业务负责人签字；未在名单里的账号一律 403。
2. **Pilot 环境禁止用生产写库账号。** 只读账号、只读视图、连接数上限写进运行手册。
3. **没有运行手册和事故预案，不准发邀请链接。** 不是吓唬你，是保护你这 5 位领导的时间。

## 6. 本章 Maven / 依赖提醒

工程化不新增「AI 魔法依赖」，主要是 Boot 自带能力：

```xml
<!-- 健康检查与指标（生产建议全开，pilot 至少开 health） -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

Spring AI 部分仍用你在 part-03 定下的 BOM **2.0.0**，不要为上线单独升快照版。
