# 08 · 如何避免学完就落后

> 同学们最怕两件事：  
> 一是学完不会用；二是刚学会就过时。  
> 第二件事的一半是焦虑幻觉 —— 行业天天发新模型名，但**企业 Agent 的骨架三年没怎么变**。  
> 本章教你盯什么、忽略什么，让你做完 Decision Copilot 灰度后，仍能持续迭代而不瞎忙。

---

## 1. 先建立「不变层」与「易变层」

```
易变层（少花时间追）
  - 某个模型叫 v3 还是 v4
  - 某个厂商又发了一篇博客
  - 某个网红框架 GitHub star 涨了

不变层（值得持续投资）
  - 工具循环 + 权限 + 审计
  - 检索增强与口径治理
  - 评测集与回归门禁
  - 可观测性（日志、指标、trace）
  - 互操作协议（MCP）
  - Advisor 组合式扩展
```

你学完这本讲义，**不变层已经覆盖 80%**。落后的典型不是「没用过最新模型」，而是：

> 无工具、无来源、无评测、无审计的聊天框。

---

## 2. 四个框架能力雷达（每月自评 1～5 分）

每月花 30 分钟，给四维打分。任一维 < 3，优先补讲义对应章，不要刷模型新闻。

### 2.1 Advisor（编排与护栏）

**是什么：** Spring AI 2.0 把记忆、RAG、工具循环、结构化校验都做成可排序、可重入的 Advisor 链。

**你要会：**

- 画出你项目里 Advisor 顺序图
- 说清 `ToolCallingAdvisor` 与 `MessageChatMemoryAdvisor` 谁先谁后
- 能自定义一个「审计 Advisor」或「限流 Advisor」

**落后信号：** 还在搜 1.x 的 `toolNames`、`internalToolExecutionEnabled`。

**复习：** part-03、part-04、part-05 的 `04-RetrievalAugmentationAdvisor实战.md`。

---

### 2.2 MCP（工具互操作）

**是什么：** 把外部进程/团队的能力，以标准协议插进 `ChatClient.tools()`，而不是 endless 复制 `@Tool`。

**你要会：**

- 区分 MCP Client / Server
- 知道「MCP 不会自动进 ChatClient，要 `SyncMcpToolCallbackProvider`」
- pilot 期只接只读 MCP，并有降级预案

**落后信号：** 每个新系统都手写一套 HTTP 工具，无统一鉴权与版本管理。

**复习：** part-04 `07-MCP是什么以及本周了解到哪.md`；本章 07 路线图。

---

### 2.3 评测（质量门禁）

**是什么：** 固定问答集 + 断言 + CI，改 prompt 或换模型后先跑评测再发 pilot。

**你要会：**

- 维护 ≥ 30 条核心用例（数字、口径、拒答、越权）
- 区分「冒烟 10 条」与「全量 100 条」
- 把领导反馈过的 bad case 转成用例

**落后信号：** 每次发版靠「我手动问了三个问题好像没问题」。

**复习：** part-02 能力地图 L5；本章 07 评测自动化。

---

### 2.4 观测（可追责）

**是什么：** traceId、token 用量、工具耗时、降级次数、熔断状态 —— 能回答「昨晚领导那问为什么慢」。

**你要会：**

- 日志字段齐全（见 02 章）
- Actuator `metrics` 或接入公司现有监控
- 用量与 DeepSeek 控制台对账（见 04 章）

**落后信号：** 出问题时只有「用户说不对」，手里没有 traceId。

**复习：** part-09 的 02、04、06 章。

---

## 3. 每月 2 小时「保鲜」例行公事

| 步骤 | 时间 | 做什么 |
|---|---|---|
| 1 | 20 min | 看 Spring AI **Release Notes**（官方发布说明，非八卦博客） |
| 2 | 20 min | 看 DeepSeek 控制台：定价/配额/模型列表有无变更 |
| 3 | 30 min | 跑一遍评测冒烟 10 条 |
| 4 | 30 min | 读 1 条你们自己的 pilot 坏 case，加进评测集 |
| 5 | 20 min | 更新四维雷达分，写一条下月改进 |

**不要**每天刷模型排行榜；**要**每月固定保鲜 Ritual。

---

## 4. 什么该追、什么该忽略

| 建议追 | 建议忽略（灰度第一年） |
|---|---|
| Spring AI 2.x 小版本修复与安全公告 | 每个新开源 Agent 框架「又火了」 |
| Boot / Framework 与你公司基线对齐 | 预训练、微调论文（除非单独立项） |
| MCP 规范小版本与官方 Java SDK | 「多 Agent 自治公司」营销稿 |
| 你们行业的口径与指标字典变更 | 通用大模型在八卦题上的排名 |
| 评测集与事故复盘 | 把聊天记录当知识库 |

---

## 5. 模型升级时的正确姿势（不换栈）

当 DeepSeek 或公司政策要求换模型名时：

```
1. 在 dev 换配置 model 名（或换 starter 若换厂商）
2. 跑全量评测 —— 看掉点在哪类问题
3. 只针对掉点调 prompt / 工具描述 / RAG 阈值
4. pilot 金丝雀：你先问一天，再开放领导
5. 记录版本：model 名 + 日期写入发布说明
```

**禁止：** 周五改 model 名，周一让 5 位领导「感受一下变聪明了」。

模型是**可替换零件**；Advisor + 工具 + 评测是**底盘**。

## 6. 学习资源怎么选（无英文外链版）

| 类型 | 去哪看 |
|---|---|
| Spring AI 2.0 | 官方参考文档与 Release Notes（搜索「Spring AI 参考文档」） |
| Spring Boot 4 | 官方 Boot 文档对应你使用的 4.1.x 版本 |
| DeepSeek | 开放平台控制台内的文档与定价页 |
| 本讲义 | `part-00`～`part-09` 按路线图复习；**以你跑通的项目为准** |
| 社区 | 内部 Wiki、同事 code review、灰度周报 —— 比泛中文教程贴近你们口径 |

【易混】搜索教程时看到 1.x、`QuestionAnswerAdvisor` 当唯一 RAG、`toolNames()` —— 关掉，回到讲义 2.0 主路径。

---

## 7. 从 L5 毕业以后往哪走

讲义主线毕业 ≈ **L4 稳 + L5 作品**。之后不是换一本更厚的书，而是：

```
深：某一域的数据治理与指标字典（比模型更重要）
宽：MCP 接入更多只读系统
高：评测与 CI 门禁、金丝雀发布
厚：事故文化与复盘（06 章）
```

若你带团队：

- 把四维雷达做成团队月会一页纸
- 新人入职先跑 part-04 + part-09，再碰 prompt 花活

---

## 8. 给还在焦虑的你三句话

1. **管理层要的是可信决策，不是最新模型名。** 把来源、审计、拒答做好，你已经领先多数「API 演示」。
2. **落后是「无评测发版」，不是「没用过某模型」。**
3. **这本讲义结束，工程化才开始。** 灰度、周报、季度路线图（05、07 章）才是你的长期教材。

---

## 9. 【必做】作业

1. 画一张你当前项目的 Advisor 链顺序图，标 order。
2. 填四维雷达，哪维最低就复习对应章。
3. 日历里设「每月第一个周五」2 小时保鲜 Ritual。
4. 把领导反馈过的 3 个 bad case 写进评测 YAML。

---

## 10. 本章结语

工程化与上线这一章，是讲义从「学会」到「敢给领导用」的桥。  
桥走过去之后，靠的不是每天换模型名，而是 **Advisor、MCP、评测、观测** 四根柱子。  
柱子立在，模型换代你只是换一块砖。
