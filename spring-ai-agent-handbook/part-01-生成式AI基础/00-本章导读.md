## 2. 本周要解决的五个根本问题

管理层问一句：「华东仓 A 类物料还能撑几天？要不要补货？」  
你的系统要能回答，背后至少要分清五件事：

| 问题 | 本周对应章节 | 一句话答案 |
|------|-------------|-----------|
| 模型怎么「说话」？概率、温度、长度限制是什么？ | 01-核心概念 | 它是按概率续写文本，不是查表 |
| 你怎么「管」它说什么？ | 02-提示词工程 | 系统提示是岗位说明书，输出是契约 |
| 数字从哪来？ | 03-函数调用与工具 | Java 查库，模型只负责选工具和解释 |
| 制度口径从哪来？ | 04-RAG | 向量检索外挂资料，不是让模型背公司制度 |
| 上一轮聊了什么？ | 05-记忆与会话 | 对话记忆≠知识库，别塞全公司数据 |

再加上：

- **06-Agent 架构模式**：多个概念怎么排成一条流水线。
- **07-评估护栏与幻觉**：没有评测集就没有迭代；红线怎么写进工程。

这五问，合上书你要能**对着空气讲三分钟**。这是本周毕业标准，不是期末标准。

## 4. 与 Spring AI 2.0、DeepSeek 的关系

本周不讲 `@Tool` 注解怎么写，但你要带着这两条线读：

**Spring AI 2.0**  
- `ChatClient` 是一等公民；工具循环在 `ToolCallingAdvisor` 里。  
- 配置里 `temperature`、`max-tokens`、`stop` 等选项，对应本章讲的采样参数。  
- 结构化输出、Advisor 链，对应「提示词契约」和「护栏」。

**DeepSeek**  
- 对话模型有普通档与带 **thinking**（思考过程）的档。  
- **reasoning-effort** 控制推理力度。  
- 多轮对话时，**思考过程（CoT）通常不回灌到下一轮上下文**——这是 DeepSeek 的 API 行为特点，企业 Agent 设计时要记住：你保存给下一轮的，应是「最终答案 + 工具结果」，不是模型内部推理全文。

决策类场景的温度建议：**0.1～0.3**。本周在 01 章会讲透为什么；技术选型说明书里的默认 `0.2` 就是这个区间。

## 5. 本周统一输出结构（先背下来）

后面所有章节、你写的提示词草稿、将来产品的管理层报告，都尽量固定五段：

1. **结论** — 一句话，敢不敢拍板先放这里（仍须带依据）。  
2. **数字** — 必须来自工具或明确标注「无数据」；模型不许自编。  
3. **依据** — 查了哪些工具、引了哪条制度/文档（RAG 来源）。  
4. **风险** — 数据延迟、口径冲突、权限未覆盖、模型不确定处。  
5. **建议** — 可执行下一步；默认**建议单**，不是直接改库。

这不是排版爱好，是**防幻觉的工程习惯**。02 章会展开怎么写进系统提示。

## 10. 【易混】导读

| 易混点 | 正确理解 |
|--------|----------|
| 聊天机器人 vs 决策 Agent | 前者以对话体验为主；后者以**可追溯的数字和依据**为主 |
| 参数多 vs 更准 | 温度低是**更稳**，不是更聪明；聪明靠工具和 RAG |
| 提示词长 vs 效果好 | 长提示浪费 token，还增加污染面；关键是结构清晰、红线明确 |
| 记忆大 vs 更懂你 | 塞全公司数据进会话 = 泄密 + 污染 + 贵 |
| CoT 回灌 | DeepSeek 思考过程多轮通常**不进**下一轮上下文；别自己瞎塞 |
| 本周 vs 下周 | 本周概念；下周才写 `ChatClient` |

## 14. 与你们 EMS / 供应链场景的映射

讲义举例常用「库存、仓库、补货」，是因为管理层问题高度同质。你若做设备能源管理（EMS），请做一张**概念替换表**，贴在笔记首页：

| 讲义术语 | 你可替换为 |
|----------|-----------|
| 仓库 warehouse | 厂区 / 产线 / 站点 |
| 物料 sku | 设备位号 / 测点 / 能源介质 |
| 库存 qty | 实时读数 / 累计能耗 / 备用件数量 |
| 补货 | 检修派工 / 采购备件 / 负荷调剂 |
| 安全库存制度 | 设备维护规程 / 能耗定额制度 |

机制不变：**数字走工具，口径走 RAG，格式走提示词**。换名词不换架构。

## 15. 开卷术语表（先抄 10 个，本周凑满 20 个）

1. **Token**：模型计费与上下文长度的基本单位，不是「一个字」。  
2. **Temperature（温度）**：控制随机性；决策建议 0.1～0.3。  
3. **Hallucination（幻觉）**：自信但错误的内容，机制性必然，需工程治理。  
4. **Function Calling（函数调用）**：模型输出调用意图 JSON，Java 执行。  
5. **Embedding（嵌入）**：文本转向量，用于语义检索。  
6. **RAG**：检索增强生成，外挂制度片段再回答。  
7. **TopK**：检索返回最相似的 K 个文档块。  
8. **SessionId**：会话唯一标识，绑定记忆与审计。  
9. **Advisor**：Spring AI 2.0 中可组合的拦截链，插记忆/RAG/工具循环。  
10. **Guardrail（护栏）**：权限、只读、来源校验等多层防御。

剩余 10 个词请你在读完 01～07 后自己写定义，不要抄书原句。

## 20. 深度阅读：为什么 Java 工程师适合学 Agent

你们已经习惯：

- **接口契约**：提示词和 JSON schema 就是契约。  
- **分层架构**：API / Service / DAO 对应 API / Agent / Tool。  
- **事务与权限**：比「让模型自觉」可靠一万倍。  
- **集成存量系统**：Agent 的价值在打通 ERP，不在聊天 UI。

你们不习惯的只有一件事：**输出不确定**。本周就是把不确定性关进「温度、工具、评测」的笼子里。

## 30. 深度专题：本周与「写代码」的边界

允许写的：Markdown 笔记、YAML 评测草稿、Draw.io 图、提示词 txt。  
不允许写的：Spring Boot 工程、`pom.xml`、连生产库脚本。

## 32. 收束：打开第一章之前

确认你已准备好：笔记本、可脱敏的真实业务问句三条、2 小时不被打扰的时间。

**致 Java 老兵**：你们见过太多「框架先上、业务后补」的项目翻车。AI 项目翻车的姿势一样——先接 API 再补护栏。我们故意把顺序倒过来：先护栏与概念，后代码。信这个顺序，十周后你会感谢自己。
