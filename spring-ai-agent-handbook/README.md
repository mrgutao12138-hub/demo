# Spring AI Agent 手把手讲义

> 写给已经会 Java / Spring Boot 的工程师。  
> 目标不是“会调一次大模型接口”，而是：**独立设计、实现、上线一个面向管理层的企业辅助决策 Agent**。

---

## 0. 这份讲义是干什么的

你现在的处境，我替你说清楚：

- 你会写 Java 服务端：Controller、Service、Mapper、事务、权限、接口契约。
- 你听说 AI Agent 很火，但不知道从哪下手。
- 你不想再学一套 Python 生态，时间不够。
- 你最终要做的不是聊天机器人，而是：**把公司 ERP / WMS / EMS 的数据变成管理层能问、能信、能决策的助手**。

这份讲义就是为此准备的。你学完之后，应该能够：

1. 用自己的话讲清：大模型、Token、Prompt、Tool、RAG、Memory、Agent 分别是什么，彼此怎么咬合。
2. 从零搭建 `Spring Boot 4.1 + Spring AI 2.0 + DeepSeek 云端 API` 项目。
3. 独立完成：对话、流式输出、结构化输出、工具调用循环、会话记忆、RAG、只读数据查询、权限与审计。
4. 独立搭出第一版「管理层辅助决策系统」：能问库存、订单、异常、趋势，答案带来源，危险操作被拦住。
5. 知道 GPT、本地大模型、多模型路由怎么接，但不会把它们和主流程搅在一起。

**学完不等于成为大模型研究员。学完等于你能当这个系统的主程。**

## 1. 技术选型（主线，不要改）

主学习流程全程只用这一套：

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 / 运行时 | Java 21（最低 17，可选 25） | Boot 4.1 最低 Java 17，生产建议 21 LTS |
| 应用框架 | Spring Boot **4.1.x** | 建立在 Spring Framework 7、Jakarta EE 11、Jackson 3 |
| AI 框架 | Spring AI **2.0.0**（BOM） | 2026-06 正式 GA，ChatClient 为一等 API |
| 大模型 | DeepSeek 云端 API | 官方 starter：`spring-ai-starter-model-deepseek` |
| 默认对话模型 | `deepseek-v4-pro`（复杂决策）/ `deepseek-v4-flash`（日常） | 2.0 默认值是 flash，本讲义决策场景用 pro |
| 构建 | Maven 3.9+ | 用 `spring-ai-bom` 管版本，不要手写传递依赖版本 |
| 向量库（学习） | 内存 `SimpleVectorStore` | 先跑通，再换 pgvector |
| 向量库（生产） | PostgreSQL + pgvector | 企业最省事的一档 |
| Embedding | 本地 Transformers starter，或兼容 OpenAI 的中文 embedding 服务 | DeepSeek 对话 API **不提供** embedding，必须另接 |

扩展知识（**不要提前学，学完主线再看**）在 `extensions/`：

- GPT / OpenAI 兼容接口
- 本地大模型（Ollama）
- 通义 / 智谱 / 文心等国产云
- 多模型路由
- Spring AI 1.x → 2.0 迁移
- MCP 与 Agent Skills 深水区

## 3. 最终要做成什么样（先看见终点）

管理层打开一个内部网页（或企业微信里的一个入口），用中文问：

- 「华东仓 SKU-88321 现在能发多少？缺货风险大吗？」
- 「本月采购超期的供应商 Top 5 是谁？影响了哪些在途单？」
- 「昨天 EMS 设备停机超过 30 分钟的产线有哪几条？和产出缺口对得上吗？」

系统做的事情，不是“编一段听起来专业的话”，而是：

1. 识别意图（查库存 / 查供应商 / 查停机）。
2. 调用你写好的**只读工具**去查库（带租户、仓、权限）。
3. 必要时检索制度文档、口径说明（RAG）。
4. 把数字、对比、风险、建议组织成结构化回答。
5. 每条关键数字带来源：哪张表、哪个时间、哪个过滤条件。
6. 任何写操作（下单、改库存、关工单）默认拒绝，或走人工确认。

这就是 Agent。聊天窗口只是壳。

## 4. 学习原则（请先读，后面会反复用）

1. **大模型是不可靠的推理引擎，不是数据库。** 数字必须来自工具或检索，不能来自“它记得”。
2. **Agent = 模型 + 工具 + 循环 + 约束。** 缺任何一块都只是 chatbot。
3. **先只读，后写入。** 企业里写错一行库存，比答错一句话严重一百倍。
4. **Spring AI 2.0 请用 ChatClient，不要把 ChatModel 当日常 API。** ChatModel 是底层积木。
5. **工具循环在 Advisor 链里，不在模型 SDK 里。** 这是 2.0 相对 1.x 最大的架构变化。
6. **不要把 ERP 的全部表结构塞进 Prompt。** 用工具暴露“业务能力”，不是暴露“数据库”。
7. **扩展模型（GPT、本地）只换 starter 和配置，不换你的业务代码。** 这正是选 Spring AI 的理由。

## 6. 关于“资料尽量不要外部链接”

本讲义把你需要的概念、配置、代码、坑，全部写在文件夹里。你不需要先去翻英文官网才能学。

个别地方会点名官方构件名（例如 `spring-ai-starter-model-deepseek`），这是坐标，不是作业。版本以讲义冻结的为准：

- Spring Boot：`4.1.x`
- Spring AI BOM：`2.0.0`
- 主模型：DeepSeek 云端 `deepseek-v4-pro` / `deepseek-v4-flash`

如果将来版本号前进了，先看 `appendix/踩坑手册.md` 里的「版本漂移怎么办」，再决定是否升级。学习阶段不要追快照版。
