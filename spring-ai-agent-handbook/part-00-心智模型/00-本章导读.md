# Part 00 · 心智模型 · 本章导读

> 同学，欢迎来到整本讲义的第一站。  
> 在写任何一行 Spring AI 代码之前，我们要先把「脑子里的地图」画对。  
> 地图错了，后面代码再漂亮，也是在错误的方向上狂奔。

## 你现在在哪

你此刻的位置，可以用一句话概括：

**你已经会写 Spring Boot 服务端，但还不确定「Agent」到底和你熟悉的 Controller、Service、Repository 是什么关系。**

你可能已经：

- 在浏览器里用过 ChatGPT、DeepSeek 网页版，觉得「挺聪明」；
- 听过 RAG、Tool Calling、向量库这些词，但说不清和 MyBatis 有啥区别；
- 被领导或产品问过：「我们能不能做一个问数、问库存、问设备的智能助手？」

你还没做到的是：

- 把大模型放进 Spring 应用里，而不是打开一个网页；
- 让 Agent 查到的数字来自 ERP/WMS/EMS 的真实数据，而不是模型「编」出来的；
- 画出一张能拿去跟架构师、安全、DBA 对齐的系统图。

Part 00 就是专门解决「脑子里的地图」的。后面 Part 01～09 会教环境、API、Tool、RAG、上线；**但 Part 00 决定你读后面每一章时，是在「组装零件」，还是在「理解系统」。**

## 学完 Part 00 你能干什么

把 Part 00 六讲啃完、作业做完、验收题答顺之后，你应该能：

1. **用 Java 工程师的语言**解释：ChatClient、ChatModel、Advisor、Tool、RAG、Memory 各自像 Spring 生态里的哪一层，而不是背 AI 黑话。
2. **明确说出**大模型能做什么、不能做什么——尤其能向非技术同事解释：「它像高级文案和推理助手，不是数据库，不能当财务数的来源。」
3. **理解 Token、Prompt、上下文窗口**对成本和正确性的影响，知道为什么管理层问一句「全公司库存怎么样」可能既贵又容易错。
4. **区分**聊天机器人和企业 Agent：后者必须有工具、权限、审计、只读边界。
5. **画出**你要做的「管理层辅助决策系统」全景：从 HTTP 入口到 DeepSeek，再到只读宽表/视图，以及第一版明确不做的事。

如果你学完 Part 00 仍然觉得「Agent 就是一个更聪明的 ChatController」，请重读第 04、05 讲，不要急着进 Part 02 写 HelloWorld。

## 1. Part 00 在整本讲义里的位置

把整本讲义想成你以前带新人做 ERP 对接项目时的阶段划分：

```
Part 00  心智模型     ← 你现在在这：先统一语言和对系统的想象
Part 01  生成式 AI 基础
Part 02  环境与 HelloWorld
Part 03  Spring AI 核心 API
Part 04  工具调用与 Agent 循环
Part 05  RAG 与企业知识
Part 06  企业数据接入
Part 07  记忆、安全、可观测
Part 08  综合项目：管理层辅助决策系统

```

Part 00 **没有**要求你配 DeepSeek 密钥、没有要求你 `mvn spring-boot:run`。这是刻意的。

很多工程师的习惯是：文档刚打开就 clone、改 `application.yml`、跑起来再说。做 CRUD 这样没问题；做 Agent 这样很容易在第三周才发现：**你接的是「聊天接口」，不是「决策辅助系统」。** 返工成本比多花一晚上读概念高一个数量级。

Part 00 的定位，相当于项目启动会上的「业务边界 + 架构原则」——先对齐，再编码。

## 2. 本 Part 六讲分别解决什么问题

### 2.1 第 01 讲：从 Java 服务端到 AI Agent

你会看到一张「对照表」：Controller、Service、Filter、JdbcTemplate、缓存，分别对应 Spring AI 里的谁。

核心结论先剧透一句：**Agent 不是新语言，是在你现有 Spring 分层上，多了一条「会调用大模型、会循环调 Tool」的编排链。**

### 2.2 第 02 讲：大模型到底是什么

不讲微积分，讲「概率接龙机」和「训练数据边界」。你会理解为什么模型会说得很像真的、但库存数字可能是假的。

【红线】这一讲要刻进骨头：**大模型不是数据库。**

### 2.3 第 03 讲：Token、Prompt、上下文窗口

这是成本和稳定性的开关。管理层一句模糊的大问题，可能吃掉几万 Token；上下文塞满了，模型还会「忘记」你 ten 分钟前给的约束。

用 Java 类比：Token 像字节流计费单位；Prompt 像完整 HTTP 请求体；上下文窗口像一次请求能携带的最大 body——超了就得截断或摘要。

### 2.4 第 04 讲：Agent 不是聊天机器人

ChatGPT 网页版是给「人随便聊」的产品；企业 Agent 是给「有权限的人、在边界内、查真实数据、留审计」的系统。

你会学到：没有 Tool、没有权限、没有只读护栏的 Demo，只能叫 ChatBot，不能叫管理层辅助决策 Agent。

### 2.5 第 05 讲：辅助决策系统全景

全 Part 00 的收束。ASCII 架构图、三个管理层问题样例（库存、超期采购、设备停机）、以及第一版**明确不做**的事（自动改库存、自动下单）。

这一讲结束时，你应该能拿着图去跟 DBA 谈只读账号、跟安全谈出网策略、跟产品谈 MVP 范围。

## 3. 读 Part 00 的三条纪律

### 3.1 带着 ERP/WMS/EMS 场景读，不要带着「写小说」场景读

讲义里的例子会反复出现：

- 某 SKU 在华东仓到底还有多少可用库存？
- 哪些采购订单超期未到货、影响哪条产线？
- 空压站昨天非计划停机多久、近 30 天同类故障几次？

这些不是举例装饰，而是后面 Part 08 综合项目的题眼。你读概念时就要想：**这个问题，数字从哪张表来？能不能只读？要不要审计？**

### 3.2 主动做 Java 类比，不要被动背术语

每讲都会给类比，但你要自己再补一条「你们公司里的真实对应物」：

| Spring AI 概念 | 讲义类比 | 请你填：你们项目里像什么 |
|--------------|----------|--------------------------|
| ChatClient | 业务门面 Facade | 例如：`InventoryQueryFacade` |
| ChatModel | JDBC 驱动 | 例如：DeepSeek 官方 Starter 背后的实现 |
| Advisor | 可循环的 Filter | 例如：鉴权 + Tool 循环 + 日志 |
| Tool | 受控的 Service 方法 | 例如：`queryStockBySku()` |
| RAG | 带语义的只读缓存检索 | 例如：制度 PDF + 向量库 |
| Memory | 会话级缓存 | 例如：Redis 里按 sessionId 存最近 N 轮 |

填不出来没关系，先写「待定」；Part 06 接入数据时会回来补。

### 3.3 验收不过，不进入 Part 01

Part 00 每讲末尾都有【必做】作业和口头验收题。这是学习契约（见 handbook 根目录《00-使用说明与学习契约》），不是形式主义。

特别是下面三道，必须能脱稿答：

1. 大模型和 MySQL 的本质区别是什么？
2. 为什么企业 Agent 第一版建议只读？
3. ChatGPT 网页版和企业里 Spring AI Agent 差在哪至少三点？

有一道卡壳，就重读对应讲次，不要「先往下走再说」。

## 4. 本 Part 会用到的技术名词（先混个脸熟）

后面章节会反复出现，这里只给「一句话印象」，细节在各讲展开：

- **Spring Boot 4.1**：你熟悉的 Boot，基线升到 4.x，与 Spring Framework 7 对齐。
- **Spring AI 2.0**：Spring 官方 AI 抽象；日常开发以 **ChatClient** 为主入口，**ChatModel** 是底层实现。
- **DeepSeek**：云端大模型 API；讲义用官方 `spring-ai-starter-model-deepseek`，密钥走环境变量。
- **Embedding**：把文本变成向量，供相似度检索；不是生成回答本身。
- **VectorStore**：存向量、按相似度查；像「语义索引」，不是业务事实库。
- **@Tool**：声明模型可调用的 Java 方法；必须受权限和参数校验约束。

【易混】现在不需要会写代码，但要知道：**Spring AI 1.x 的很多中文教程已过时**（例如把 `QuestionAnswerAdvisor` 当主路径、`internalToolExecutionEnabled` 等）。本讲义全程按 2.0 讲。

## 6. 老师带你走一遍：假设你是某厂仓储经理的「数字参谋」

我先讲一个完整故事，帮你把 Part 00 的六讲串成一条线。你可以对照自己公司改名词。

**背景：** 某制造集团，WMS 在华东、华南有两个大仓；ERP 管 PO；EMS 管空压站和关键产线设备。厂长每周例会前要搞清三件事：库存是否撑得住、采购是否拖排产、设备是否频繁非计划停机。

**若只有 ChatGPT 网页：** 厂长在浏览器里问「ABC 华东还有多少」。页面返回一段很像真的文字，甚至带表格。他截图发群里，计划员去系统里一查——数是错的。没人能复盘「这个 500 从哪来的」。安全部门也会问：这算不算把经营数据贴到公网？

**若有 Part 00 心智模型里的企业 Agent：** 厂长打开内网 Portal，SSO 登录。问同样问题。请求进 `AgentController`，`ChatClient` 带着 system 红线调 DeepSeek。模型 **不猜数**，而是规划调用 `queryAvailableStock`。Advisor 执行 `@Tool`，只读视图 `v_wms_available_stock` 返回 `{ "qty": 127, "asOfTime": "..." }`。模型用中文归纳：「当前可用 127 件，低于安全库存 150，建议人工跟进在途 PO……」界面底部显示：**数据来源视图 + 查询时间**。日志里 traceId 可审计。

看到差别了吗？Part 00 六讲就是在解释 **第二个世界** 怎么搭：第 01 讲分层，第 02 讲模型不能当库，第 03 讲 Token 别贴 Excel，第 04 讲不是聊天套壳，第 05 讲整图。

### 6.1 你作为 Java 工程师在故事里的位置

你不是去训练模型，而是：

1. 和 DBA 定义只读视图（Part 06 细讲）；
2. 把现有 `InventoryReadService` 包成 `@Tool`（Part 04）；
3. 用 ChatClient 挂 Advisor 链（Part 03）；
4. 在 system prompt 里写「只读宪法」（本章 + 第 04 讲）；
5. 打 usage 与 tool 日志（Part 07）。

**你的主战场仍是 Spring 服务端**，只是多了一条「自然语言入口」。这也是讲义坚持 Java 路线、不引 Python 的原因：Tool 背后本来就是你的 Service，没必要再养一套运行时。

### 6.2 Part 00 学完后，跟各角色怎么说话

| 对象 | 你可以说什么 |
|------|--------------|
| 产品经理 | 第一版是辅助看数和制度，不自动改库存、不自动下单；聊天框只是 UI。 |
| DBA | 我要只读账号和 3 个视图，不在应用里写 ad-hoc 大 join；每次查询要 asOfTime。 |
| 安全 | 走 SSO；出网只有 DeepSeek API；Prompt 里最小化敏感字段；全链路 audit。 |
| 厂长 | 数来自 WMS/ERP/EMS，不是 AI 「想出来的」；建议要人点确认才执行。 |

能把这张表讲顺，Part 00 就值了。代码可以后面再敲，**对齐预期**必须先做。

### 6.7 FAQ：Part 00 开课前最常问的五个问题

**Q1：我 Maven 很熟，但没碰过 AI，会不会跟不上？**  
跟得上。本 Part 不教训练模型，只教 **怎么在 Spring 里接 DeepSeek + Tool**。你已有的分层、SQL、权限经验是主资产，AI 是新增一条编排链。

**Q2：公司还没批 DeepSeek 出网，能学 Part 00 吗？**  
能。Part 00 全部可以 **无密钥** 完成；只有第 02 讲作业里的「网页幻觉实验」需要你能访问某模型 playground，也可用讲义里描述的「假想结果」自测。

**Q3：我们实际是 MES 不是 EMS，讲义例子要不要改？**  
概念通用。库存对应 WMS/ERP，停机对应 MES/EMS 设备模块；架构图里 EMS 框改成 MES 即可，Tool 与视图命名跟你们主数据走。

**Q4：Part 00 要做笔记吗？**  
要，但 **不超过 5 条/讲**（学习契约已写）。建议固定记：今天一个类比、一个红线、一个要问 DBA 的问题。

**Q5：Part 00 和 Part 01 重复吗？**  
Part 00 是 **工程心智 + 企业边界**；Part 01 补 **生成式 AI 少量原理**（仍不写复杂数学）。00 讲「Tool 必须查库」，01 讲「为什么生成式输出概率性」。互补，不重复。

### 6.8 写给带新人的你：如何讲 Part 00

若你将来带同事学这套讲义，建议 **不要** 第一节就演示 ChatGPT。第一节带他们画 **REST 链 vs Agent 链**，讲 **「数字从哪来」**。第二周再 Demo HelloWorld。顺序错了，团队会把 Agent 理解成「接口调 DeepSeek」，后面改心智成本极高。你现在的学习顺序，就是将来带人的标准教案。

## 常见误解

| 误解 | 正解 |
|------|------|
| 「Part 00 是理论，可以跳过直接写代码」 | Part 00 是边界和地图；跳过的话，你很可能先做成了一个无 Tool、无审计的聊天 Demo，后面全盘重构。 |
| 「Agent 就是调大模型 API，和调第三方支付 API 一样」 | 支付 API 返回确定结果；大模型返回的是概率生成的文本，**事实性数字必须来自 Tool/SQL**。 |
| 「公司同事会用 ChatGPT，所以 Agent 产品形态就是聊天窗口」 | 聊天只是交互壳；企业 Agent 的核心是 **Tool + 权限 + 数据边界 + 可观测**；ChatGPT 网页没有你们库的连接。 |
| 「心智模型懂了，后面代码很简单」 | 心智模型降低返工概率；Tool 设计、RAG 质量、SQL 宽表、安全护栏，后面每一章都有硬活。 |
| 「EMS 和 MES 搞不清，没法学」 | 讲义按设备/能源/运维类系统理解；库存、采购、停机三类问题在 WMS/ERP/EMS 里都有对应，概念通用。 |
