# 00 · 使用说明与学习契约

> 老师先跟你把规矩讲清楚。后面所有章节都按这个契约写，你也按这个契约学。

---

## 1. 这份讲义的读者画像

你符合下面大部分条件，这份讲义就是为你写的：

- 独立做过 Spring Boot 服务：CRUD、鉴权、定时任务、消息、对接过至少一个内部系统。
- 会 SQL，见过 ERP / WMS / MES（你写的是 EMS，本讲义按「设备/能源/运维类业务系统」理解；若你们实际是 MES，概念同样适用）。
- 没系统学过机器学习，也不打算转算法岗。
- 明确拒绝 Python 作为主技术栈。
- 最终交付物是给管理层用的辅助决策系统，不是给研发的 Copilot。

如果你还不会 Spring Boot，请先停下来，把「依赖注入、配置、Web、JDBC」补到能独立写一个带登录的 CRUD 服务。本讲义不教 Spring 入门。

## 2. 学习契约（请认真对待）

### 2.1 你要承诺的

1. **每一章的代码自己敲一遍。** 复制能跑，但记不住。Agent 开发最怕“看起来会”。
2. **每一章末尾的验收题必须口头答出来。** 答不出来就重读，不要硬往下赶。
3. **涉及公司真实库之前，先用讲义里的模拟库。** 在本地用 Docker 起一个 Postgres，灌演示数据。不要一上来连生产只读账号。
4. **密钥永远不进 Git。** `DEEPSEEK_API_KEY` 放环境变量或本地未提交的配置。
5. **写操作默认不做。** 学习阶段所有 Tool 只读。综合项目里若要做“建议补货”，也只生成建议单，不直接改库存。

### 2.2 我作为讲义要承诺的

1. 主线只使用 Spring Boot 4 + Spring AI 2.0 + DeepSeek，不把 GPT / Ollama 混进步骤。
2. 每个关键概念用 Java 工程师听得懂的类比解释，再给可运行代码。
3. 每个阶段告诉你：现在在哪、下一步干什么、怎样才算过关。
4. 过时 API（Spring AI 1.x 的 `QuestionAnswerAdvisor` 主路径、`internalToolExecutionEnabled`、`toolNames()`）会明确标「不要用」。
5. 企业场景里的安全红线会反复出现，而不是最后一章才提。

## 3. 你每天的标准学习动作

用这个循环，不要“打开文档看到哪算哪”：

1. **读**本章导读（5～10 分钟）：知道今天要解决什么问题。
2. **读**正文时，遇到代码先想「如果是我，我会怎么写」，再看讲义写法。
3. **敲**代码。卡壳先看本章「常见卡点」，再看 `appendix/踩坑手册.md`。
4. **跑**起来，用讲义给的输入测 3 组：正常、边界、恶意/胡扯。
5. **讲**：合上文档，用不超过 3 分钟给空气讲一遍今天的核心机制。
6. **记**：在自己的笔记里只记 5 条以内——不是抄书，是你自己的坑和顿悟。

如果某天只能学 40 分钟：只做 1、2、5。代码放到第二天，但概念不要断。

## 4. 难度标记

正文里你会看到三种标记：

- **【必做】** 不完成不能进入下一章。
- **【建议】** 强烈建议做，能显著减少后面返工。
- **【选做】** 有余力再做，不影响主线毕业。

还有两种警告：

- **【红线】** 企业里做错会出事：权限、写库、密钥、幻觉当事实。
- **【易混】** Spring AI 1.x 教程和 2.0 行为不一样的地方。网上大量中文帖还停在 1.x。

---

## 5. 你不需要先会的东西

下面这些，**先不要学**，否则你会迷路：

- PyTorch / 微调 / 训练自己的模型
- CUDA、显卡驱动（本地模型是扩展篇的事）
- LangChain / LangGraph / LlamaIndex（那是 Python 生态，概念可借鉴，代码不要混）
- Kubernetes 上的 GPU 调度
- 多 Agent 自治公司、完全自动下单的“数字员工”

第一版决策系统的正确形态是：**人问 → Agent 查 → 给出带来源的判断和建议 → 人决定。**

## 6. 工具与环境最低要求

- 一台能安装 JDK 21 和 Maven 的电脑（8GB 内存可学；16GB 更舒服，尤其后面开 Postgres + 本地 embedding）。
- 能访问 DeepSeek API 的网络。
- 一个 DeepSeek 账号，并完成实名与充值（学习阶段 50～100 元足够跑很久，前提是你不要把长文档循环送进去）。
- IDE：IDEA 社区版即可。
- Docker Desktop 或等价环境（part-06 起用来起 Postgres）。没有 Docker 也能学到 part-05，用 H2 / 内存库替代，但 part-06 会变别扭。

## 7. 代码风格约定（全讲义统一）

- 包名示例：`com.company.decision`
- 配置一律 `application.yml` + 环境变量
- 对外 HTTP 用 JSON，字段用 camelCase
- Tool 方法名用英文动词短语：`queryInventory`、`listOverduePurchaseOrders`
- Tool 的 `description` 用中文写清楚「做什么、何时用、不要做什么」
- 所有给管理层的回答结构尽量固定为：结论 → 关键数字 → 依据 → 风险 → 建议下一步
- 日志打印 Tool 名、参数摘要、耗时、是否命中缓存；**不打印**完整证件号、完整密钥、完整身份证

【易混】如果你看到这些写法，直接当过时：

- `PromptChatMemoryAdvisor`

## 9. 毕业标准（先记在心里）

当你能独立做到下面这件事，就可以宣布主线毕业：

> 在一个只有演示数据的 Postgres 上，启动你的 Spring Boot 应用。  
> 用浏览器问三句不同业务域的话（库存、采购超期、设备停机）。  
> 系统自动选工具、查出数字、给出建议，关键数字能追溯到 SQL 或文档片段。  
> 你把 API Key 配错、把无权限仓位问一遍、把“帮我把库存改成 0”问一遍，系统分别能报错、拒绝、拒绝。  
> 日志里能看到每次调用的模型、token、工具、耗时。

详细打勾清单在 `02-能力地图与验收标准.md`。
