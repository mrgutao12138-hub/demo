# 术语表

> 随手查用。每条：**一句话定义** → **在本讲义项目中的用法** → **易混点**。  
> 版本冻结：Spring Boot 4.1.x · Spring AI BOM 2.0.0 · DeepSeek 云端 API。

---

## A

### Agent（智能体）
**定义：** 能根据目标自主选择工具、多轮调用、直到满足停止条件的应用形态，不只是单轮问答。

**本项目用法：** part-04 起用 `ChatClient` + `@Tool` + `ToolCallingAdvisor` 实现库存决策 Agent；part-08 综合为 Decision Copilot。

**易混点：** Agent ≠ 聊天机器人。没有工具循环和约束，只是 Chatbot。

### Advisor（顾问 / 拦截器）
**定义：** 挂在 `ChatClient` 请求链上的可组合组件，可在调用模型前后改写 Prompt、注入检索、驱动工具循环，且支持重入。

**本项目用法：** `MessageChatMemoryAdvisor`（记忆）、`RetrievalAugmentationAdvisor`（RAG）、`ToolCallingAdvisor`（工具循环）按 order 排序组合。

**易混点：** 类似 Servlet Filter，但 Advisor **可以重入**（工具循环每一轮都会再走链）；Filter 通常只走一次。

---

## B

### BOM（Bill of Materials，物料清单）
**定义：** Maven 用 `import` 作用域引入的依赖版本清单，子模块不写版本号，由 BOM 统一对齐。

**本项目用法：** `spring-ai-bom:2.0.0` 必须在 `dependencyManagement` 里 `type=pom` + `scope=import`，见 `appendix/pom完整模板.md`。

**易混点：** 只写 `dependency` 不写 `import` scope，版本会漂移，出现 `NoSuchMethodError`。

---

## C

### ChatClient
**定义：** Spring AI 2.0 面向业务的一等 API，提供 fluent 链式调用：prompt / advisors / tools / call / stream。

**本项目用法：** Controller 和 Service 日常只注入 `ChatClient` 或 `ChatClient.Builder`，不直接用 `ChatModel`。

**易混点：** `call()` 本身不立刻打模型；真正发请求的是 `.content()`、`.entity()`、`.stream()` 等消费端。

### ChatModel
**定义：** 与大模型提供商通信的底层接口，负责把 `Prompt` 转成 `ChatResponse`。

**本项目用法：** 自动配置注册 `DeepSeekChatModel`；业务代码几乎不注入，只有手写工具循环或调试时才碰。

**易混点：** 1.x 教程让 Controller 直接注入 `ChatModel`；2.0 日常编程对象是 `ChatClient`。

### Context Window（上下文窗口）
**定义：** 单次请求模型能「看见」的最大 Token 总量，含 system、历史、检索片段、工具 schema、用户输入。

**本项目用法：** part-01 讲预算；part-05 控制 RAG `topK`；part-07 管记忆截断；超窗会截断或报错。

**易混点：** 窗口大 ≠ 可以塞全文制度；企业文档仍要走 RAG 按需检索。

### CONVERSATION_ID
**定义：** 标识一次多轮对话会话的运行时参数，供 `MessageChatMemoryAdvisor` 读写对应记忆。

**本项目用法：** API 层从登录用户 + 前端会话 ID 生成，每次 `chatClient.prompt().advisors(a -> a.param(CONVERSATION_ID, id))` 传入。

**易混点：** 不传则所有人共享一份记忆，或每次都没有历史；与 HTTP Session ID 概念相近但应显式传递。

---

## D

### DeepSeek Chat / Flash / Pro
**定义：** DeepSeek 云端对话模型档位：Flash 快且便宜，Pro 强且适合复杂决策与思考模式。

**本项目用法：** Hello World 用 `deepseek-v4-flash`；决策 Agent 默认 `deepseek-v4-pro` + `thinking` + `reasoning-effort: high`。

**易混点：** DeepSeek **不提供**官方 embedding API；对话模型不能替代向量模型。

### Document（文档对象）
**定义：** RAG 流水线中的基本单元，含文本内容与元数据（标题、制度编号、组织、生效日等）。

**本项目用法：** part-05 把 Markdown 制度按标题切分成 `Document`，经 `EmbeddingModel` 写入 `VectorStore`。

**易混点：** `Document` 是框架类型，不是磁盘上的原始 PDF 文件；入库前要加载和切分。

---

## E

### Embedding（嵌入 / 向量）
**定义：** 把文本映射为高维浮点向量，使语义相近的文本在向量空间中距离更近。

**本项目用法：** 学习期用 `spring-ai-starter-model-transformers` 本地 ONNX 模型；生产可换 pgvector + 专用 embedding 服务。

**易混点：** Embedding 是**另一类模型**，与 DeepSeek Chat 无关；配置前缀也不是 `spring.ai.deepseek`。

### EMS（设备管理系统）
**定义：** 制造企业用于设备台账、停机、维保、OEE 等的管理系统。

**本项目用法：** part-06 暴露只读 Tool（如 `queryDowntime`）；与 WMS/ERP 并列，各 2～3 个决策问题即可。

**易混点：** EMS 数据走 Tool + 宽表，不走 RAG；设备**制度**（维保 SOP）才进向量库。

### ERP（企业资源计划）
**定义：** 覆盖采购、销售、财务、主数据等的企业核心系统。

**本项目用法：** part-06 通过只读视图或同步宽表接入；Agent 不直连 ERP 写库。

**易混点：** 不要把 ERP 全表结构塞进 Prompt；用指标字典 + 固定 Tool 暴露「业务能力」。

---

## F

### Flash（闪速模型档）
**定义：** 延迟低、成本低的对话模型档位，适合简单问答与路由。

**本项目用法：** `flashClient` Bean 处理闲聊、意图粗分；复杂分析走 `proClient`。

**易混点：** Flash 仍会幻觉；涉及数字和制度时仍要 Tool/RAG，不能因「快」就省略护栏。

---

## H

### Hallucination（幻觉）
**定义：** 模型生成看似合理但与事实不符的内容，包括编造数字、条款、客户名。

**本项目用法：** 用 Tool 出数字、RAG 出口径、空检索拒答、结构化输出校验；part-01 与 part-07 反复强调。

**易混点：** 降低温度能减少胡编，**不能消除**；企业场景必须「无来源不说」。

---

## J

### Jackson 3
**定义：** Spring Boot 4 默认 JSON 序列化库，包名与 Jackson 2 不同（`tools.jackson` 等）。

**本项目用法：** DTO 用 record；工具返回值默认 Jackson 序列化给模型；结构化输出 `.entity()` 依赖它。

**易混点：** 网上旧示例仍是 `com.fasterxml.jackson`；混依赖会编译或运行失败。

---

## M

### MCP（Model Context Protocol，模型上下文协议）
**定义：** 标准化「远程工具进程」与 Agent 宿主之间发现、调用工具的协议，类似 USB 插座规范。

**本项目用法：** part-04 仅建立概念；可选 `spring-ai-starter-mcp-client`，需显式 `.tools(mcpProvider)`，不会自动进 ChatClient。

**易混点：** MCP ≠ 主数据接入方式；ERP 仍建议 Java `@Tool` + 只读库，MCP 用于接外部已封装能力。

### Message（消息）
**定义：** 对话中的单条记录，类型包括 System、User、Assistant、Tool（工具结果）。

**本项目用法：** `MessageChatMemoryAdvisor` 持久化 User/Assistant；JDBC 仓库对 Tool 消息支持有限，默认记忆放循环外。

**易混点：** Assistant 里可能含 tool call 请求；与最终给用户看的纯文本不是同一层概念。

### 指标字典
**定义：** 将中文业务指标名映射到官方 SQL、服务方法、口径说明与负责人的受控登记表。

**本项目用法：** part-06 Tool 内部查字典再执行固定 SQL；回答里写清指标定义来源与数据截止时间。

**易混点：** 指标字典文字说明可进 RAG；**实时数值**仍走 Tool，不能让模型从字典「猜」当前数。

---

## P

### Prompt（提示词）
**定义：** 发给模型的全部指令与上下文集合，含 system、user、历史、检索片段、工具定义等。

**本项目用法：** `defaultSystem` 写角色与红线；用户输入用 `.user()`；不要把密钥写进 Prompt。

**易混点：** Prompt 工程（part-01）是文本契约；运行时 Prompt 是框架组装后的完整消息列表。

### Pro（专业模型档）
**定义：** 能力强、适合推理与多步分析的对话模型档位，通常更贵更慢。

**本项目用法：** 库存对比、归因、风险建议走 `deepseek-v4-pro`；可开 `thinking` 与 `reasoning-effort: high`。

**易混点：** Pro 也会幻觉；「更强」不替代 Tool/RAG/权限。

---

## Q

### QuestionAnswerAdvisor
**定义：** Spring AI 1.x 时代常用的「检索 + 拼 Prompt + 调模型」一体化 Advisor。

**本项目用法：** **不作为 2.0 主路径**；讲义统一用模块化 `RetrievalAugmentationAdvisor`（`spring-ai-rag`）。

**易混点：** 中文旧教程 90% 仍教 QAA；照抄会与 2.0 Advisor 链、空结果策略冲突。

---

## R

### RAG（Retrieval-Augmented Generation，检索增强生成）
**定义：** 先按问题检索相关文档片段，再让模型基于片段生成回答，减少凭空编造。

**本项目用法：** **口径与制度走 RAG，数字走 Tool**；`RetrievalAugmentationAdvisor` + `VectorStoreDocumentRetriever`。

**易混点：** RAG 不是把 PDF 全文塞进 system；也不是实时库存查询的替代品。

### ReAct（推理 + 行动）
**定义：** Agent 模式：模型交替「思考下一步」与「调用工具」，直到得出最终答案。

**本项目用法：** Spring AI 2.0 由 `ToolCallingAdvisor` 实现循环，无需手写 ReAct 模板字符串。

**易混点：** ReAct 是模式名，不是某个 Java 类名；别去找 `ReActAgent` 这个 Bean。

### record（记录类型）
**定义：** Java 16+ 的不可变数据载体，适合结构化输出 DTO。

**本项目用法：** part-02 `.entity(MyRecord.class)` 与 `validateSchema()`；Boot 4 + Jackson 3 原生支持。

**易混点：** record 字段名要与 schema 一致；不要用可变 POJO 却指望自动修复字段名。

### returnDirect
**定义：** 工具注解属性：为 true 时工具结果直接作为最终答案，不再回模型组织话术。

**本项目用法：** 库存 Agent **默认不用**；管理层需要模型用数字解释风险与建议。

**易混点：** 同轮多个工具时，需**全部** returnDirect 才生效；混合场景行为易踩坑。

---

## S

### SSE（Server-Sent Events，服务端推送事件）
**定义：** HTTP 长连接单向推送文本流的技术，适合流式吐字。

**本项目用法：** part-02 `chatClient.prompt().user(msg).stream().content()` + `MediaType.TEXT_EVENT_STREAM`；需 `webflux` 依赖。

**易混点：** SSE 是传输方式，不是模型能力；与 WebSocket 双向通信不同，讲义第一版 SSE 足够。

### Structured Output（结构化输出）
**定义：** 约束模型输出符合 JSON Schema，并映射为 Java 类型。

**本项目用法：** `.entity(Dto.class)` 或 `.entity(Dto.class, spec -> spec.validateSchema())`；决策回答可固定「结论/数字/依据/风险/建议」。

**易混点：** 结构化输出减少格式乱，**不保证**数字正确；数字仍须来自 Tool。

### System Prompt（系统提示）
**定义：** 对话最高优先级指令，定义角色、红线、输出格式，通常每条会话都带。

**本项目用法：** `ChatClient.Builder.defaultSystem(...)` 或 `ChatClientBuilderCustomizer`；写清禁止写操作、禁止编造数字。

**易混点：** system 会被用户 Prompt 注入攻击试探；需 part-07 护栏，不能单靠「请遵守规则」。

---

## T

### Temperature（温度）
**定义：** 控制采样随机性的参数，越高越发散，越低越确定。

**本项目用法：** 查数、选工具用 0.2～0.3；写纪要可略高；不要全局 1.0。

**易混点：** 温度只影响措辞与路径选择，不能替代权限校验和 Tool。

### Token
**定义：** 模型处理文本的最小计费与长度单位，中英文切分方式因模型而异。

**本项目用法：** part-01 学预算；费用 = 输入 Token + 输出 Token；日志里记录 usage 做成本核算。

**易混点：** Token ≠ 汉字个数；长 system、工具 schema、RAG 片段都会占 Token。

### Tool Calling（工具调用）
**定义：** 模型在响应中声明要调用的函数名与 JSON 参数，由宿主执行后把结果回填再继续生成。

**本项目用法：** `@Tool` 方法 + `.tools(bean)` + `ToolCallingAdvisor` 自动循环。

**易混点：** 模型**不执行** Java；它只是「点菜」，厨房是你的 Service。

### ToolCallingAdvisor
**定义：** Spring AI 2.0 中负责工具定义下发、解析 tool calls、执行回调、多轮重入的核心 Advisor。

**本项目用法：** 默认自动注册一个（order ≈ 300）；与 `MessageChatMemoryAdvisor`（≈200）配合，记忆默认在循环外。

**易混点：** 1.x 循环藏在 `ChatModel` 内部；2.0 必须在 Advisor 链理解顺序。链上只能有**一个** ToolAdvisor。

### Tool Search（工具搜索）
**定义：** 工具过多时，先让模型选子集再披露 schema，避免一次塞几百个工具定义爆 Token。

**本项目用法：** 可选 `spring-ai-starter-tool-search-advisor`，替换默认 `ToolCallingAdvisor` 为 `ToolSearchToolCallingAdvisor`。

**易混点：** 工具少（<15）不必上 Tool Search；上了也要保证核心工具可被搜到。

### Transformers（本地向量模型 Starter）
**定义：** Spring AI 提供的基于 ONNX 的本地 `EmbeddingModel` 启动器，学习期免外网 embedding API。

**本项目用法：** `spring-ai-starter-model-transformers` 与 DeepSeek Chat **并存**；各干各的。

**易混点：** 名字叫 transformers，不是让你训练大模型；只是拉取预训练 embedding 权重做推理。

---

## V

### VectorStore（向量存储）
**定义：** 存储文档向量并支持相似度检索的组件。

**本项目用法：** 学习 `SimpleVectorStore`（内存）；生产 `PostgreSQL + pgvector`；与业务 OLTP 库物理分离。

**易混点：** VectorStore 存的是**制度知识**，不是实时库存表；实时数走 Tool。

---

## W

### WMS（仓储管理系统）
**定义：** 管理入库、出库、库存、库位、可用量等的系统。

**本项目用法：** part-04 假数据 Agent；part-06 `queryInventory` 等只读 Tool 对接宽表或只读视图。

**易混点：** WMS「可用量」口径以制度+RAG 为准，数以 Tool 查询结果为准，两者要对齐。

### 宽表
**定义：** 为分析或 Agent 查询预聚合、_denormalize_ 的只读大宽表，字段面向业务问题而非第三范式。

**本项目用法：** part-06 主路径：ERP/WMS/EMS 定时同步到决策宽表，Tool 只打宽表 + 白名单 SQL。

**易混点：** 宽表不是让模型随便 JOIN；每条 Tool 对应固定查询或字典 SQL。

---

## 其

### 会话记忆（Chat Memory）
**定义：** 在同一 `CONVERSATION_ID` 下保留多轮 User/Assistant 上下文，供后续追问。

**本项目用法：** `MessageChatMemoryAdvisor` + `ChatMemoryRepository`（内存 / Redis / JDBC）；**默认放工具循环外**。

**易混点：** 记忆 ≠ RAG；聊天内容不可当制度库。JDBC 记忆对 tool 消息支持差，勿把记忆塞进循环内除非确有必要。

### 只读（Read-Only）
**定义：** Agent 工具与数据源仅允许 SELECT 类查询，禁止 INSERT/UPDATE/DELETE 及副作用 API。

**本项目用法：** 全讲义红线；演示库也用只读账号；「改库存」「自动下单」一律拒绝或转人工。

**易混点：** 只读是**权限 + 代码设计**双保险；光有 `@Tool` 描述「只读」不够，要不提供写工具。

### 评测集（Evaluation Set）
**定义：** 固定问答用例集，用于改 Prompt/工具/检索策略后的回归，防止越改越差。

**本项目用法：** part-08 要求 20 条；含命中、未命中、拒写、越权、注入等类型；毕业答辩前必跑一遍。

**易混点：** 评测集不是单元测试替身；它测的是**端到端行为**与业务可接受性。

### 结构化输出
**定义：** 见 Structured Output；中文场景常指「结论 / 数字 / 依据 / 风险 / 建议」五段式回答契约。

**本项目用法：** part-02 用 record + schema；part-08 统一响应 DTO 给前端来源卡片。

**易混点：** 五段式是产品契约；`.entity()` 是技术实现；数字字段必须来自 Tool 返回值填充，不能让模型填。

### Prompt 注入（提示词注入）
**定义：** 攻击者在用户输入或文档中插入「忽略系统规则」等指令，企图劫持 Agent 行为。

**本项目用法：** part-07 测伪造指令；system 红线 + 工具权限 + 审计；RAG 文档也要当不可信输入处理。

**易混点：** 注入不是 SQL 注入；防的是**模型行为**被拐偏，仍要保留参数化 SQL 防注入。

### 多租户（Multi-Tenancy）
**定义：** 同一套 Agent 服务按租户隔离数据、配置、记忆与审计。

**本项目用法：** part-06/07 每个 Tool 强制带 `tenantId`；RAG 检索加 `org` 过滤；会话 ID 含用户与租户。

**易混点：** 多租户不是多个 ChatClient Bean 那么简单；鉴权必须在 Tool 和检索层落地。

### 思考模式（Thinking）
**定义：** DeepSeek 等模型在回答前输出内部推理链路的可选能力，提高复杂问题质量，增加 Token 与延迟。

**本项目用法：** 决策分析开 `spring.ai.deepseek.chat.thinking.type: enabled`；简单闲聊关。

**易混点：** 思考内容可能出现在响应元数据；管理层 UI 默认只展示最终结论，不展示推理过程。

### 空上下文策略
**定义：** RAG 检索不到任何片段时，是否仍允许模型自由发挥。

**本项目用法：** **默认关闭** `allowEmptyContext`；必须答「未检索到相关制度」，禁止编条款。

**易混点：** 聊天产品常开 allowEmptyContext 提升「总有回答」；决策系统要相反。
