# 踩坑手册

> 讲义学员最高频翻车点。每条：**现象 → 根因 → 修复 → 预防**。  
> 学习期版本钉死：**Spring Boot 4.1.x · spring-ai-bom 2.0.0 · Java 21**。

---

## 1. BOM 未 import

### 现象
- `mvn dependency:tree` 里 Spring AI 子依赖版本不一致
- 运行期 `NoSuchMethodError`、`ClassNotFoundException`
- IDE 报红但「明明写了依赖」

### 根因
只在 `<dependencies>` 里加了 `spring-ai-starter-model-deepseek`，**没有**在 `dependencyManagement` 里 import `spring-ai-bom`，或写成了普通 `dependency` 而非 `type=pom` + `scope=import`。

### 修复
```xml
<properties>
    <spring-ai.version>2.0.0</spring-ai.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

子依赖**不要**手写 `<version>`。

### 预防
复制 `appendix/pom完整模板.md`；改 pom 后习惯性跑 `mvn dependency:tree | grep spring-ai`。

## 2. 旧 starter 名

### 现象
- 依赖解析失败：找不到 `spring-ai-openai-spring-boot-starter`
- 文档示例能搜到，你一复制就报错

### 根因
Spring AI **1.x** 命名是 `spring-ai-*-spring-boot-starter`；**2.0** 改为 `spring-ai-starter-model-*` 形态。

### 修复对照表

| 错误（1.x） | 正确（2.0 主线） |
|---|---|
| `spring-ai-openai-spring-boot-starter` | `spring-ai-starter-model-deepseek`（本讲义） |
| `spring-ai-openai-spring-boot-starter` | 若接 GPT：`spring-ai-starter-model-openai`（扩展篇） |
| 手写 `spring-ai-core` 版本 | 交给 BOM |

### 预防
看到文章发布日期在 2025 年前、或出现 `internalToolExecutionEnabled`，直接关掉。

## 3. 写成 spring.ai.openai 却用 DeepSeek starter

### 现象
- 启动报 `Could not resolve placeholder` 或 Key 明明设了仍 401
- 日志里请求打到错误端点

### 根因
pom 引的是 `spring-ai-starter-model-deepseek`，`application.yml` 却抄了 OpenAI 前缀：

```yaml
# 错误
spring.ai.openai.api-key: ${DEEPSEEK_API_KEY}
```

### 修复
```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      chat:
        model: deepseek-v4-flash
```

环境变量名仍可用 `DEEPSEEK_API_KEY`（这是你自定义的占位符名，与 yaml 前缀无关）。

### 预防
**starter 名、yaml 前缀、控制台申请的 Key 三方一致**。贴一张对照表在显示器边。

## 4. 无 API Key

### 现象
- `Could not resolve placeholder 'DEEPSEEK_API_KEY'`
- 或启动成功，一调接口 401 / `Invalid API Key`
- IDEA 能跑，终端 `mvn spring-boot:run` 不能跑

### 根因
- 环境变量未设置或拼写错误
- IDE Run Configuration 里配了 Key，系统 shell 没有
- Key 含空格、换行、引号被吃

### 修复
```bash
# Linux / macOS
export DEEPSEEK_API_KEY="sk-xxxxxxxx"
echo $DEEPSEEK_API_KEY

# Windows PowerShell
[System.Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-xxxxxxxx", "User")
```

IDEA：`Run` → `Edit Configurations` → Environment variables 补一行。

### 预防
- **反例必测**：删掉 Key 再启动，确认错误信息可读
- `git grep -i api-key` 确保仓库无真实密钥

## 5. call() 后没 content()

### 现象
- 断点打在 `call()` 以为会发 HTTP，实际没有请求
- 返回类型不对，拿到 `CallResponseSpec` 却当 String 用
- 单元测试「mock 了 call 却没触发模型」

### 根因
2.0 设计：`call()` 返回**惰性**的 `CallResponseSpec`；真正消费响应才打模型。

### 修复
```java
// 同步文本
String text = chatClient.prompt().user(msg).call().content();

// 结构化
MyDto dto = chatClient.prompt().user(msg).call().entity(MyDto.class);

// 流式不用 call().content()，用 stream()
Flux<String> flux = chatClient.prompt().user(msg).stream().content();
```

### 预防
团队 Code Review 规定：禁止 `call()` 单独一行不跟消费端。

## 6. 模板 {} 与 JSON 冲突

### 现象
- Prompt 模板里想塞 JSON 示例，`{` `}` 被 StringTemplate 当成占位符
- 运行时 `IllegalArgumentException: Not enough template variables`
- JSON 花括号被吃掉一半

### 根因
`ChatClient` 的 `PromptTemplate` / `.user(String, Map)` 用 `{}` 做变量替换，与 JSON 语法冲突。

### 修复
**任选其一：**
1. JSON 示例放 **system** 或资源文件，不用模板变量
2. 用户消息用 `.user(完整字符串)`，不用 `{}` 模板
3. 需要动态插值时，只对**短变量**用模板，JSON 用 `"""` 文本块原样拼接：

```java
String jsonExample = """
    {"conclusion":"...", "metrics":[]}
    """;
chatClient.prompt()
    .system("输出必须符合以下 JSON 结构：\n" + jsonExample)
    .user(question)
    .call().content();
```

4. 结构化输出优先 `.entity(Record.class)`，少在 Prompt 里手写 JSON 样例

### 预防
part-02 验收口试题；团队默认「JSON 契约用 record + validateSchema，不用模板嵌 JSON」。

## 7. 不传 CONVERSATION_ID

### 现象
- 用户 A 刚说的仓，用户 B 追问能对上
- 多轮对话永远像「第一次见面」
- 记忆库只有一条记录被反复覆盖

### 根因
挂了 `MessageChatMemoryAdvisor` 但每次请求没传 `ChatMemory.CONVERSATION_ID`（或 2.0 等价参数键）。

### 修复
```java
import static org.springframework.ai.chat.memory.ChatMemory.CONVERSATION_ID;

chatClient.prompt()
    .advisors(a -> a.param(CONVERSATION_ID, sessionId)) // sessionId = userId + ":" + clientSession
    .user(message)
    .call().content();
```

`sessionId` 由 API 层生成：登录用户 ID + 前端会话 UUID，**不要**全局单例。

### 预防
集成测试用两个 `CONVERSATION_ID` 各问一轮，断言互不影响。

## 8. 用 QuestionAnswerAdvisor 当 2.0 唯一 RAG

### 现象
- 照抄旧文，类找不到或行为与文档不符
- 空检索时模型仍胡编制度
- 无法加元数据过滤、查询改写

### 根因
`QuestionAnswerAdvisor` 是 1.x 一体化方案；2.0 主推 **模块化 RAG**（`spring-ai-rag`）。

### 修复
主路径：
```java
RetrievalAugmentationAdvisor.builder()
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .topK(4)
        .similarityThreshold(0.50)
        .build())
    .build()
```

空结果：**不要**默认 `allowEmptyContext(true)`。

### 预防
代码库 `grep QuestionAnswerAdvisor` 应为 0（或仅迁移说明注释）。

## 9. toolNames()

### 现象
- 编译错误：找不到 `toolNames` 方法
- 以为注册了 `@Bean Function` 模型就能自动调

### 根因
2.0 **删除** `ChatClient.toolNames()` 与 `SpringBeanToolCallbackResolver`。

### 修复
显式传入：
```java
chatClient.prompt()
    .user(msg)
    .tools(inventoryTools)           // @Tool 对象
    // 或 .tools(callback1, callback2)
    .call().content();
```

或构建时 `.defaultTools(...)`。

### 预防
旧博客出现 `.toolNames("weather")` 直接划掉。

## 10. DeepSeek 当 embedding

### 现象
- 配了 `spring.ai.deepseek` 却没有任何 `EmbeddingModel` Bean
- RAG 入库报 `No qualifying bean of type EmbeddingModel`
- 误以为「一个 Key 全能」

### 根因
DeepSeek 对话 API **不提供**官方 embedding 端点（本讲义主线设定）。

### 修复
额外引入：
```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-transformers</artifactId>
</dependency>
```
或接兼容 OpenAI 的 embedding 服务（扩展篇）。

对话仍用 `spring-ai-starter-model-deepseek`。

### 预防
架构图永远画两个模型框：**Chat** 与 **Embedding**。

## 11. 两个 ChatModel 不 @Primary

### 现象
- 启动失败：`No qualifying bean of type ChatModel` 或 `expected single matching bean but found 2`
- `ChatClient.Builder` 不知道绑哪个模型

### 根因
定义了 `flashChatModel` 和 `proChatModel` 两个 `ChatModel` Bean，未指定默认。

### 修复
**方案 A：** 一个 `@Primary` 作默认，另一个专用 Builder：
```java
@Bean
@Primary
ChatModel primaryChatModel(DeepSeekChatModel model) { return model; }

@Bean
ChatClient proChatClient(ChatModel proModel) {
    return ChatClient.builder(proModel).defaultSystem("...").build();
}
```

**方案 B：** 不用 `@Primary`，全部显式 `ChatClient.builder(specificModel)`。

### 预防
多模型从 day1 就画 Bean 图：谁默认、谁专用、Controller 注入谁。

## 12. Jackson 3 差异直觉

### 现象
- `import com.fasterxml.jackson` 编译失败
- 旧库传递依赖 Jackson 2，与 Boot 4 冲突
- 自定义 `ObjectMapper` Bean 覆盖了 Boot 自动配置

### 根因
Spring Boot 4 基线是 **Jackson 3**（包名、部分 API 与 2.x 不同）。

### 修复直觉
1. 新业务 DTO 用 **record**，少写 getter 注解
2. 不要复制 2024 年前的 `@JsonProperty` 示例，先让自动配置工作
3. `mvn dependency:tree | grep jackson` 检查是否混进 `com.fasterxml.jackson.core` 与 `tools.jackson` 两套
4. 工具 `resultConverter` 如需自定义序列化，跟 Spring Boot 4 文档走，别粘旧 Gist

### 预防
pom 里排除老旧 starter 传递的 Jackson 2；升级第三方库到支持 Boot 4 的版本。

## 13. 记忆放循环内但 JDBC 仓库不支持 tool 消息

### 现象
- 开启「循环内记忆」后，第二轮开始模型行为异常
- JDBC `ChatMemoryRepository` 丢消息或插入失败
- 记忆膨胀极快，Token 暴增

### 根因
工具循环每一轮都会产生 Assistant（含 tool call）与 Tool 消息。默认 **JDBC 记忆实现不完整支持 tool 消息类型**；循环内记忆还会记住大量中间态。

### 修复
**默认策略（讲义推荐）：**
- `MessageChatMemoryAdvisor` order **200**
- `ToolCallingAdvisor` order **300**
- 记忆在**工具循环外**：只持久化最终面向用户的轮次（框架默认行为）

确需循环内记忆：换支持完整 Message 类型的仓库（如内存、Redis 实验实现），并自行截断 tool 消息。

### 预防
读 part-04 `05-记忆放循环内还是循环外.md`；答辩能画出 order 200 vs 300。

## 14. Token 爆炸：system + 历史 + 工具 schema + 检索

### 现象
- 账单突然变贵
- 模型报 context length exceeded
- 回答变慢，中间段落「看不见」

### 根因
单次请求 = system（可能很长）
+ 会话历史（未截断）
+ 每个 `@Tool` 的 JSON Schema（工具多时巨大）
+ RAG `topK` 片段
+ 用户输入

### 修复
| 杠杆 | 做法 |
|---|---|
| system | 控制在 2k Token 内；细则进 RAG |
| 历史 | `MessageWindowChatMemory` 限制轮数；旧轮摘要 |
| 工具 | 合并工具；Tool Search；description 精炼 |
| RAG | `topK(4)` 起步；`similarityThreshold`；Document 压缩 |
| 模型 | 简单问 flash；别对闲聊开 thinking |

### 预防
日志打 `usage`；part-07 做单用户日限额；改 Prompt 先跑评测集再看费用。

## 15. Maven 镜像挡仓库

### 现象
- `Could not find artifact org.springframework.ai:spring-ai-bom:2.0.0`
- 依赖一直 `Downloading from aliyun` 然后失败
- 公司私服只有 Boot 3 时代缓存

### 根因
国内镜像或公司 Nexus **未同步** Spring AI 2.0 / Spring Boot 4.1 构件；或 `mirrorOf=*` 把 `spring-milestones` 也劫持了。

### 修复
1. 临时注释镜像，直连 central（网络允许时）
2. `settings.xml` 里对 `spring` 仓库用专用 `<profile>`，不用 `mirrorOf=*`
3. 请运维同步：`org.springframework.boot:4.1.x`、`org.springframework.ai:2.0.0`
4. 学习期**不要**用 SNAPSHOT

### 预防
新项目第一天用 `mvn -U dependency:get -Dartifact=org.springframework.ai:spring-ai-bom:2.0.0` 验证解析。

## 16. 版本漂移怎么办：学习期钉死 2.0.0 / Boot 4.1

### 现象
- 讲义代码与最新 Release 对不上
- 升级一个小版本，Advisor API 变了
- 同学之间「我这边能跑你那边不能」

### 根因
Spring AI 2.x 仍在快速演进；Boot 4.1 补丁版也可能带来传递依赖变化。

### 修复（学习期策略）
```
Java            21
Spring Boot     4.1.0（或同讲义 4.1.x 小版本，全班统一）
Spring AI BOM   2.0.0（禁止 SNAPSHOT）
```

**允许升级的前提：**
1. 全班/全组一起升
2. 跑通 part-02～part-05 验收清单
3. 查 Spring AI 2.0 Release Notes 里 Advisor、配置前缀变更
4. 更新 `appendix/pom完整模板.md` 本地副本

### 预防
`pom.xml` 用 property 锁版本；Dependabot 在学习期**关闭**。

## 17. 其他高频短坑（速查）

| 现象 | 一句话修复 |
|---|---|
| 流式 404 / 不吐字 | 加 `spring-boot-starter-webflux` |
| 工具执行两次 | 链上挂了多个 ToolAdvisor，只保留一个 |
| 模型返回 tool call 但不执行 | `spring.ai.chat.client.tool-calling.enabled=false` 被关了 |
| MCP 加了 starter 没工具 | 必须 `.tools(mcpToolCallbackProvider)` |
| RAG 答非所问 | 检查 embedding 是否与入库时同一模型；元数据过滤是否过严 |
| 结构化输出字段 null | 模型没填满；开 `validateSchema()` 让它重试或降级 |
| Git 泄露 Key | 轮换 Key；用 `git filter-repo`；pre-commit 扫密钥 |
| 演示时网络抖动 | 准备离线截图 + 本地录屏；工具超时有降级文案 |

## 18. 排障顺序（老师建议）

1. **版本**：Boot / BOM / JDK 是否与讲义一致  
2. **Key**：环境变量与 yaml 前缀  
3. **Bean**：`dependency:tree`、启动日志里 ChatModel 实现类  
4. **消费端**：有没有 `.content()` / `.entity()`  
5. **链顺序**：Advisor order、CONVERSATION_ID、工具是否显式 `.tools()`  
6. **Token**：砍 system / 历史 / 工具数 / RAG topK  
7. **仍不行**：最小复现 pom + 一个接口，对照 `appendix/pom完整模板.md` diff
