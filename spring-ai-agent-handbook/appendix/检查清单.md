## Part 04 · 工具调用与 Agent 循环

> 目标：L3 Agent 开发者 — 第一个真 Agent，三个必测问题。

### 工具定义

- [ ] 至少 3 个 `@Tool`：`getSku`、`queryInventory`、`compareWarehouses`（或等价）
- [ ] **故意不提供** `updateInventory` 等写工具
- [ ] `@ToolParam` 中文描述清晰；description 写明「只读、不用于写操作」
- [ ] 工具内校验 `warehouseId` 白名单 / 用户权限
- [ ] 异常返回可读中文，**不**把堆栈甩给模型

### 工具循环

- [ ] 理解 `ToolCallingAdvisor` 在 Advisor 链（非 ChatModel 内部）
- [ ] `.tools(inventoryTools)` 显式传入（无 `toolNames()`）
- [ ] 能白板画出：Definition → tool calls → 执行 → 回填 → 再生成
- [ ] 链上仅有**一个** ToolAdvisor
- [ ] 配置知晓：`spring.ai.chat.client.tool-calling.enabled` 含义

### 必测三问

- [ ] Q1：「A 仓 SKU-1001 现有多少可用库存？」— 调工具，数字来自 Java
- [ ] Q2：「对比 A 仓和 B 仓 SKU-1001，哪个更该补货？」— 多工具或批量
- [ ] Q3：「帮我把 A 仓 SKU-1001 库存改成 0。」— **礼貌拒绝**，日志无写操作
- [ ] 三次调用的工具轨迹已记录（日志或笔记）

### 护栏

- [ ] 最大工具迭代轮次已限制（防死循环）
- [ ] 工具 sleep 超阈值时有降级/超时处理
- [ ] 无关问题（如彩票号）不编造业务数字
- [ ] 审计日志含：工具名、参数摘要、耗时

### 记忆与进阶

- [ ] 能解释 `MessageChatMemoryAdvisor`(≈200) 与 `ToolCallingAdvisor`(≈300) 顺序
- [ ] 默认记忆在**循环外**（未把 JDBC 记忆硬塞循环内）
- [ ] 【建议】知晓 Tool Search 与 MCP 概念（可不实现）

### 口试

- [ ] 模型有没有直接连数据库？
- [ ] 为什么 2.0 把循环从 ChatModel 提到 Advisor？
- [ ] `internalToolExecutionEnabled` 为什么不能再写？

## Part 06 · 企业数据接入

> 目标：L4 数据部分 — 只读、白名单、新鲜度、指标字典。

### 数据源与模式

- [ ] 演示 Postgres（Docker）或等价只读库已就绪
- [ ] 应用数据源账号 **无** INSERT/UPDATE/DELETE 权限
- [ ] 接入模式选型能说清：API / 只读视图 / **宽表同步** / 笼中 Text-to-SQL
- [ ] 主路径为宽表 + 固定 Tool，非模型现场拼 SQL 打核心库

### 工具与 SQL

- [ ] 实现 ≥3 只读工具：库存可用量、超期采购、设备停机（或公司等价）
- [ ] 每条 Tool 背后固定 SQL 或固定仓储方法
- [ ] **禁止** `Statement` 拼接用户原始字符串
- [ ] 参数白名单：`warehouseId` 改 SQL 片段时被拒绝
- [ ] 强制过滤：`tenantId` / `warehouseId` / `userId`

### 指标与回答

- [ ] 指标字典：中文名 → 官方 SQL / 方法 / 口径说明
- [ ] 每个数字回答含**数据截止时间/新鲜度**
- [ ] 「库存」等术语与指标字典、RAG 口径一致
- [ ] ERP / WMS / EMS 各暴露 2～3 个决策问题（非 200 张表）

### 权限反例

- [ ] 无权限仓/租户：拒绝或空结果，**不编造**
- [ ] 越权 `warehouseId` 测试通过
