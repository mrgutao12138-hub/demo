# 00 · 本章导读：RAG 与企业知识

> 同学们好。从这一章开始，你的 Agent 不再只靠「脑子里的常识」说话，而是能**查你们自己的制度、SOP、口径说明**。  
> 这是决策系统从「聊天玩具」变成「管理层敢用」的分水岭。

---

## 1. 本章要解决什么问题

前面几周，你已经能让 DeepSeek 对话、调 Tool 查库存数字。但管理层还会问另一类话：

- 「可用量到底按哪个口径算？」
- 「超期采购的定义是什么？算不算在途？」
- 「华东仓和华南仓的冻结规则一样吗？」

这些话**不能**让模型凭记忆编。数字走 Tool，**定义和口径走 RAG**。

本章教你用 **Spring AI 2.0 模块化 RAG** 把企业文档变成可检索知识，并与 Tool 正确分工。

## 3. 技术主线（请背下来）

本章 **唯一** RAG 主路径是下面这条链，不要偷换成网上旧的 `QuestionAnswerAdvisor` 教程：

```
Maven 依赖
  spring-ai-rag
  spring-ai-vector-store（+ pgvector starter 生产）
  spring-ai-starter-model-transformers（学习期本地 embedding）
  spring-ai-starter-model-deepseek（对话，不是向量）

入库
  Markdown/制度 → 按标题切分 → Document + 元数据
  → EmbeddingModel.embed() → VectorStore.add()

问答
  ChatClient
    .advisors(RetrievalAugmentationAdvisor.builder()
        .documentRetriever(VectorStoreDocumentRetriever.builder()
            .vectorStore(vectorStore)
            .similarityThreshold(0.50)
            .topK(4)
            .build())
        .build())
    .user(问题)
```

运行时按组织、仓库过滤：

```java
.advisors(a -> a.param(
    VectorStoreDocumentRetriever.FILTER_EXPRESSION,
    "type == 'policy' && org == 'east-china'"))
```

**空上下文默认不许瞎答**；只有显式 `ContextualQueryAugmenter.builder().allowEmptyContext(true)` 才允许模型在无检索结果时自由发挥——决策系统里**默认不要开**。

## 5. 三个【红线】先念一遍

1. **DeepSeek 对话 API ≠ Embedding API。** 用 DeepSeek 生成回答，用**另一套** `EmbeddingModel` 做向量。混用会整章跑不通。
2. **检索不到时，默认让模型拒答。** 制度场景宁可说「库里没有」，也不要 `allowEmptyContext(true)` 默认打开。
3. **文档里的「忽略以上规则」不能覆盖系统红线。** 见 `07` 与 `04` 的系统提示示例。
