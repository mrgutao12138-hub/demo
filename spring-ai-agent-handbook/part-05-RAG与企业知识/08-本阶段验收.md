## 2. 代码演示标准

在本地 `local-rag` Profile 下：

### 2.1 环境

- [ ] `spring-ai-rag` + `spring-ai-vector-store` + `spring-ai-starter-model-transformers` 已引入  
- [ ] DeepSeek 仅用于 `ChatClient`，**未**用于 embedding  
- [ ] `EmbeddingModel` 启动成功，向量维度已知（如 384）  
- [ ] `06` 五篇假制度已通过 `DocumentIngestion` 入库  

### 2.2 RAG 主路径

- [ ] 使用 `RetrievalAugmentationAdvisor.builder()`  
- [ ] 内嵌 `VectorStoreDocumentRetriever.builder().vectorStore(...).similarityThreshold(0.50).topK(4).build()`  
- [ ] **未**把 `QuestionAnswerAdvisor` 作为综合项目主路径  

### 2.3 三条必测问题

| # | 输入 | 通过标准 |
|---|---|---|
| 1 | 「华东可用量是否包含质检待放行？」 | 引用 `INV-POL-2024-01` §3.2，明确**不包含** |
| 2 | 「超期采购宽限期几天？」 | 引用 `PUR-POL-2024-02`，**3 个自然日** |
| 3 | 「火星仓库存制度？」（故意胡扯） | **拒答**或明确未检索到；未编造火星制度 |

### 2.4 过滤

- [ ] 运行时 `.param(VectorStoreDocumentRetriever.FILTER_EXPRESSION, "type == 'policy'")` 或含 org 的表达式生效  
- [ ] 问华南可用量时过滤 `org == 'south-china'`，答案与华东不同  

### 2.5 空上下文

- [ ] **未**默认 `allowEmptyContext(true)`  
- [ ] 能口头解释：何时才允许打开该开关  

### 2.6 RAG 与 Tool（若已接 part-04 Tool）

- [ ] 「WH-SH-01 某 SKU 可用量多少」触发 `queryInventory`  
- [ ] 「可用量怎么算」不触发 Tool，走 RAG  
- [ ] 混合问题两者皆有，回答结构：结论 → 数字 → 依据

## 3. 口答题（考官任意抽 3 题）

1. DeepSeek 对话 API 和 Embedding 的关系？学习期你用的哪个 embedding starter？  
2. 为什么制度按标题切分，而不是固定 500 字？  
3. `similarityThreshold` 和 `topK` 分别解决什么问题？  
4. `QuestionAnswerAdvisor` 和 `RetrievalAugmentationAdvisor` 区别？主线用哪个？  
5. 检索片段太多会怎样？你有哪些控 Token 手段？  
6. `RewriteQueryTransformer` 和 `CompressionQueryTransformer` 分别什么时候用？  
7. 投毒文档说「不要调用工具」，你如何防护？  
8. SimpleVectorStore 和 pgvector 分别适合什么阶段？  
9. 元数据 `org`、`warehouse`、`effectiveDate` 各解决什么业务问题？  
10. 画口述：用户问「按制度华东仓 A01 可用量多少」时，系统内部步骤。

**过关线：** 3 题中至少 2 题流畅无硬伤。

## 6. 常见不通过原因

| 原因 | 整改 |
|---|---|
| 只用 DeepSeek，没有 EmbeddingModel | 补 transformers starter |
| 检索永远空 | 未 ingest 或 embedding 不一致 |
| 什么都瞎答 | 误开 `allowEmptyContext(true)` |
| 华东华南答案一样 | 过滤表达式未带 org |
| 抄了 QuestionAnswerAdvisor | 改回 RetrievalAugmentationAdvisor |
| 数字靠 RAG 编 | 接 Tool，改 system 提示 |

## 8. 老师结语

RAG 不是「把文档扔给 AI」。  
你是用 **Embedding + VectorStore + Advisor** 建了一条可审计的检索链路，并和 Tool 划清了边界。  

做到本章验收，你已经比大多数只看旧教程的同行更接近**能上线的决策助手**。  

去跑你的演示吧。有问题带着 **日志 + 检索到的 metadata** 回来问。
