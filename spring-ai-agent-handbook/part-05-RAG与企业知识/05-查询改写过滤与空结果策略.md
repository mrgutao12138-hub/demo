# 05 · 查询改写、过滤与空结果策略

> 检索质量决定 RAG 上限。这一章讲「问法不对、过滤不对、上下文塞爆」三类常见病。

---

## 1. 模块化 RAG 流水线（复习）

```
Query 进入
  → QueryTransformer（改写 / 压缩 / 翻译）
  → QueryExpander（多查询扩展，可选）
  → DocumentRetriever（VectorStore + 过滤 + topK + 阈值）
  → DocumentJoiner（多路合并，可选）
  → DocumentPostProcessor（压缩 / 去重 / 重排，可选）
  → QueryAugmenter（ContextualQueryAugmenter 拼上下文）
  → ChatModel 生成
```

`RetrievalAugmentationAdvisor.builder()` 上可挂这些模块。

---

## 2. 空上下文策略【红线】

### 2.1 默认行为

`RetrievalAugmentationAdvisor` 默认使用 `ContextualQueryAugmenter`，且 **`allowEmptyContext` 默认为 false**：

- 检索结果为空，或全部被 `similarityThreshold` 滤掉  
- → 增强器指示模型 **不要回答用户问题**（典型话术：知识库无相关内容）

这是决策系统的**正确默认**：制度场景禁止无依据发挥。

### 2.2 何时才 `allowEmptyContext(true)`

```java
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.generation.augmentation.ContextualQueryAugmenter;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;

Advisor advisor = RetrievalAugmentationAdvisor.builder()
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .similarityThreshold(0.50)
        .topK(4)
        .build())
    .queryAugmenter(ContextualQueryAugmenter.builder()
        .allowEmptyContext(true)   // 显式允许「无检索仍回答」
        .build())
    .build();
```

仅建议在：

- 纯 FAQ 闲聊兜底页  
- 明确标注「非制度咨询模式」的助手  

**管理层决策入口不要默认开启。**

## 3. 运行时过滤表达式

### 3.1 标准写法

```java
chatClient.prompt()
    .advisors(retrievalAugmentationAdvisor)
    .advisors(a -> a.param(
        VectorStoreDocumentRetriever.FILTER_EXPRESSION,
        "type == 'policy'"))
    .user(question)
    .call()
    .content();
```

### 3.2 组合条件

```java
.advisors(a -> a.param(
    VectorStoreDocumentRetriever.FILTER_EXPRESSION,
    "type == 'policy' && org == 'east-china' && effectiveDate <= '2024-12-31'"))
```

字段名必须与 `DocumentIngestion` 写入的 metadata 一致。

### 3.3 与登录用户绑定

```java
String org = TenantContext.currentOrg();
String wh = TenantContext.currentWarehouse();
String expr = String.format(
    "org == '%s' && (warehouse == '%s' || warehouse == 'ALL')", org, wh);
```

【红线】不要把用户输入直接拼进过滤表达式而不校验；`org` 应从会话/Token 解析，防注入式越权检索。

## 4. 查询改写（Pre-Retrieval）

改写组件使用 **ChatModel（DeepSeek）**，与 Embedding **仍是两条线**。

### 4.1 RewriteQueryTransformer

用户啰嗦、歧义时，改写成利于检索的短句。

```java
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.rag.preretrieval.query.transformation.RewriteQueryTransformer;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;

Advisor advisor = RetrievalAugmentationAdvisor.builder()
    .queryTransformers(RewriteQueryTransformer.builder()
        .chatClientBuilder(chatClientBuilder.mutate())
        .build())
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .similarityThreshold(0.50)
        .topK(4)
        .build())
    .build();
```

适用：「那个啥可用量是不是要减掉质检的啊」→「库存可用量是否扣除质检待放行数量」。

**温度建议 0～0.2**，避免改写时「创造性」发挥。

### 4.2 CompressionQueryTransformer

多轮对话后，把历史 + 追问压成**独立查询**。

```java
import org.springframework.ai.rag.preretrieval.query.transformation.CompressionQueryTransformer;

.queryTransformers(CompressionQueryTransformer.builder()
    .chatClientBuilder(chatClientBuilder.mutate())
    .build())
```

适用：

- 用户：「华东仓可用量口径？」  
- 助手：「按 INV-POL…」  
- 用户：「那超期采购呢？」 ← 需要压缩成带上下文的单句  

与 `MessageChatMemoryAdvisor` 配合时，注意 Advisor 顺序。

### 4.3 TranslationQueryTransformer

embedding 模型偏英文、用户中文时，可翻成 embedding 友好语言（或统一中文）。

```java
import org.springframework.ai.rag.preretrieval.query.transformation.TranslationQueryTransformer;

.queryTransformers(TranslationQueryTransformer.builder()
    .chatClientBuilder(chatClientBuilder.mutate())
    .targetLanguage("chinese")
    .build())
```

若你已用多语言 embedding（如 `paraphrase-multilingual-MiniLM-L12-v2`），**可先不加**，观察召回再决定。

### 4.4 链式组合

```java
.queryTransformers(
    CompressionQueryTransformer.builder().chatClientBuilder(chatClientBuilder.mutate()).build(),
    RewriteQueryTransformer.builder().chatClientBuilder(chatClientBuilder.mutate()).build())
```

顺序：先压缩历史，再改写措辞。

## 5. MultiQueryExpander（查询扩展）

一条问题扩成多条语义相近查询，合并检索结果，提高召回。

```java
import org.springframework.ai.rag.preretrieval.query.expansion.MultiQueryExpander;

Advisor advisor = RetrievalAugmentationAdvisor.builder()
    .queryExpander(MultiQueryExpander.builder()
        .chatClientBuilder(chatClientBuilder.mutate())
        .numberOfQueries(3)
        .includeOriginal(true)
        .build())
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .similarityThreshold(0.50)
        .topK(4)   // 注意：多查询后总片段可能暴涨，见 Token 预算
        .build())
    .build();
```

代价：更多次向量检索 + 更多 Chat 调用 + **上下文更长**。生产上先 A/B，别默认全开。

## 6. DocumentPostProcessor（Post-Retrieval）

检索后、进模型前，对 `List<Document>` 再处理：

- 按相似度重排  
- 去掉重复 docId  
- **压缩**每段文字以省 Token  

Spring AI 2.0 提供 `DocumentPostProcessor` 接口，可自定义：

```java
package com.company.decision.rag;

import org.springframework.ai.document.Document;
import org.springframework.ai.rag.postretrieval.document.DocumentPostProcessor;
import org.springframework.ai.rag.Query;
import org.springframework.stereotype.Component;

import java.util.*;
import java.util.stream.Collectors;

/**
 * 去重 + 截断单段长度，防止上下文塞爆。
 */
@Component
public class TokenBudgetPostProcessor implements DocumentPostProcessor {

    private static final int MAX_CHARS_PER_DOC = 600;
    private static final int MAX_TOTAL_DOCS = 4;

    @Override
    public List<Document> process(Query query, List<Document> documents) {
        Map<String, Document> byDocSection = new LinkedHashMap<>();
        for (Document doc : documents) {
            String key = doc.getMetadata().get("docId") + "#" + doc.getMetadata().get("section");
            byDocSection.putIfAbsent(key, truncate(doc));
        }
        return byDocSection.values().stream()
            .limit(MAX_TOTAL_DOCS)
            .collect(Collectors.toList());
    }

    private Document truncate(Document doc) {
        String text = doc.getText();
        if (text.length() <= MAX_CHARS_PER_DOC) {
            return doc;
        }
        String shorter = text.substring(0, MAX_CHARS_PER_DOC) + "…（已截断）";
        return Document.builder()
            .text(shorter)
            .metadata(doc.getMetadata())
            .build();
    }
}
```

挂到 Advisor：

```java
RetrievalAugmentationAdvisor.builder()
    .documentRetriever(/* ... */)
    .documentPostProcessors(tokenBudgetPostProcessor)
    .build();
```

（若你本地 API 方法名为 `documentPostProcessor` 单数，以 IDE 自动补全为准，2.0 支持注册多个后处理器。）

## 7. Token 预算：检索片段不要把上下文塞爆

### 7.1 估算

- 中文粗略：**1 汉字 ≈ 1～2 token**（视分词而定）。  
- `topK(4)` × 每段 800 字 ≈ 3200 字 ≈ 数千 token，**还没算** system、历史、工具 schema。  
- DeepSeek 上下文虽大，但**贵且慢**；决策回答通常不需要整章制度。

### 7.2 控制手段（按优先级）

1. **切分阶段**：单块 300～800 字（`02`）  
2. **`topK`**：制度问答 3～5 足够  
3. **`similarityThreshold`**：滤掉弱相关  
4. **`DocumentPostProcessor` 截断**  
5. 少开 `MultiQueryExpander`，或降低 `numberOfQueries`  

### 7.3 配置示例（偏保守）

```java
VectorStoreDocumentRetriever.builder()
    .vectorStore(vectorStore)
    .similarityThreshold(0.55)
    .topK(3)
    .build()
```

配合 `TokenBudgetPostProcessor`。

## 8. ContextualQueryAugmenter 定制（可选）

可自定义如何把片段拼进用户问题：

```java
ContextualQueryAugmenter.builder()
    .allowEmptyContext(false)
    // .promptTemplate(customTemplate)  // 需含 query 与上下文占位符
    .build();
```

默认模板已要求「仅依据上下文回答」。制度场景保持默认即可。

## 9. 完整进阶 Advisor 示例

```java
@Bean
public Advisor advancedRagAdvisor(
        VectorStore vectorStore,
        ChatClient.Builder chatClientBuilder,
        TokenBudgetPostProcessor postProcessor) {

    return RetrievalAugmentationAdvisor.builder()
        .queryTransformers(
            CompressionQueryTransformer.builder()
                .chatClientBuilder(chatClientBuilder.mutate())
                .build(),
            RewriteQueryTransformer.builder()
                .chatClientBuilder(chatClientBuilder.mutate())
                .build())
        .documentRetriever(VectorStoreDocumentRetriever.builder()
            .vectorStore(vectorStore)
            .similarityThreshold(0.50)
            .topK(4)
            .build())
        .documentPostProcessors(postProcessor)
        .queryAugmenter(ContextualQueryAugmenter.builder()
            .allowEmptyContext(false)
            .build())
        .build();
}
```

## 10. 小结

| 机制 | 作用 |
|---|---|
| `RewriteQueryTransformer` | 啰嗦问法 → 检索友好短句 |
| `CompressionQueryTransformer` | 多轮追问 → 独立查询 |
| `TranslationQueryTransformer` | 语言对齐 embedding |
| `MultiQueryExpander` | 提高召回，注意 Token |
| `FILTER_EXPRESSION` | org / warehouse / type 隔离 |
| `allowEmptyContext(false)` | 默认，无检索拒答 |
| `DocumentPostProcessor` | 去重、截断、控 Token |

## 11. 【必做】实验

1. 关闭所有改写，问口语化问题，记录命中率。  
2. 加上 `RewriteQueryTransformer`，对比同一问题。  
3. 故意问不存在条款，确认**未**设置 `allowEmptyContext(true)` 时拒答。  
4. 把 `topK` 调到 20，观察响应时间与回答质量——理解为何要预算。
