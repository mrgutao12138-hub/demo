# 01 · 为什么决策系统必须有 RAG

> 有同学问：「我都接 ERP 了，还要 RAG 干什么？」  
> 好问题。这一章把「数字」和「口径」分开，你就不会再混。

---

## 1. 两类问题，两套答案来源

管理层的问题可以粗分成两类：

| 类型 | 例子 | 正确答案从哪来 |
|---|---|---|
| **事实数字** | 「华东仓 A01 可用量多少？」「有多少张超期 PO？」 | 数据库 / Tool / 宽表 SQL |
| **定义与口径** | 「可用量扣不扣预留？」「超期采购怎么定义？」 | 制度、SOP、财务口径说明 |

大模型**两者都容易编**。Tool 能解决第一类；第二类若没有 RAG，模型只能「像那么回事」地胡说。

【红线】在汇报场景里，**口径编错比数字编错更隐蔽**——数字还有人会对账，口径错了会连累一整张报表。

---

## 2. 没有 RAG 时会发生什么

假设用户问：「按公司制度，库存可用量是否包含质检待放行数量？」

### 2.1 纯对话

模型可能答：「一般包含」或「一般不包含」——听起来合理，**但不是你们公司的制度**。

### 2.2 只有 Tool、没有 RAG

你若只做了 `queryInventory`，返回的是**按某一 SQL 算出来的数**，但用户问的是**定义**，不是数。  
Tool 答不了「为什么这样算」；模型若强行解释，仍在编。

### 2.3 正确形态

1. RAG 检索《库存管理口径说明》相关条款 → 得到「可用量 = 账面 − 预留 − 冻结 − …」  
2. 若用户还要具体数字 → 再调 `queryInventory` Tool  
3. 回答结构：**结论 → 口径依据（文档片段）→ 数字（Tool）→ 风险**

这就是「可信决策」的最小闭环。

---

## 3. RAG 在 Spring AI 2.0 里是什么

不要把它想成「把 PDF 塞进 prompt」。

在 Spring AI 2.0 里，RAG 是一条**可组合的流水线**（Modular RAG）：

```
用户问题
  →（可选）查询改写 / 扩展 / 翻译
  → 向量化查询
  → VectorStore 相似度检索 + 元数据过滤
  →（可选）DocumentPostProcessor 压缩 / 去重
  → ContextualQueryAugmenter 把片段拼进上下文
  → ChatModel 生成回答
```

对外，你用 **`RetrievalAugmentationAdvisor`** 把这条链挂到 `ChatClient` 上。  
模块在 `spring-ai-rag`；向量存储在 `spring-ai-vector-store`。

---

## 4. 为什么不用「把制度全文放进 system prompt」

小册子也许行。真实企业：

- 制度 + SOP + 口径 + 变更记录，动辄几十万字。  
- 全塞进 prompt：**爆 Token、贵、慢、还塞不下**。  
- 模型对长文中间段落「看不见」（lost in the middle）。

RAG 的做法是：**每次只检索与问题相关的几段**（本章默认 `topK(4)`），并控制 Token 预算（见 `05`）。

---

## 5. 企业知识库通常放什么、不放什么

### 5.1 适合进 VectorStore 的

- 库存、采购、财务**口径说明**（定义型文字）  
- 审批 SOP（步骤、角色、例外）  
- 报表指标字典（「周转天数」官方解释）  
- 已脱敏的 FAQ、培训讲义  

### 5.2 不适合只靠 RAG 的

- **实时库存、订单状态** → Tool + 只读库  
- **个人薪资、未脱敏客户名单** → 别进向量库；即使进了也要强权限过滤  
- **频繁秒级变化的数据** → 向量索引跟不上，用 Tool  

### 5.3 元数据为什么重要

同一句话「可用量」，华东仓和华南仓制度可能不同。  
检索时必须能过滤：`org`、`warehouse`、`effectiveDate`。  
这在 `02`、`05` 会写透。

---

## 6. 和 Memory 的区别

| | 会话 Memory | RAG 知识库 |
|---|---|---|
| 存什么 | 本轮对话上下文 | 企业审定文档 |
| 谁写入 | 用户聊天自动积累 | 管理员发布/同步任务 |
| 可信度 | 低（用户可能说错） | 高（假定文档已审定） |
| 典型用途 | 「刚才那个仓是哪一个？」 | 「超期采购定义是什么？」 |

【易混】不要把聊天记录当制度库。口径会漂，审计也过不了。

---

## 7. 本章不做什么

- 不教微调 embedding 模型（第一版不需要）  
- 不教用 DeepSeek 做向量（**它没有这条 API**）  
- 不把 RAG 当成写权限、改库存的通道  

---

## 8. 小结（请能复述）

1. **数字走 Tool，口径走 RAG。**  
2. RAG 是「检索相关片段再生成」，不是全文背诵。  
3. Spring AI 2.0 主路径是 `RetrievalAugmentationAdvisor`，不是旧教程里的 `QuestionAnswerAdvisor` 一条龙。  
4. 检索不到时，**默认应拒答**，见 `05`。
