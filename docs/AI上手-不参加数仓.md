> 写给：有 Java 经验，**不负责数仓**，但要参与原华框架「AI 部分」，并且觉得 AI Agent 完全无从下手的人。

> 总计划仍见：[学习路径-原华规则逻辑框架.md](./学习路径-原华规则逻辑框架.md)  
> **逐步课表 + 打卡：** [逐步学习计划.md](./逐步学习计划.md)、[学习打卡表.md](./学习打卡表.md)

## 0. 先把两件事拆开（这是你卡住的根因）

你现在把三个完全不同的「AI」叠在了一个词上，所以会觉得整座山都要从零爬：

| 别人嘴里的 AI | 原华框架里是不是这个 | 你要不要现在学 |
|---|---|---|
| ChatGPT / Agent / LangChain / 多工具自动干活 | **不是。** 规格 §3 是状态空间预测，§4 是规则 + 优化 | **现在不要作为主线** |
| 机器学习：预测销量、逾期概率、XGBoost | **部分是。** D3/D4 才是，而且 MVP **后置** | 第二波 |
| 统计预测 + 库存公式：P10/P50/P90、安全库存、效期截顶 | **就是这个。** §3 + D1/D5 | **你的第一份工作** |

所以：

- 你要参与的「AI 开发」，**第一年的主体不是 Agent**，而是 **需求预测服务 + 补货/近效期决策数字**。
- Agent（大模型调工具、写理由、问答）最多是外壳：把已经算好的 `Q_final` 翻译成话术、帮人查一条建议。  
  **Q_final 绝不能让 LLM 口算。** 规格里的公式、删失、硬红线都经不起「模型随便说一个数」。

无从下手时，只做这一句就够：**先写一个能对 1 个 SKU 吐出 P50 和补货量的脚本，而不是先学 Agent 框架。**

## 1. 不参加数仓，你的工位到底在哪

```
数仓团队（你不参加）
  产出：dws_fact_aligned / feat_* / 库存批次 / 三口径
           │
           │  你必须会：读表、验收字段、打回脏数据
           ▼
你（AI）     读入特征 → 拟合/推理 → 写出 dws_demand_forecast
           │
           ▼
你或 Java同事  D1/D5 规则（建议你用 Python 原型，再迁 Java）
           │
           ▼
合规/审计    硬红线裁剪（继续用 Java 类型系统，这是你旧技能）
```

**数仓你可以不建，但你不能当数据文盲。**  
否则模型会把压货、缺货、开票虚高全部当成「真实需求」。这不是数仓的锅，是建模的锅。

你对数仓同事的关系是 **甲方 + 验收员**：

1. 给出 **数据契约**（下面有清单），而不是「你们随便给张宽表」。  
2. 抽几条 SKU 自己 `SELECT` 对一下：缺货月出货是不是还被标成完整需求。  
3. 契约不满足就 **拒绝训练**，不要先用脏数据把模型跑起来装进度。

最少要会的 SQL（不是建仓，是消费）：

```sql
SELECT product_id, period,
       qty_anchor, available_qty, backorder_proxy, fill_rate,
       push_intensity, inv_cover_days, near_exp_ratio
FROM dws_fact_aligned   -- 表名以数仓实际为准
WHERE product_id = :sku
ORDER BY period;
```

窗口函数、拉链表、调度不用你写。`GROUP BY`、过滤、空值、和业务对数字，必须会。

## 2. 你要交付的 AI 产物（先记住这 4 张「接口表」）

忘掉「智能体」「知识库」「多 Agent 协作」。你的代码对系统只做四件事：

### 2.1 读入（数仓给你）

至少这些字段，没有就让他们补，不要自己在模型里猜：

| 字段 | 你为什么要 |
|---|---|
| `product_id, period, qty_anchor` | 拟合目标（G1：签收为锚） |
| `available_qty, backorder_proxy, fill_rate` | 删失：缺货月不能当需求变差（G3、§3.3） |
| `push_intensity` / `is_push_month` | 透支池 `h_t`（G4） |
| `lead_time_days, moq_qty, shelf_life_months` | D1 公式 |
| `on_hand, in_transit, remaining_months` | D1/D5 |
| `demand_pattern`（或你自己按 ADI/CV 算） | 高频走 §3，间歇走 Croston |

### 2.2 写出（这就是你的模型服务）

`dws_demand_forecast`：`p10, p50, p90, overhang_h, supply_censor_flag, demand_pattern, model_version, fit_metric`

### 2.3 算出建议（MVP：D1 + D5）

`Q_final`、理由链、风险三元（断货/积压/效期）。公式在规格 §4.2，不是神经网络。

### 2.4 被合规裁剪（你配合 Java）

候选方案进硬红线时 **不能带收益字段**。AI 侧不要输出「违规方案的 ROI」。

## 3. 从 Java 到这套 AI：只要换一套「心智模型」

| Java 里你熟悉的 | 预测代码里对应什么 |
|---|---|
| `List<Double> y` | 一条 SKU 的月销量序列 |
| `for` + 滑动窗口 | 滚动回测（不能随机 shuffle，那是泄漏） |
| `interface Forecaster { Quantiles fitAndPredict(...) }` | 模型版本可替换 |
| 单元测试 `assertEquals` | 用 **WAPE、分位覆盖率** 验收，而不是「感觉准」 |
| 配置中心 / version | `model_version`、冻结随机种子、冻结训练截止日 |
| 日志 traceId | 这条建议用了哪版模型、哪天的库存快照 |
| `Optional` / 空值 | 缺货删失：不是 0，是「需求 ≥ 出货」 |

你不是去「学会 AI 这个行业」，而是去写一个 **对时间序列负责的 Java 程序员**，语言暂时换成 Python。

## 5. 真正要学的最小集合（按周，全部对着代码）

原则：**每一周都有一个能跑的脚本。** 看课超过写代码，就是又在「无从下手」。

### 第 1 周 · Python 和一条序列

**学：** Python 语法到能写函数即可（变量、列表、字典、函数、读写 CSV）。不必学面向对象全集。  
**对照 Java：** `list/dict` ≈ `List/Map`；切片 `y[-12:]` 就是「最后 12 个月」。  
**做：** 跑通仓库里的 `ai-starter/toy_forecast_d1.py`，改三个数字看 `Q_final` 怎么变。  
**出门：** 能向别人讲：脚本里 P50、σ、安全库存、MOQ 各是哪一行。

### 第 2 周 · 回测，而不是「拟合得很漂亮」

**学：** 时间序列必须按时间切：用 2023 年拟合，预测 2024，禁止打乱月份。  
**指标：** WAPE = Σ|预测-实际| / Σ|实际|；覆盖率 = 实际落在 P10–P90 里的比例。  
**做：** 把 starter 改成「最后一个 6 个月当测试集」，打印 WAPE。  
**出门：** 你不再用「看起来拟合很好」当验收。

### 第 3 周 · 业务约束进模型（这才像原华）

**学三个概念就够：**

1. **删失：** 库存为 0 的月份，出货是需求的下限，不是需求本身（G3）。  
2. **压货：** 采购异常高的月，后面几个月出货里有一部分是在消化库存，不是终端突然变好（G4）。  
3. **分位数：** 备货看的是断货风险，不是平均值；所以要 P90 而不是只给一个点。

**做：** 在模拟数据里人为制造 2 个缺货月，对比「把缺货当 0 需求」和「把缺货标成删失」两种 P50。  
**出门：** 能在白板上画出规格 §3.3 的三种观测：精确 / 供给删失 / 透支压制。

### 第 4 周 · 把 D1 写成你交得出去的函数

对照 §4.2 手算 1 个 SKU，再和代码对得上：

```
σ_d = (P90 - P50) / 1.28
SS  = z * σ_d * sqrt(lead_time)     # 近效期高则下调 SS
S   = P50 * (lead_time + review) + SS
Q   = max(0, S - available - in_transit)
Q   = min(Q, 效期内能卖完的量)
Q_final = ceil(Q / moq) * moq
```

**做：** Python 原型 + 3 个单测（MOQ 进位、效期截顶、P50=0）。然后用 Java 再写一遍同一组测试，你会立刻回到舒适区。  
**出门：** 供应链问「为什么是 24 箱」你能用理由链复述，而不是「模型说的」。

### 第 5–6 周 · 接真数据（仍然不建仓）

1. 把数据契约发给数仓（本文第 7 节）。  
2. 拿 1 条产品线、20 个 A 类高频 SKU 的月序列。  
3. 先 **季节朴素 / Holt-Winters / 去扭曲中位数**，不要上状态空间全文。  
4. 写出 `dws_demand_forecast` 样例行，让决策同事接 D1。  
5. 间歇品（很多月为 0）先隔离，标 `intermittent`，走「有单再采」话术，别硬套连续模型。

规格 MVP 到这里已经能参与开发了。Croston、透支池 `h_t`、PyTorch 路径 B 是下一轮，不是「入门门票」。

## 6. 那 Agent 到底要不要学？什么时候学？

**要，但排在 D1 数字稳定之后。** 否则你只会做「会聊天的错误补货」。

原华框架里，Agent 只适合做这些（全部是 **读已算结果 + 写人话 + 调工具**）：

| 可以交给 LLM Agent | 不可以交给 LLM |
|---|---|
| 把 `reason_chain` 写成业务能读的段落 | 计算 `Q_final`、P50、净收益 N* |
| 「这个客户为什么在 D5 红灯」的问答 | 硬红线是否命中（必须规则/类型系统） |
| 调用工具：查某 SKU 的预测表、库存快照 | 在生成期给被裁方案估 ROI |
| 汇总经营会草稿（数字全部来自表） | 自己编一个不存在的覆盖率 |

### 若你仍想提前摸一下 Agent：只学 6 个词

学完这 6 个词，你已经超过大多数「Agent 教程」的实质内容：

1. **LLM API：** 就是一次 HTTP POST，输入文本，输出文本。和调微信支付一样，不是新语言。  
2. **结构化输出：** 强制模型只吐 JSON，字段和 `dws_decision_advice` 对齐；解析失败就重试或降级。  
3. **Tool calling：** 模型不能算库存，只能说「请调用 `get_forecast(sku)`」；真正的数还是你的 Python/Java 函数返回。  
4. **上下文：** 把这一条 SKU 的预测、库存、规则版本塞进提示词，不要塞整本规格书。  
5. **人在回路：** 软边界高风险必须人批（规格 §5.4），Agent 不能直接 `executed=true`。  
6. **评测：** 准备 20 道「建议解释是否忠实于数字」的题；Agent 胡编数字 = 不及格。

Java 同学以后用 **Spring AI 或 LangChain4j** 即可，不必先学 Python Agent 生态。  
**预测本体继续 Python**（statsmodels / 以后 PyTorch），和 Agent 框架解耦。

### 一个正确的 Agent 形状（记住就行，现在不用实现）

```
用户: 为什么 SKU-A 建议进 24 箱？
  → Agent 调工具 get_forecast + get_inventory + get_d1_calc
  → 工具返回 {p50:10, p90:14, ss:5, q_final:24, moq:12, ...}
  → LLM 只负责把这些字段写成 reason_chain
  → 审计日志记下 tool 返回的快照哈希，而不是记下模型「脑内数字」
```

和规格 §4.6、§5.4 是同一套：建议四件套 + 可回放审计。

## 7. 发给数仓的数据契约（你不建仓，但要会要数）

复制下面这段给他们。没有这些字段，你的 AI 部分无法开工：

```text
MVP 只要 1 条产品线、A 类高频 SKU，月粒度。

一张对齐事实（或等价视图），每行 = product_id + period：
- qty_sign / qty_ship / qty_invoice
- qty_anchor（按规格 COALESCE + 转换率，或给我们原始三口径我们自己算）
- order_qty, backorder_qty, available_qty
- fill_rate 或我们可以根据上面计算
- is_push_month, push_intensity（探针1 标签，规格 6.4）
- lead_time_days, moq_qty, shelf_life_months
- on_hand_qty, in_transit_qty, near_exp_ratio
- 训练截止日、时区、单位（箱/件必须统一）

验收：
- 缺货月不得把需求当 0 且无删失标记
- 签收滞后可追溯（T+7 校准）
- 效期字段完整率达到经营会能用的程度
```

你要会做的验收不是建表，而是：**随便抽 3 个 SKU，用 Excel 也能复现一行数字。** 复现不了就打回。

## 8. 第一周日程（解决「无从下手」）

不要排课，按这 7 天打勾。每天 1.5–2 小时。

| 天 | 具体动作 | 完成的标志 |
|---|---|---|
| D1 | 安装 Python 3.11+；能在命令行 `python3 --version` | 环境不再是障碍 |
| D2 | 运行 `python3 ai-starter/toy_forecast_d1.py` | 看到 P10/P50/P90 和 Q_final |
| D3 | 打开脚本，改 `LEAD_TIME`、`MOQ`、`AVAILABLE`，记录 Q 如何变 | 知道公式在干活，不是魔法 |
| D4 | 用纸手算脚本打印的那组数，和输出对上 | 你开始信任自己而不是信任「AI」这个词 |
| D5 | 把 `simulate_series()` 里某两个月改成缺货（出货=0，库存=0），看 P50 被带歪没有 | 第一次碰到 G3 删失直觉 |
| D6 | 写 10 行笔记：规格 G1–G5 各用脚本哪一段对应 | 规格不再是天书 |
| D7 | 把第 7 节数据契约发给数仓/老板，约 20 个 SKU | AI 部分正式进入协作，而不只是自学 |

第 8 天仍然不要打开 LangChain。

## 9. 推荐材料（只保留能支撑上面 6 周的）

1. Python 官方教程到「函数」一章，或任何「Python for Java developers」短文（语法对照即可）。  
2. 规格原文：G1–G5、§3.3、§3.7、§4.2、§4.5、§6.5。每天读一小节，对着 starter 代码。  
3. Hyndman *Forecasting: Principles and Practice* 里：时间序列是什么、朴素预测、ETS、回测、Croston。不要一上来读状态空间全书。  
4. 安全库存 / (s,S) 任意供应链短文，能看懂 `z * σ * √L` 即可。  
5. Agent 推迟到第 6 周以后：先读 OpenAI 或任意厂商的 **function calling / tool calling** 一页文档，比任何 Agent 框架书都有用。

## 10. 你怎么知道自己已经「入门了」

同时满足这 5 条，你就可以在项目里认领 AI 任务，而不是继续焦虑 Agent：

1. 能独立跑通 starter，并改参数解释 `Q_final`。  
2. 能指出缺货月为什么不能当普通 0。  
3. 能写出 `dws_demand_forecast` 一行样例，字段齐全。  
4. 能用手算复核 D1。  
5. 能对数仓说出「没有删失标记我拒收」。

还没满足时，你缺的不是更多框架，是 **再写一周代码**。
