## 先回答：要不要学 AI Agent 应用开发（LLM 调优除外）？

**做原华这套东西：主线不要学 Agent，选修再学。**

| 问题 | 答案 |
|---|---|
| 原华 MVP 的核心是 Agent 吗？ | 不是。是 **分位数预测 + D1/D5 规则**（规格 §3、§4.2、§4.5、§6.5） |
| `Q_final` 该不该让 Agent 算？ | **不该。** 必须用公式/代码算，LLM 最多解释数字 |
| 「Agent 应用开发」里、不含微调的那些技能要不要碰？ | **要，但放在阶段 9。** 指的是：调 LLM API、强制 JSON、Tool calling、人在回路、评测。不是 LangGraph 多角色演戏 |
| 现在就去学 LangChain 会怎样？ | 会耽误你学会 P50 和 `Q_final`，而这才是业务要的 |

岗位如果写成「AI Agent」，但活是这本规格，**以规格为准**。阶段 0–8 是必做；阶段 9 是「会做解释型助手」；阶段 10 是以后才需要的加深。

主线心智：你是 **会写预测与补货数字的 Java 工程师**，不是 ChatGPT 产品经理。

```
阶段0 规格地图
  → 1 Python
  → 2 读 CSV/序列
  → 3 均值·分位数·正态
  → 4 基线预测（P10/50/90）
  → 5 删失与口径（消费侧，不建仓）
  → 6 D1/D5 代码化（Q_final）
  → 7 工程化（版本、接口、测试）
  → 8 间歇品 Croston
  → 9 选修：Agent 应用（Tool calling，不含微调）
  → 10 以后：透支池 h_t / 路径B / D3
```

## 阶段 3 · 均值、波动、分位数、正态（约 8 小时）

**阶段目标：** 理解 P10/P50/P90 和 `σ_d = (P90−P50)/1.28` 从哪来。不学测度论。

### 步骤 3.1 描述统计

- **学什么：** 均值、中位数、方差、标准差、MAD（中位数绝对偏差，规格初始化用过）。  
- **做什么：** 对 `sku_demo.csv` 的 `qty_anchor` 手算或脚本算：均值、中位数、标准差。  
- **参考档案（必读）：** 任意入门统计「集中趋势与离散」一章，例如可汗学院 Statistics: Average, Median, Standard deviation。  
- **参考档案（选读）：** 规格 §3.5 初始化那一段（μ₀=去扭曲中位数，σ 用残差 MAD）。

### 步骤 3.2 分位数

- **学什么：** P50=中位数；P90=只有约 10% 的情况比它更大。备货看断货风险，所以要 P90，不是只给一个平均数。  
- **做什么：** 把 36 个数排序，找出大约 10%、50%、90% 位置的值，和「均值±某倍数标准差」比一比。  
- **参考档案（必读）：** 规格 G5；[FPP3 预测什么](https://otexts.com/fpp3/what-can-be-forecast.html) 中关于不确定性的段落（第1章内）。

### 步骤 3.3 正态与 1.28

- **学什么：** 标准正态大约：均值+1.28σ ≈ 90% 分位；+1.65σ ≈ 95%。所以规格写 `σ_d = (P90−P50)/1.28`，D1 用 `z≈1.65` 做 95% 服务水平。  
- **做什么：** 在笔记写清：已知 P50、P90 如何反推 σ；已知 σ 如何得到 P10/P90。对照玩具脚本里的 `1.28 * sigma`。  
- **参考档案（必读）：** 玩具脚本 `forecast_quantiles()`；规格 §4.2 第一行公式。  
- **参考档案（选读）：** 维基「标准正态分布」分位数表。

**阶段 3 成果：** `learning/stage3-quantiles.md`：用 demo 数据算出的均值/P50/P90/反推σ，并写一句「为什么补货不能只用平均值」。

**通过标准：** 合上规格能默写 `σ_d = (P90−P50)/1.28` 并解释每个字母。

## 阶段 4 · 基线预测（约 10–12 小时）

**阶段目标：** 自己实现季节朴素，输出 P10/P50/P90，并用 **WAPE** 做回测。不上神经网络。

### 步骤 4.1 朴素与季节朴素

- **学什么：** 朴素=预测等于上个月；季节朴素=预测等于去年同月。这是规格里「水平+季节」的最简版。  
- **做什么：** 在 `learning/forecast_baseline.py` 读取 CSV，用季节朴素预测「最后一个月」，打印预测值。  
- **参考档案（必读）：** [FPP3 5.2 简单预测方法](https://otexts.com/fpp3/simple-methods.html)；玩具脚本 `seasonal_naive_p50()`。

### 步骤 4.2 用残差估 P10/P90

- **学什么：** 残差=实际−预测；残差标准差≈需求波动；P10/P90≈P50±1.28σ。  
- **做什么：** 复现玩具脚本的分位数，允许和打印结果有少量舍入差。  
- **参考档案（必读）：** 玩具脚本 `residual_sigma()`、`forecast_quantiles()`；规格 §3.7 `p10/p50/p90`。

### 步骤 4.3 回测与 WAPE

- **学什么：** WAPE = Σ|预测−实际| / Σ|实际|。用「第 1–24 月」的方法去衡量「第 25–36 月」（或滚动：每月用此前数据预测下一个月）。  
- **做什么：** 计算季节朴素在 demo 上的 WAPE，写入 `learning/stage4-wape.md`。  
- **参考档案（必读）：** [FPP3 5.8 预测评估](https://otexts.com/fpp3/accuracy.html)（MAPE/MAE；WAPE 与加权绝对百分比同类）；规格 §6.3 预测层「分品类 WAPE」「分位数覆盖率」。

### 步骤 4.4（选做）ETS / Holt-Winters 知道即可

- **学什么：** 指数平滑=对近期加权更大；Holt-Winters=水平+趋势+季节。这是以后换掉「季节朴素」的下一档，仍不是深度学习。  
- **做什么：** 读完 FPP3 第7章开头，列三个名词：level、trend、season。现在不必编码。  
- **参考档案（选读）：** [FPP3 第7章 ETS](https://otexts.com/fpp3/ets.html)；以后才用 [statsmodels ExponentialSmoothing](https://www.statsmodels.org/stable/generated/statsmodels.tsa.holtwinters.ExponentialSmoothing.html)。

**阶段 4 成果：** `learning/forecast_baseline.py` + `stage4-wape.md`（写出 WAPE 数字和计算方法）。

**通过标准：** 能独立从 CSV 打出一行「假的 `dws_demand_forecast`」：`p10,p50,p90,model_version,fit_metric`。

## 阶段 5 · 删失与口径（消费侧，约 8 小时）

**阶段目标：** 缺货月不再当「需求变成 0」。仍不建仓，但会验收数仓字段。

### 步骤 5.1 三口径只做读者

- **学什么：** `qty_invoice / qty_ship / qty_sign`；分析锚在签收；T+7 回填。你不负责 ETL，但训练前要确认用的是锚口径。  
- **做什么：** 笔记中画：下单 → 出库 → 签收。标明你建模用哪一个。  
- **参考档案（必读）：** 规格 G1、§2.2 状态机（读懂即可）。

### 步骤 5.2 右删失

- **学什么：** 库存不够或 `backorder_proxy=1` 时，出货 ≤ 真实需求。把出货当完整需求，模型会以为需求变差。  
- **做什么：** `sku_demo.csv` 里已有两个 `backorder_proxy=1` 且出货为 0 的月。分别计算：（A）把这两月当 0 需求求均值；（B）丢掉这两月再求均值。把两个均值写进笔记，说明为什么（A）会低估。  
- **参考档案（必读）：** 规格 G3、§3.3 情形表（精确 / 供给删失 / 透支压制）。  
- **参考档案（选读）：** 搜 “Tobit censored regression intuition”（只看「观测被截断」的图，不推导）。

### 步骤 5.3 压货直觉（还不算 h_t）

- **学什么：** 厂商压货月采购很大，随后出货里有一部分是渠道消化库存。探针 1 的 `is_push_month` 是标签，将来用来验收 `h_t`。现在只要能在业务上认出「假需求」。  
- **做什么：** 用自己的话写 3 句：压货月、回补月、若当成真实需求会怎样。  
- **参考档案（必读）：** 规格 G4、§6.4 探针 1。

**阶段 5 成果：** `learning/stage5-censor.md`：两次均值对比 + §3.3 三种情形各举一个业务例子。

**通过标准：** 看到 `available_qty=0` 且出货很小，第一反应是「可能删失」而不是「需求没了」。

## 阶段 6 · D1 / D5 代码化（约 10 小时）

**阶段目标：** 用手算和代码同时得到同一个 `Q_final`；D5 能标近效期风险。这是你作为前 Java 开发最有迁移优势的阶段。

### 步骤 6.1 手算一个 SKU

- **学什么：** 规格公式全链条（见阶段 0.2）。  
- **做什么：** 用玩具脚本打印的 P50/P90，加上假设：可用库存、在途、MOQ、效期，在纸上算出 `Q_final`。再跑脚本核对。  
- **参考档案（必读）：** 规格 §4.2；`toy_forecast_d1.py` 里 `d1_replenish()`。

### 步骤 6.2 Python 实现并写断言

- **学什么：** 边界：库存已够 → 0；MOQ 进位；效期截顶后可能比 raw 小。  
- **做什么：** `learning/d1.py` 实现函数 `replenish(...)`，至少 3 个 `assert`：  
  1. 库存极大时 `Q_final==0`  
  2. `Q_raw=15, MOQ=12` → `Q_final==24`  
  3. 效期极短时 `Q_final` 不超过可销量  
- **参考档案（必读）：** 规格 §4.2 例外（停产/物流卡先不用做）；§4.6 建议四件套字段名（action、reason_chain、risk_band…）。

### 步骤 6.3 用 Java 再写一遍（回家）

- **学什么：** 同一套测试，语言换回 Java。证明规则层不必绑死 Python。  
- **做什么：** `learning/D1Calculator.java` + 主方法里同样 3 个断言（`javac` 能跑）。`reason_chain` 用 `List<String>`。  
- **参考档案（必读）：** 你过往的 JUnit 习惯；本步骤的 Python 断言。

### 步骤 6.4 D5 清单规则

- **学什么：** 近效期红灯：剩余效期 < 在库/P50月销 + 缓冲；呆滞：覆盖天数高且动销下降；declining 停采。  
- **做什么：** 写伪代码或简单 if：输入 `remaining_months, on_hand, p50, inv_cover_days`，输出 `RED/YELLOW/EXIT/OK`。  
- **参考档案（必读）：** 规格 §4.5。

**阶段 6 成果：** `learning/d1.py`（带 assert）+ `learning/D1Calculator.java` + 一张 D5 判定表。

**通过标准：** 随机改输入，手算与 Python、Java 三个 `Q_final` 一致。能解释「为什么是 24 不是 15」。

- **参考档案（必读）：** 规格 §3.7、§4.6。

### 步骤 7.2 一种最小 API

- **学什么：** 一个 POST：`/forecast-and-replenish`，请求体 JSON，返回 P 分位和 `Q_final`。Python 用标准库 `http.server` 或 Java 用你熟悉的 Spring Controller，二选一。  
- **做什么：** 本地 curl 通一次。把请求/响应贴进笔记。  
- **参考档案（选读）：** Spring Web `@RestController` 你已会的部分；或 Python [http.server](https://docs.python.org/zh-cn/3/library/http.server.html) 仅作玩具。

### 步骤 7.3 审计字段（为以后 Agent 打底）

- **学什么：** `model_version`、输入快照哈希、规则版本。人以后问「为什么 24 箱」时能回放。  
- **做什么：** 对请求 JSON 做 SHA-256，放进响应 `input_snapshot_hash`。  
- **参考档案（必读）：** 规格 §5.4 `log_audit_trail` 字段列表（先实现 hash 与 version 即可）。

**阶段 7 成果：** 可 curl 的本地接口 + 一份成功的请求/响应样例（含 `Q_final`、`reason_chain`、`model_version`、hash）。

**通过标准：** 同事只看 JSON 就能复核数字，不必读你的 Python 控制台。

## 阶段 8 · 间歇品（约 6 小时）

**阶段目标：** 很多月为 0 的 SKU 不再输出「每月 0.3 件」。

### 步骤 8.1 ADI / 分类

- **学什么：** ADI≈平均多少期才来一次需求；规格用 CV+ADI 每月打标 `high_freq / intermittent / declining`。  
- **做什么：** 计算 demo 的 ADI；再造一条「多数月为 0」的序列，标成 intermittent。  
- **参考档案（必读）：** 规格 §3.6；玩具脚本 `classify_pattern()`。

### 步骤 8.2 Croston 思想

- **学什么：** 分开估计「多久来一次单」和「来单时买多少」；SBA 是偏差修正版。输出：发生概率 × 条件均值。话术：「X% 概率要货、常备 n、有单再采」。  
- **做什么：** 用伪代码或简短 Python 实现最朴素 Croston（不必一上来 SBA）。打印 `prob_occur, cond_mean`。  
- **参考档案（必读）：** 规格 §3.6、§3.7 的 `prob_occur/cond_mean`。  
- **参考档案（选读）：** [FPP3 Intermittent demand](https://otexts.com/fpp3/intermittent-demand.html)；搜 Croston 1972 思想综述即可。

**阶段 8 成果：** `learning/croston_toy.py` + 两句给商务看的话术样例。

**通过标准：** 你能判断一个 SKU 该走阶段 4 主路径还是本阶段，而不是都丢进同一个平均模型。

## 阶段 9 · 选修：AI Agent 应用开发（不含微调）（约 12–16 小时）

**前置：** 阶段 7 已有「根据工具返回的 JSON 就能解释 Q_final」。否则不要开始。

**阶段目标：** 会做 **解释型助手**：LLM 只能调你的工具拿数字，不能自己编 `Q_final`。不学微调、LoRA、GPU。

### 步骤 9.1 LLM API 就是 HTTP

- **学什么：** 一次 POST，messages 进，文本出。与调任何第三方 HTTP 相同。  
- **做什么：** 用 curl 或 Java `WebClient` 调任意兼容 OpenAI 的 chat 接口（公司网关也行），让它复述「2+2=4」。  
- **参考档案（必读）：** 你所用模型商的 Chat Completions / Messages 文档（OpenAI、Azure、国内网关择一）。  
- **参考档案（Java）：** [Spring AI 入门](https://docs.spring.io/spring-ai/reference/getting-started.html) 或 [LangChain4j 文档](https://docs.langchain4j.dev/) 的 Chat Model 一节。只看「如何发一条消息」。

### 步骤 9.2 结构化输出

- **学什么：** 要求模型只吐 JSON，字段固定；解析失败则重试或降级为「无法生成文案」。  
- **做什么：** 把阶段 7 的响应塞进提示词，要求输出 `{ "summary": "...", "q_final": <必须原样拷贝> }`。断言 `q_final` 与工具数字相等。  
- **参考档案（必读）：** 厂商文档里的 JSON mode / structured output；规格 §4.6 `reason_chain`。

### 步骤 9.3 Tool calling（Agent 的真正核心）

- **学什么：** 模型不返回最终答案，而返回「请调用 `get_replenish(sku)`」；你的 Java/Python 执行函数，把结果还回去，模型再写人话。  
- **做什么：** 实现一个工具：内部调用阶段 7 的计算（**禁止**让模型算库存）。用户问「SKU 演示品该进多少」，最终回答里的箱数必须等于代码里的 `Q_final`。写一条失败用例：若模型改了数字，测试应报错。  
- **参考档案（必读）：** [OpenAI Function calling](https://platform.openai.com/docs/guides/function-calling)（其它厂商「工具调用」文档同类）；Spring AI Tools / LangChain4j Tools 对应章节。

### 步骤 9.4 人在回路与硬红线

- **学什么：** 软边界高风险必须人批；硬红线方案不能出现收益数字。Agent 不得把 `executed=true` 自己写上。  
- **做什么：** 设计：工具若返回 `compliance_tag=HARD_BLOCK`，LLM 只允许说「已被合规拒绝」，不得编 ROI。  
- **参考档案（必读）：** 规格 G6、§5.4 流程。

### 步骤 9.5 评测（没有评测就没有 Agent 产品）

- **学什么：** 准备 10–20 条「用户问题 + 标准数字」。检查：回答是否包含正确 `Q_final`、是否编造覆盖率、是否泄露被裁方案收益。  
- **做什么：** 一张 `learning/agent_eval.tsv`：问题、必须出现的数字、禁止出现的词。手工跑 5 条也算完成。  
- **参考档案（选读）：** 任意「LLM eval / golden set」短文一篇。

### 阶段 9 明确不学

LangGraph 多智能体、AutoGPT 自主循环、向量库 RAG 当预测引擎、微调/强化学习、用 Agent 跑批处理预测。

**阶段 9 成果：** 一个本地 Demo：问「为什么建议进 N 箱」→ 先 tool 后自然语言；评测表上至少 5 条数字零幻觉。

**通过标准：** 你能画对这个序列：用户 → LLM → tool → 你的 D1 代码 → 数字回填 → LLM 写理由 → 审计记 hash。
